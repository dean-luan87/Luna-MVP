# 长期解决方案：语音播放等待时间问题

## 🔍 问题分析

### 当前问题
- `voice_av.py` 的 `speak()` 方法是非阻塞的，会立即返回
- 调用方需要自己估算等待时间，容易出错
- 如果等待时间不够，下一条语音会打断上一条

### 根本原因
- macOS `say` 命令是异步的，无法直接知道何时播放完成
- 需要轮询检查进程状态来判断是否播放完成

## ✅ 长期解决方案

### 方案：添加 `wait_until_done()` 和 `speak_and_wait()` 方法

#### 1. `wait_until_done(timeout=None)` 方法
- **功能**：等待当前播放完成（阻塞）
- **参数**：
  - `timeout`: 超时时间（秒），None 表示无限等待
- **返回**：True 表示播放完成，False 表示超时或出错
- **实现**：轮询 `is_speaking()`，每 100ms 检查一次

#### 2. `speak_and_wait(text, tts_manager=None, timeout=None)` 方法
- **功能**：播报文本并等待完成（阻塞）
- **适用场景**：
  - 测试脚本
  - 重要提示（需要确保完整播放）
  - 需要顺序播放的场景
- **参数**：
  - `text`: 要播报的文本
  - `tts_manager`: 兼容参数，不使用
  - `timeout`: 超时时间（秒），None 表示无限等待
- **返回**：True 表示播放成功并完成，False 表示失败或超时

## 📊 使用场景对比

### 场景 1：需要立即打断（导航、紧急提示）
```python
# 使用非阻塞 speak()
voice.speak("普通提示")  # 立即返回，不等待
voice.speak("紧急提示")  # 会立即打断上一条
```

### 场景 2：需要确保完整播放（测试、重要提示）
```python
# 使用阻塞 speak_and_wait()
voice.speak_and_wait("重要提示", timeout=10)  # 等待完成，最多 10 秒
voice.speak_and_wait("下一条提示", timeout=10)  # 上一条完成后才播放
```

### 场景 3：需要等待但不阻塞（主循环中）
```python
# 先 speak()，然后在循环中检查
voice.speak("提示")
# ... 其他逻辑 ...
if not voice.is_speaking():
    # 播放完成，可以继续
    pass
```

## 🔧 实现细节

### `wait_until_done()` 实现
```python
def wait_until_done(self, timeout: Optional[float] = None) -> bool:
    start_time = time.time()
    while True:
        if not self.is_speaking():
            return True
        if timeout is not None:
            if time.time() - start_time >= timeout:
                return False
        time.sleep(0.1)  # 每 100ms 检查一次
```

### `speak_and_wait()` 实现
```python
def speak_and_wait(self, text: str, tts_manager: Optional[object] = None, timeout: Optional[float] = None) -> bool:
    if not self.speak(text, tts_manager):
        return False
    return self.wait_until_done(timeout=timeout)
```

## 📝 使用建议

### 1. **主循环中的播报**（推荐使用非阻塞）
```python

def tts_say(text: str) -> None:
    # 非阻塞，不等待
    self.voice.speak(text, self.tts_manager)
    # 立即返回，不阻塞主循环
```

```python

    # 阻塞等待，确保每条完整播放
    voice.speak_and_wait(message, timeout=10)
```

### 3. **重要提示**（根据需求选择）
```python
# 如果需要确保完整播放
voice.speak_and_wait("重要提示", timeout=10)

voice.speak("普通提示")
```

## 🎯 优势

1. **灵活性**：调用方可以根据场景选择阻塞或非阻塞
2. **准确性**：不需要估算等待时间，自动检测播放完成
3. **可靠性**：支持超时保护，避免无限等待
4. **兼容性**：保留原有的 `speak()` 方法，不影响现有代码

## ⚠️ 注意事项

1. **主循环中避免使用阻塞方法**：会卡住主线程
2. **超时时间设置**：根据文本长度合理设置，建议 `len(text) * 0.25 * 2` 秒
3. **性能影响**：`wait_until_done()` 会轮询检查，每 100ms 一次，开销很小
