# Luna Badge v1.4.5 发布说明

## 版本信息

- **版本号**: v1.4.5
- **发布日期**: 2025-12-09
- **基线版本**: v1.4.4

## 版本目标

v1.4.5 的核心目标是构建"Composition Engine"（组合引擎），实现任务链的积木化扩展能力。主要包含：

1. **核心架构重构**：引入 `ModelScheduler`、`FlowEngine`、`QueryEngine` 等新模块
2. **任务链积木化**：实现 `TaskPiece` 系统和 `CompositionEngine`
3. **Hook 体系**：支持多 Hook 点、多 Piece 协同、多 Patch 串联
4. **Scene 系统**：完整的场景识别、注册、加载、上下文管理（v1.4.7）

## 主要变更

### 1. 核心架构（v1.4.5 基础）

#### 新增模块

- **`core/model_scheduler/`**
  - `ModelRegistry`: 模型注册与元数据管理
  - `ContextAwareModelSelector`: 上下文感知的模型选择器
  - `ModelScheduler`: 统一模型执行接口（单模型 + fallback 链）

- **`core/flow_engine/`**
  - `FlowNode` / `FlowEdge` / `FlowDefinition` / `FlowInstance`: 核心数据结构
  - `FlowPlanner`: 根据 Intent + Scene 拼装任务链
  - `FlowRuntime`: 任务链执行、暂停、恢复、插入任务

- **`core/query_engine/`**
  - `QueryEngine`: 问询触发策略、问题生成、答案落盘
  - 支持 GOAL、CONTINUE、CANCEL、SWITCH、NEXT 等问询类型

- **`core/flow_templates/`**
  - `BaseFlowTemplate`: 抽象模板基类
  - `FlowTemplateRegistry`: 模板注册与选择
  - `GoHospitalTemplate`: 医院导航模板示例

#### 增强模块

- **`decision_core/decision_core.py`**
  - 集成 `FlowPlanner`、`FlowRuntime`、`QueryEngine`
  - 支持新任务请求、待处理问询、任务控制命令

- **`task_chain/task_chain_manager.py`**
  - 完整任务状态机（ACTIVE、PAUSED、FINISHED、CANCELLED、FAILED）
  - 支持暂停、恢复、取消、插入子任务

### 2. 任务链积木化（v1.4.5a）

#### Composition Engine

- **`composition/composition_engine.py`**
  - 统一的任务链组合引擎
  - 支持 Hook 点声明、Piece 筛选、Patch 应用

- **`composition/hook_scheduler.py`** (C-2)
  - Hook 执行计划生成
  - 按 priority 排序、条件过滤

- **`composition/patch_utils.py`**
  - `TaskPatch` 统一抽象 (C-3)
  - `apply_task_patch()` 统一应用接口
  - 边重接（rewire）逻辑

#### TaskPiece 系统

- **`pieces/base_piece.py`**
  - `TaskPiece` 基类
  - `TaskPieceType` 枚举（NODE、SUBFLOW、DECORATOR、REWRITE）
  - `build_patches()` 统一接口（渐进式兼容）

- **`pieces/registry.py`**
  - `TaskPieceRegistry`: Piece 注册中心
  - 支持按 hook_point 过滤、条件过滤

- **`pieces/builtin/`** (C-1)
  - `MapRecordPiece`: 地图记录（GO_BEFORE, priority=40）
  - `StaffAssistPiece`: 工作人员协助（REGISTER_BEFORE, priority=30）
  - `PreCheckPiece`: 预检查（START_BEFORE, priority=30）
  - `NavigationEnhancePiece`: 导航增强（NAV_BEFORE, priority=45）
  - `SafetyCheckPiece`: 安全检查（SAFETY_BEFORE, priority=35）
  - `OcrDetectPiece`: OCR 检测（OCR_BEFORE, priority=60）
  - `HumanAssistPiece`: 人工协助（HELP_BEFORE, priority=25）

#### FlowPatch 系统

- **`patches/flow_patch.py`**
  - `FlowPatch` 数据结构
  - 支持新增节点/边、删除节点、重接入口/出口

### 3. Scene 系统（v1.4.7）

#### 核心模块

- **`task_engine/scene/scene_registry.py`**
  - `SceneRegistry`: 场景包注册与查找
  - 支持默认场景包和 tag 级别场景包

- **`task_engine/scene/scene_pack_loader.py`**
  - `ScenePackLoader`: 从 JSON 加载场景包
  - 完整结构校验

- **`task_engine/scene/scene_classifier.py`**
  - `SceneClassifier`: 场景识别（OCR + objects + GPS）
  - 规则 + 评分机制

- **`task_engine/scene/scene_context.py`**
  - `SceneContext`: 场景运行时上下文
  - `SceneContextManager`: 全局上下文管理

- **`task_engine/scene/scene_integration.py`**
  - `SceneIntegrationService`: 统一集成入口
  - `ensure_scene_context()` 一条龙服务

## 架构改进

### 职责分离

- **CompositionEngine**: 只负责"按计划应用 patch"
- **HookScheduler**: 负责"选 Piece + 排序"
- **TaskPiece**: 负责"生成 patch"
- **SceneIntegrationService**: 负责"场景识别 → 上下文更新"

### 渐进式兼容

- 新接口：`build_task_patches()` -> `List[TaskPatch]`
- 兼容旧接口：`build_patch()` -> `(nodes, edges)`
- 兼容最老接口：`builder()` -> `FlowPatch`
- 自动包装和转换，无需强制修改现有实现

### 可扩展性

- 易于添加新的 Hook 点
- 易于添加新的 Piece
- 支持环境感知的条件判断
- 支持一个 Piece 产生多个 Patch

## 已知限制

1. **Scene 系统与 TaskEngine 集成**：当前 Scene 系统已就绪，但尚未完全集成到 TaskEngine/DecisionCore 中
2. **剪枝功能**：`prune_flow()` 当前为占位实现
3. **FlowPatch 高级特性**：`rewire_entry` / `rewire_exit` 暂未完全实现
4. **多 Patch 边重接**：当前主要支持单 Patch 的边重接，多 Patch 串联时的边重接逻辑可进一步优化
