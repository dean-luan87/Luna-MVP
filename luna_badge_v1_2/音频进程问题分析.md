# 音频播放进程问题分析

## 🔍 问题发现

### 1. 多个 main.py 进程同时运行

**发现：**
```
PID  3514 - 运行时间: 20:04.62 (从 10:57AM 开始)
PID  3953 - 运行时间: 9:22.93 (从 11:08AM 开始)
PID  4214 - 运行时间: 3:35.93 (从 11:14AM 开始)
```

**影响：**
- 每个进程都有独立的 TTS 子进程
- 每个进程都有独立的 TTSGuard 实例
- 每个进程都会独立触发"已到达"播报
- **导致用户听到重复播报（3个进程 × 各自的播报 = 3倍播报）**

### 2. 用户反馈

- ✅ 听到了"Luna 已启动"（但和"已到达"一起播放）
- ⚠️ 听到了多次"已到达示例地点附近"（平均5-10秒播放一次）
- ⚠️ 说明有多个音频源在同时播放

## 🔍 代码分析

### navigation_controller.py 中的播报逻辑

```python
# 第51-54行：当距离 <= 0.5 米时
if self._distance <= 0.5:
    if now - self._last_broadcast_ts > self._broadcast_interval:
        self._tts(f"已到达 {self._target_name} 附近。")
        self._last_broadcast_ts = now

# 第59-62行：当距离 <= 0 米时
else:
    if now - self._last_broadcast_ts > self._broadcast_interval:
        self._tts(f"已到达 {self._target_name} 附近。")
        self._last_broadcast_ts = now
```

**问题：**
1. **两个播报点**：当距离在 0-0.5 米之间时，可能同时满足两个条件
2. **每个进程独立**：每个 main.py 进程都有独立的 `_last_broadcast_ts` 和 `_broadcast_interval`
3. **TTSGuard 不共享**：每个进程有独立的 TTSGuard，无法跨进程防抖

### TTSGuard 的作用范围

- ✅ **进程内防抖**：同一个进程内的重复播报会被阻止
- ❌ **跨进程防抖**：不同进程之间的播报无法互相阻止

## 🔧 解决方案

### 方案 1: 确保只有一个 main.py 进程运行（立即执行）

**已执行：**
```bash
pkill -f "main.py"
```

**验证：**
```bash
ps aux | grep "Python.*main.py" | grep -v grep
```

### 方案 2: 修复 navigation_controller 的重复播报逻辑

**问题：**
- 当 `distance <= 0.5` 时，会触发第53行的播报
- 当 `distance <= 0` 时，会触发第61行的播报
- 如果距离在 0-0.5 之间，可能两个条件都满足

**建议修复：**
```python
# 合并两个条件，只保留一个播报点
if self._distance <= 0.5:
    if now - self._last_broadcast_ts > self._broadcast_interval:
        self._tts(f"已到达 {self._target_name} 附近。")
        self._last_broadcast_ts = now
        # 到达后不再播报距离信息
        return NavState(at_target=True, distance=self._distance)
```

### 方案 3: 检查 _broadcast_interval 的值

需要确认 `_broadcast_interval` 的值，如果太小（比如5秒），会导致频繁播报。
