# 已知问题记录

## 📋 问题清单

### 🔴 问题 #1：语音播报不能播放完整

**发现时间**: 2024-12-04

**问题描述**:
- 语音播报（TTS）开始播放后，只播放开头部分就消失了
- 无法播放完整的语音内容

**复现步骤**:
1. 运行系统
2. 触发语音播报（例如：识别结果播报、导航提示等）
3. 观察 TTS 输出
4. 发现语音只播放开头就中断

**相关日志**:
```
2025-12-04 18:28:30 - luna_badge - INFO - 开始语音播报识别结果...
2025-12-04 18:28:32 - luna_badge - INFO - 开始处理当前帧...
```

**可能原因**:
1. **主循环中断播放**（最可能）
   - 从日志看：`开始语音播报识别结果...` 后立即 `开始处理当前帧...`
   - 主循环每 2 秒处理一帧，可能在 TTS 播放完成前就开始下一帧处理
   - 新的处理可能触发新的播报，中断当前播放

2. **音频资源被抢占**
   - 多个播报请求并发执行
   - 音频设备被其他进程占用
   - 音频缓冲区被清空

3. **线程同步问题**
   - TTS 播放线程和主循环线程冲突
   - 没有播放队列，新播报覆盖旧播报
   - 没有检查播放状态就启动新播报

4. **TTS 实现问题**
   - 播放未完成就被停止
   - 异步播放但主线程继续执行
   - 音频文件被过早删除

**影响范围**:
- 所有需要语音播报的场景
- 用户体验：无法听到完整的提示信息
- 导航提示、识别结果播报等关键信息丢失

**优先级**: 🔴 高

**状态**: ✅ 已修复（2024-12-04）

**修复方案**:
- 新增 `speech/tts_manager.py` - 基于队列的 TTS 管理器
- 修改 `main.py` - 使用 TTSManager 替代直接调用
- 修改 `navigation/navigation_controller.py` - 添加播报节流机制（3 秒间隔）

**修复效果**:
- ✅ 播报按顺序完成，不被主循环覆盖
- ✅ 句子完整播放，不会中断
- ✅ 主循环高频推送不会导致语音错乱
- ✅ 导航重复播报问题已解决（3 秒节流）

**相关代码位置**:
- `modules/voice.py` - Voice 类的 `_speak_edge_tts` 和 `_speak_pyttsx3` 方法
- `Luna_Badge/core/tts_manager.py` - TTSManager 的 `speak` 方法
- 主循环中调用 TTS 的位置

**备注**:
- 从日志时间戳看：播报开始后 2 秒就开始处理下一帧，可能中断了播放
- 需要检查 TTS 是否在独立线程中播放
- 需要实现播报队列，避免并发播放
- 需要添加播放状态检查，确保播放完成后再开始新播报

## 🔧 修复建议

### 针对问题 #1：语音播报中断

**可能解决方案**:

1. **检查 TTS 播放线程**
   - 确保 TTS 播放在独立线程中
   - 避免主循环阻塞 TTS 播放
   - 检查线程同步机制

2. **检查音频资源管理**
   - 确保音频设备不被其他进程占用
   - 检查音频缓冲区管理
   - 确保播放完成前不释放资源

3. **检查主循环逻辑**
   - 确保主循环不会中断 TTS 播放
   - 检查是否有新的播报请求覆盖了当前播放
   - 实现播报队列，避免并发播放

4. **添加播放状态检查**
   - 在开始新播报前检查是否有正在播放的内容
   - 实现播报队列机制
   - 添加播放完成回调

**需要检查的文件**:
- TTS 相关模块（`luna_tts_*.py` 或 `speech/` 目录下的 TTS 实现）
- 主循环文件（`main.py` 或主循环相关文件）
- 音频资源管理代码
