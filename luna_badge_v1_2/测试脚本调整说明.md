- 测试 4（长句子）：也没有完整播放
- 其他测试正常

## 🔧 调整内容

### 关键调整：增加了等待时间

#### 调整前（第一次）：
```python
# 测试 2：完整性测试（长句子）
voice.speak("这是第二句测试语音，内容较长...")
time.sleep(8)  # 等待 8 秒

# 测试 4：打断后恢复测试
voice.speak("刚才的语音已经被打断...")
time.sleep(6)  # 等待 6 秒

# 测试 6：最终确认测试
voice.speak("测试六号，所有测试已完成...")
time.sleep(6)  # 等待 6 秒
```

#### 调整后（第二次）：
```python
# 测试 2：完整性测试（长句子）
voice.speak("这是第二句测试语音，内容较长...")
time.sleep(12)  # 等待 12 秒（从 8 秒增加到 12 秒）

voice.speak("刚才的语音已经被打断...")
time.sleep(8)  # 等待 8 秒（从 6 秒增加到 8 秒）

# 测试 6：最终确认测试
voice.speak("测试六号，所有测试已完成...")
time.sleep(10)  # 等待 10 秒（从 6 秒增加到 10 秒）
```

## 💡 为什么这样调整有效？

### 核心原因：`voice_av.py` 的设计机制

在 `voice_av.py` 的 `speak()` 方法中：

```python
def speak(self, text: str, tts_manager: Optional[object] = None) -> bool:
    with self._lock:
        # 先尝试停止上一条
        self._stop_locked()  # ⚠️ 关键：新语音会先停止上一条
        
        # 然后启动新语音
        cmd = ["say", "-v", self._voice_name, "-r", str(self._rate), text]
        self._current_proc = subprocess.Popen(cmd, ...)
```

**设计逻辑：**
- 每次调用 `speak()` 时，会先调用 `_stop_locked()` 停止当前正在播放的语音
- 这是为了防止叠音，确保同时只有一条语音在播放

### 问题场景

**第一次测试的问题：**
1. 测试 2 开始播放长句子（需要约 10-12 秒才能完整播放）
2. 测试脚本只等待了 8 秒
3. 8 秒后，测试脚本发送测试 3 的语音
4. 测试 3 的 `speak()` 被调用，触发 `_stop_locked()`
5. 测试 2 的语音被强制停止（此时只播放了约 2/3）

**第二次测试的解决：**
1. 测试 2 开始播放长句子
2. 测试脚本等待 12 秒（足够长句子完整播放）
3. 12 秒后，测试 2 已经播放完成
4. 测试脚本发送测试 3 的语音
5. 此时测试 2 已经结束，不会被停止

## 🎯 关键发现

### 1. **`voice_av.py` 的"自动停止"机制**
- 这是设计特性，用于防止叠音
- 但需要确保上一条语音播放完成后再发送下一条

### 2. **等待时间的重要性**
- macOS `say` 命令是异步的，需要足够时间才能完整播放
- 等待时间 = 语音长度 × 语速系数 + 安全余量

### 3. **实际应用中的考虑**
- 在 `main.py` 中，导航播报通常比较短，不会遇到这个问题
- 但如果将来有长句子播报，需要确保有足够的等待时间
- 或者修改 `voice_av.py`，添加"等待上一条完成"的选项

## 🔧 可选优化方案

如果将来需要支持"等待上一条完成"的功能，可以这样修改：

```python
def speak(self, text: str, tts_manager: Optional[object] = None, wait_previous: bool = False) -> bool:
    if wait_previous:
        # 等待上一条播放完成
        while self.is_speaking():
            time.sleep(0.1)
    
    # 然后正常播放新语音
    ...
```

但当前的设计（自动停止上一条）对于大多数场景已经足够，只需要确保调用方有足够的等待时间即可。

## ✅ 总结

**调整内容：** 增加了长句子播放后的等待时间
- 测试 2：8秒 → 12秒
- 测试 4：6秒 → 8秒  
- 测试 6：6秒 → 10秒

**为什么有效：** 
- `voice_av.py` 的 `speak()` 会先停止上一条语音
- 如果等待时间不够，上一条还在播放时就被下一条停止了
- 增加等待时间后，上一条已经播放完成，不会被停止

**关键教训：**
- 使用 `voice_av.py` 时，需要根据语音长度设置足够的等待时间
- 或者修改设计，支持"等待上一条完成"的选项
