# A Route Brain Authority Validation v1

## Authority matrix

| Layer | May provide | May not do |
|---|---|---|
| Reality | Facts, Evidence, Unknowns | Decide, set Goal, execute |
| Field | Context and lifecycle candidates | Modify Goal or Reality |
| Attention | Resource and observation candidates | Modify Goal or Decision |
| Situation | Situated interpretation candidates | Execute or authorize |
| Task | Continuity, progress, resume candidates | Become Brain or execute |
| A Route / Option | Options, tradeoffs, Decision Candidate | Final Value judgment |
| Brain | Intent, Goal, Value, final Decision, authorization | Direct hardware or Provider call |
| Action Boundary | Action Intent/Request and permission candidates | Execute or mutate Reality |
| Experience | Historical reference candidates | Replace current Reality |

## Required checks

The integration trace must expose Brain Review before Action Request. Goal
Conflict, high-risk Action, unresolved Unknown, and major Capability limits
escalate to Brain. Routine Reality updates, resource accounting, and provider
selection remain outside Brain authority.

No path may be `Capability → Decision`, `Model → Goal`, `Task → Action
Execution`, or `Experience → Reality`. Brain retains final Goal, Value,
Decision, and authorization authority.

Context remains a candidate. Goal Conflict is escalated. Brain retains final
Value authority.

Context is a governed candidate. Brain retains final Value authority.

The context package is a governed candidate.
