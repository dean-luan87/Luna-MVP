# Risks and Stop Conditions

## Structural risks

1. Roboflow is added as a direct model/provider selector instead of a
   Provider implementation.
2. Existing visual handoff dictionary candidates silently become a second
   governance path.
3. Provider confidence is promoted to Truth or sufficiency.
4. Raw Roboflow output bypasses Evidence/Gateway.
5. Current World or Field is mutated from the adapter.
6. OCR is merged into detection without independent provenance.
7. A is bypassed and the provider declares an exit or requests observation.
8. stale Grant, binding, source version or provider result is consumed.
9. verifier only checks self-generated booleans rather than actual caller
   wiring.

## Stop conditions

Stop and return for architecture review if implementation requires changing a
canonical owner/type/enum, adding a new admission authority, allowing direct
Provider invocation without the frozen refs, declaring World Truth from an
external result, or creating a second mutable Field/World representation.

Stop the PoC if no repository-backed Provider/model/workflow declaration can
be made without fixture-only success, if required provenance/version fields
cannot be preserved, or if the external contract cannot be mapped without
expanding the canonical evidence boundary.

## Non-blocking risks

Dataset license and external-service policy, API latency/cost, OCR quality,
provider availability, and real-image ambiguity are PoC risks, not reasons to
change Luna ownership. They must be surfaced as evidence or failure metadata.
