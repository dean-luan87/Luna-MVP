# Luna Cognitive Self Evolution Architecture v1

## Position

Self Evolution is the controlled long-term growth layer between the closed-loop learning signal and Luna's self capability profile. It explains what repeated experience may mean for capability, behavior strategy, and limitation awareness without rewriting identity, values, constitution, or goals.

```text
Action Outcome + Expectation Difference + Feedback
                         |
              Experience Consolidation
                         |
                 Pattern Extraction
                         |
                 Strategy Evolution
                         |
          Capability Growth / Behavior Adaptation
                         |
              Self Capability Profile Update
                         |
                    Future Cognition
```

Every output is a candidate. Adoption requires evidence, confidence, review, and governance admission.

## Scope

In scope:

- consolidating outcome-linked experience;
- extracting repeated patterns without making automatic rules;
- producing strategy and behavior candidates;
- producing context-bound capability growth candidates;
- recording limitations and unknowns;
- maintaining a traceable capability profile and growth history;
- preserving Memory, Learning, Role, and Emotion Context boundaries.

Out of scope:

- Runtime Learning or autonomous online learning;
- model training, parameter updates, or provider replacement;
- automatic personality, identity, value, goal, or constitution changes;
- relationship evolution or Emotion Runtime;
- action execution and direct Reality mutation.

## Canonical boundaries

Memory records what happened. Learning supplies learning signals and candidate patterns. Self Evolution evaluates what repeated evidence may mean for the subject's capability and strategy. Capability Runtime may consume an admitted profile constraint, but it does not define Luna's identity. Role and Emotion are context metadata only in this phase.

```text
Reality > Evidence > Experience > Pattern > Candidate > Review > Adoption
```

Current reality and new evidence always supersede historical experience. Unknown remains explicit when evidence is insufficient.

## Governance rule

The only valid adoption path is:

```text
Candidate -> Evidence -> Confidence -> Review -> Adoption
```

The phase is architecture-only. This document does not authorize a scheduler, learner, model, hardware, provider, or action runtime.
