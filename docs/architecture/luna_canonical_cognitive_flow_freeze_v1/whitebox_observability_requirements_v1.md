# White-box Observability Requirements v1

Future White-box tooling should expose, per stage and edge:

- Concern, Grant and Envelope identities;
- current owner and authority category;
- transition class: formation, validation, binding, admission, adoption, mutation, execution, observation, evaluation or mechanical persistence;
- input/output refs and source versions;
- candidate/admission status and reason;
- Safety, Permission, Resource and Protocol refs;
- evidence, uncertainty, partiality and failure/block reason;
- provenance, trace identity and timestamps;
- invalidation/supersession refs;
- next return target: A, Brain, Decision, Task, Provider, Gateway or Loop.

This is an observability requirement only. It does not create a UI, authority, scheduler, retry engine or diagnostic owner.
