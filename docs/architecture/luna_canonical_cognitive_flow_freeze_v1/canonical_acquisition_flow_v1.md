# Canonical Acquisition Flow v1

## Flow

`A Cognitive Requirement → Attention focus/modality/budget candidate → Capability Requirement → Capability Scope/Logical Resolution → Capability-owned Model binding refs → Runtime Admission → Observation Request → Provider-owned binding/Provider Admission → Provider Invocation → Provider Result → Evidence Candidate mapping → Evidence Admission/Gateway → Current World Candidate and/or Field Event Candidate → Field/Current World source-owner processing → refreshed refs/products → A.`

## Authority rules

- A defines why information is needed.
- Attention allocates focus candidates; it does not execute.
- Capability resolves functional fit; it does not choose a physical provider by itself.
- Model Governance supplies declarations; it does not invoke models.
- Runtime Admission determines current executable eligibility.
- Observation owns acquisition request/result lifecycle.
- Provider owns admission, invocation and Provider Result.
- Gateway owns evidence normalization/admission.
- Field owns operational transitions; Current World remains a candidate representation.
- A evaluates relevance and Sufficiency.

## Edge classes

Requirement→Attention `BINDING`; Capability Requirement→Resolution `ADMISSION`; Provider Result→Evidence Candidate `FORMATION/MAPPING`; Evidence Candidate→Evidence `ADMISSION`; Evidence→A `ADOPTION`; A interpretation `SEMANTIC_EVALUATION`.
