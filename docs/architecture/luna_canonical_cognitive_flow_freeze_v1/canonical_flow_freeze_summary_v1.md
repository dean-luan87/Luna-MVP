# Canonical Flow Freeze Summary v1

## Final disposition

**CANONICAL_FLOW_COHERENT_WITH_CONTRACT_GAPS.** The first canonical end-to-end cognitive flow is frozen as a governed loop system. No authority decision was reopened.

## Frozen patterns

1. Cognitive: Brain Concern/Grant/Envelope → sibling Semantic Outline and Cognitive Snapshot → A.
2. Acquisition: A Requirement → Attention → Capability → Runtime → Observation → Provider → Evidence/Gateway → Field/Current World candidates → A.
3. Execution: A → Decision → Task → Action → Provider → Action Result → source/evidence updates → Task/A/Outcome.
4. Closure: multi-source results → Outcome Candidate → Brain adjudication/Assimilation → Goal/Concern consequence → authorized Loop mechanics.

## Return rule

A handles local evidence, Need, Hypothesis, Sufficiency, Reconsideration and Next-step. Brain handles Goal, Concern, Grant, global policy, cross-Concern conflict, final Outcome and Assimilation.

## Blocker result

No P0 blocker. P1 items are contract, adapter, version/invalidation, and legacy-bypass debts. Runtime absence is not a flow-definition blocker.

## Online-doc-ready sections

### 03.9.1 | Canonical Cognitive Work Unit

Brain-admitted Concern + Grant + Working Envelope. Concern identity persists across A cycles; Loop mechanics do not define semantic termination.

### 03.9.2 | Canonical Cognitive Flow

Envelope produces sibling Semantic Outline and Cognitive Snapshot candidates for A; A performs local semantic reasoning and starts acquisition or execution as required.

### 03.9.3 | Acquisition Loop

A Requirement → Attention → Capability → Runtime Admission → Observation → Provider → Evidence/Gateway → Field/Current World candidates → A.

### 03.9.4 | Decision / Task / Action Loop

A recommends; Decision commits; Task organizes; Action admits side effects; Provider invokes; results return to Task/A/Outcome.

### 03.9.5 | Outcome / Assimilation / Closure Loop

Outcome Evaluation forms a candidate; Brain adjudicates and assimilates; only Brain authorizes Concern/Goal consequence; Loop persists refs.

### 03.9.6 | A vs Brain Return Boundary

A receives local cognitive consequences. Brain receives global governance consequences. Neither replaces the other.

### 03.9.7 | Failure / Reconsideration Flow

Failures return to the responsible local boundary and then A for local reconsideration; global policy, Concern or Goal effects return to Brain.

### 03.9.8 | Version / Invalidation Flow

Domain versions propagate by refs and invalidation; no global version and no direct cross-owner mutation.

### 03.9.9 | Canonical Contract Surface

Existing distributed contracts cover the main edges; P1 gaps remain in binding schemas, runtime adapters, source-state handoffs and Outcome→Brain integration.

### 03.9.10 | White-box Observability Requirements

Expose owner, authority, transition class, refs, versions, provenance, constraints, admission status, failure reason, next target and timestamps per edge.
