# PLANNING_CANDIDATE

## M1 Objective

Establish candidate-only schema and contract alignment between Dynamic Cognitive
Architecture v2 and current engineering assets without changing any active code,
runtime, schema, contract, baseline, or owner metadata.

## Planning Rules

- Preserve one canonical writer per responsibility.
- Preserve candidate/fact separation across all proposed contracts.
- Preserve trace, replay, admission, revision, revocation, and failure behavior.
- Preserve source-owner precedence for Self, Role, Relationship, Memory,
  Emotion, Value, and Belief.
- Preserve Task Manager, Model Manager, Protocol Manager, OCR Manager, and
  Vision Manager as existing bounded engineering organs.

7. A/B Route Handoff

## Planned Outputs

- Ownership mapping for twelve candidate schema surfaces.
- Compatibility matrix and review for active engineering assets plus Memory.
- Candidate contracts for field, observation, memory, PCN, intent, causal,
  experience, A/B route, and decision boundaries.
- Boundary flow contract and rollback compatibility aliases.
- Blocked registry, phase contract, summary, manifest, and static verifier.

## Stop Boundary

Stop after documentation and static-verification assets are complete.
Do not execute runtime, do not modify existing assets, and do not perform
migration.
