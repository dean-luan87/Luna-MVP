# Luna 模型中台总纲 v1

> **对读**：条款级扩展与历史专题见 `../model_platform/LUNA_MODEL_PLATFORM_CONSTITUTION_V1.md` 及同目录其它文档；本文是 **第一轮可执行总纲**，与验收清单、对象 spec 一致即可落地。

---

## 1. 文档定位

本文是 Luna **模型中台**的架构宪法，用于定义模型中台的**定位、边界、主权关系**与**系统级原则**。

本文**不负责**定义某个具体模型的接入细节，**不负责**定义某个具体任务的输入输出，**不负责**定义蜂巢评分算法本身。

本文解决的问题只有一个：

**在 Luna 体系中，模型如何被统一纳管，而不演变成不可控的「第二大脑」。**

---

## 2. 为什么必须有模型中台

Luna 后续不会只使用单一模型。系统中将同时存在：

- 本地模型  
- 远程自建模型服务  
- 外部 API 模型  
- 个体 Luna 使用模型  
- 图书馆加工模型  
- 蜂巢评分与策略模型  

如果没有统一中台，后续一定出现以下问题：

- 各模块私接模型  
- 无统一版本管理  
- 无统一路由与主备策略  
- 无统一 fallback 与熔断  
- 无统一留痕  
- 无统一风险约束  
- 无法判断模型是否越权  

模型中台存在的核心价值，**不是**「方便调用」，而是：

**保证模型始终处于可治理、可替换、可降级、不可越权的位置。**

---

## 3. 中台在整体架构中的位置

模型中台位于**业务能力层**与**模型能力层**之间，是统一接入、统一治理、统一记录、统一执行模型策略的**中枢设施**。

**模型中台上接**：

- 个体 Luna  
- 图书馆  
- 蜂巢  
- 白盒观测层  

**模型中台下接**：

- 本地模型  
- 远程内部模型服务  
- 外部 API  
- 多模态能力服务  

**模型中台不是**：

- 任务链本体  
- 记忆系统本体  
- 白盒本体  
- 图书馆本体  
- 蜂巢本体  
- 前台执行层  

**模型中台是**：**模型与外部能力的统一治理基础设施。**

---

## 4. 中台四层结构

### 4.1 接入层

**职责**：

- 统一接入本地模型、远程模型、外部 API  
- 统一 provider / client / adapter  
- 统一鉴权、超时、重试、限流、熔断  

接入层解决的是「**怎么接**」，不解决「该用谁」和「能不能放行」。

### 4.2 注册与路由层

**职责**：

- 模型注册  
- 能力标签定义  
- 主备关系定义  
- route policy 管理  
- fallback 映射管理  

注册与路由层解决的是「**该用谁**」。

### 4.3 治理层

**职责**：

- 输入裁剪  
- 输出校验  
- schema 检查  
- 越权阻断  
- 风险约束  
- fallback 执行  
- 主链准入控制  

治理层解决的是「**能不能放心用**」。

### 4.4 评估与优化层

**职责**：

- 模型使用记录  
- 模型质量记录  
- 模型治理记录  
- 蜂巢评分输入占位  
- 图书馆经验输入占位  
- 优化建议输入占位  

评估与优化层解决的是「**用得怎么样，后续如何优化**」。

---

## 5. 四大主体关系

### 5.1 个体 Luna

个体 Luna 是前台生产与执行前理解单元。

**它负责**：

- 使用模型  
- 生成候选  
- 消费模型输出  
- 留下使用、质量、治理痕迹  

**它不负责**：

- 模型全局评分  
- 模型全局优劣判断  
- 全局升降级建议  
- 直接修改治理配置  

### 5.2 图书馆

图书馆是经验加工层。

**它负责**：

- 经验归档  
- 经验提炼  
- 经验验证  
- 经验打包  

**它不负责**：

- 主链裁决  
- 主模型切换  
- 直接改 route policy  
- 直接改治理配置  

### 5.3 蜂巢

蜂巢是全局评估与策略建议层。

**它负责**：

- 模型评分  
- 模型比较  
- 失败归因  
- 优化建议生成  

**它不负责**：

- 直接修改中台配置  
- 直接让建议生效  
- 直接替换模型  

### 5.4 中台

中台是治理执行层。

**它负责**：

- 模型接入  
- 模型注册  
- 模型路由  
- 模型治理  
- 模型升降级  
- 消费蜂巢建议  
- 执行灰度、限域、熔断、回滚  

**它不负责**：

- 替代个体 Luna 生产内容  
- 替代图书馆经验提炼  
- 替代蜂巢评分  

---

## 6. 模型不是主权者

任何模型，无论本地、远程还是外部 API，都只是能力单元，**不是**系统主权者。

**模型不得直接拥有**：

- 执行主权  
- 任务主权  
- 记忆主权  
- 白盒主权  
- 治理主权  

**模型可以拥有**：

- 结果候选生产权  
- 审核建议权  
- 评估建议权  
- 策略建议权  

但这些权力都必须经过**中台治理链、留痕链、可回滚链**。

---

## 7. 统一纳管原则

所有模型必须先进入中台注册，再允许进入系统调用路径。

**禁止**：

- 模块私接模型  
- 业务层绕过中台直接调外部 API  
- 白盒自行持有模型主链  
- 图书馆、蜂巢绕过中台各自私接模型  

**没有注册卡、没有任务卡、没有 fallback、没有留痕能力的模型，不得进入主链。**

---

## 8. 运行期治理原则

所有模型必须满足：

- 可替换  
- 可降级  
- 可熔断  
- 可观察  
- 可记录  
- 可回滚  

模型调用失败**不得拖垮主链**。**fallback 优先于僵死等待**。

**部署位置不改变治理边界**；本地模型、远程模型、外部 API 都必须接受**同一套**中台治理原则。

---

## 9. 当前阶段做什么，不做什么

**当前做**：

- 中台最小治理骨架  
- 注册卡 / 任务卡 / usage / quality / governance record  
- route policy / fallback plan  
- 蜂巢 / 图书馆对象占位  

**当前不做**：

- 自动评分闭环  
- 自动升降级  
- 自动灰度  
- 自动经验提炼  
- 自动建议生效  
- 多供应商大规模接入  
- 个体 Luna 评分  

---

## 10. 收束

Luna 模型中台的存在，不是为了让模型更容易接入，而是为了让模型在 Luna 体系中始终处于：

**可治理、可替换、可降级、不可越权。**
