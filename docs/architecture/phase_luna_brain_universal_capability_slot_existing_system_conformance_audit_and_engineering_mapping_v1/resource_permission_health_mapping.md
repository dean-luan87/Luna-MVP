# Resource, Permission, and Health Mapping

## Resources

Reuse Runtime Resource Governance for Compute, Energy, Memory, Time, and
Sensor Availability. Model Manager supplies model resource profiles and
compatibility. Slot contracts should carry references, not allocate resources
directly.

## Permissions

Reuse System Constitution and Permission Governance. Capability Governance
coordinates admission; Brain and user requests cannot bypass least-authority,
constitutional, privacy, or high-impact review.

## Health

Reuse Capability Health Model and System Maintenance diagnostics. Existing
health states Healthy, Warning, Degraded, Critical, and Unknown are evidence
about capability operation, not Module identity or World Truth.

## Gap

The canonical ingredients exist, but there is no generic Slot-facing envelope
that joins resource readiness, permission assessment, health, degradation,
recovery, and binding provenance. A future adapter is preferred before any
canonical type expansion.
