## 1. Freeze meaning

After user-terminal V2 verification and ChatGPT V3 approval, Luna Dynamic Cognitive Architecture v2 is intended to become the unique upper architecture reference for subsequent cognitive engineering. It organizes existing engineering assets and future cognitive capabilities under one vocabulary, dependency direction, ownership model, and development-governance boundary.

This freeze does not replace the Constitution, Cognitive OS governance, or Luna Architecture Baseline v2.0. It does not claim that future cognitive capabilities are implemented, that the root A3 Runtime carries Dynamic Cognitive Architecture v2, or that migration has executed.

The authority hierarchy remains:

```text

        ↓

        ↓
Luna Architecture Baseline v2.0
        ↓
Luna Dynamic Cognitive Architecture v2
        ↓

```

## 3. Frozen responsibility boundaries

### Field State System

Field State is responsible for `Reality State`:

- reducing admitted events into traceable Field State Candidates;
- maintaining current world and Field continuity;
- exposing read-only Field projections with provenance.

Field State is not responsible for Decision, Intent, causal judgment, Memory ownership, or Action execution. The Field State Reducer remains the governed reducer writer; the Field State Read Model remains read-only.

### Observation / Context

Observation is responsible for observation requests, evidence collection, modality coordination, quality, provenance, trace, and admission-handoff candidates. Context supplies governed references assembled from admitted Field, Self, Role, Memory, and other independent sources.

Observation does not declare final Fact, own Understanding, select Decision, or execute Action. Context does not mutate source objects or bypass Field State.

### Personal Cognitive Network

PCN is responsible for:

- `Connection` across governed object references;
- context-bound `Activation` candidates;
- read-only contextual `Projection` candidates.

PCN is not responsible for `Object Ownership`. It cannot own, persist, or mutate Self, Role, Relationship, Memory, Emotion, Value, Belief, Schema, or any other source object. It cannot invoke Runtime directly.

### Intent and Causal Reasoning

Intent Governance forms and governs context-bound Intent Candidates while preserving Goal, Decision, Task, and Action boundaries.

Causal Reasoning is responsible for `Candidate Reasoning`: evidence-bound, counter-evidence-aware, revisable causal and condition candidates with unknown preservation and temporal validity.

Causal Reasoning is not responsible for `Reality Mutation`, causal fact promotion, Decision selection, Task execution, Action, or Runtime state mutation.

### A/B Route

A Route retains current-Reality authority. B Route is a future simulation boundary for possible-future and counterfactual candidates. Simulation cannot override current Reality, Self, Goal, or Decision and does not exist as an active Runtime in this freeze phase.

### Decision Boundary

Decision Arbitration filters, compares, selects, traces, rejects, and reconsiders Decision Candidates under Constitution, Self, Goal, Value, risk, capability, and resource constraints. Decision is not Action and does not own task lifecycle or Runtime execution.

### Task Lifecycle

Task Manager owns approved task lifecycle, dependency, interruption, capability routing candidates, and result aggregation. It does not create Intent, own Goal, perform causal judgment, select final Decision, dispatch Runtime directly, or execute Action.

### Runtime Execution

Runtime is responsible for `Execution`:

- lifecycle and tick progression within an authorized Runtime surface;
- transport of governed context, evidence, requests, trace, and outcomes;
- execution admission and stop controls when separately implemented and authorized.

Runtime is not responsible for `Cognition`. It cannot own Intent, Causal Reasoning, Memory mutation, Reality interpretation, Value judgment, Decision selection, PCN, or A/B simulation.

The existing root A3 Runtime remains the legacy engineering surface. This freeze does not relabel it as Dynamic Cognitive Architecture v2 Runtime.

### Capability / Model

Capability Governance and Model Manager govern capability identity, model identity, admission, selection candidates, health, resource, lifecycle, fallback, diagnostics, trace, and replay. Models and providers supply computation or evidence; they do not become Luna's cognitive subject, Reality Owner, Reasoning Owner, Intent Owner, or Decision Owner.

### Outcome, Experience, and Memory

Runtime and external interaction return traceable outcome evidence. Outcome evaluation and Reality Validation establish governed feedback candidates. Experience Compression transforms validated outcomes and traces into experience, guidance, pattern, and Memory-admission candidates.

Memory remains the owner of historical and experience admission, persistence, consolidation, activation, retrieval, and historical influence. Memory cannot override current Reality, directly produce Decision, mutate Self, or transfer ownership to PCN.

## 4. Frozen information-status rules

- Evidence is not Understanding.
- Observation is not Fact.
- Context is not Reality ownership.
- Hypothesis and Causal Candidate are revisable.
- Simulation Candidate is not current Reality.
- Decision Candidate is not Action.
- Outcome is not Experience until validated and processed.
- Experience Candidate is not Memory until admitted by Memory governance.
- Architecture validation is not Runtime implementation.
- Architecture freeze is not migration execution.

No Candidate may become authoritative Reality, Memory, Self state, Contract, Schema, Task execution, or Runtime command without its governed admission path.

## 5. Frozen ownership rules

Every module, schema, contract, and state transition has one final Owner and one write authority for its scope. Architecture positioning does not transfer ownership. Read access, projection, activation, recommendation, orchestration, and execution transport do not imply write authority.

Existing engineering Owners remain authoritative until a separately authorized and verified migration explicitly changes them. Future cognitive Owners remain architecture references until their own implementation and admission phases pass.

## 6. Future development effect

Once M5 receives user-terminal V2 verification and ChatGPT V3 approval, new work must:
