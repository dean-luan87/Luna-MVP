# Self / Social Self Refactoring Whitebox v1

## Ownership questions

| Question | Canonical answer |
|---|---|
| Who owns Core Identity and continuity? | Self Layer |
| Who owns capability profile and self regulation? | Self Layer |
| Who owns Role and Relationship? | Social Self Layer |
| Who owns social norms and responsibility context? | Social Self Layer |
| Who classifies social feedback before durable change? | Cognitive Integration Layer |
| Where does Emotion mount? | Self-Social Interaction / Integration boundary |
| Who owns final decision? | Brain |
| Who constrains every layer? | L0 Constitution |

## Boundary checks

- Social Self can contextualize a Role but cannot rewrite Core Identity.
- Self can report capability and stability but does not own social roles.
- Integration routes candidates but does not become a Decision authority.
- Emotion remains context-only and has no runtime calculation in this phase.
- Existing assets are mapped; no file move, deletion, or code refactor occurs.

## Verification method

The verifier checks layer definitions, boundary ownership, internal/external
cognition separation, integration candidate-only behavior, Emotion
reclassification, role/relationship ownership, Constitution protection,
conceptual migration flags, conflict updates, and planning-only imports.
