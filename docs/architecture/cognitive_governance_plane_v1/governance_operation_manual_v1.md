# Luna Governance Operation Manual v1

## New Capability integration

```text
Capability Definition
 → Registry Registration
 → Protocol Binding
 → Admission Review
 → Provider Binding
 → Evidence Validation
 → Runtime Enable Candidate
```

## New Model integration

```text
Model Registry
 → Capability Mapping
 → Resource Profile
 → Admission
 → Benchmark Candidate
 → Controlled Enable Candidate
```

Model Manager manages assets, versions, performance, resources, health, and
Capability mapping. It does not define Goal or cognition.

## Protocol change

```text
Change Proposal
 → Compatibility Review
 → Version Upgrade
 → Migration Plan
 → Admission
 → Activation Candidate
```

Breaking changes require a new version, consumer inventory, rollback, and
explicit activation. Deprecated protocols remain available for migration.

## Authority change

```text
Authority Proposal
 → Constitution Check
 → Risk Review
 → Compatibility Review
 → Approval Candidate
 → Activation / Revocation
```

No Capability, Provider, Model, Registry, Diagnostics, or Runtime component
may grant itself permission.

## Failure handling

```text
Failure
 → Diagnostics
 → Classification
 → Fallback Candidate
 → Capability / Resource / Protocol Update Candidate
```

Failure is not an automatic Action, Goal change, Decision change, or Reality
write. Record owner, provenance, correlation, confidence, unknowns, and next
review.

## Change management rules

Every change proposal states scope, owner, Constitution impact, affected
protocols/registries, compatibility, migration, rollback, diagnostics, and
user-terminal verification command. Passed assets and checks are not weakened
or deleted.

New Protocol changes follow Change Proposal and Compatibility Review. Passed
assets are not deleted.
