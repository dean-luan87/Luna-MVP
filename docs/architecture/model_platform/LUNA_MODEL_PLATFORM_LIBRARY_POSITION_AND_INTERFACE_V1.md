# Luna 图书馆在这套体系里的位置与接口 v1

> 四方关系：**个体 Luna** — 使用、生产、留痕；**图书馆** — 提炼、归类、沉淀、生成经验资产；**蜂巢** — 评分、比较、提建议；**中台** — 治理、路由、升降级、执行。  
> 图书馆**不能**越位成中台，也**不能**缩成纯存储。  
> 配套：宪法 **第十四条**；`LUNA_MODEL_PLATFORM_MIDPLATFORM_HIVE_CONSUMPTION_V1.md`、`LUNA_MODEL_PLATFORM_HIVE_SCORING_FRAMEWORK_V1.md`。

---

## 一、图书馆的定位（一句话）

**图书馆是模型经验与任务经验的加工中枢，不是执行中枢，不是治理中枢。**

核心不是「调用模型」，而是：

- 收集经验  
- 提炼经验  
- 归类经验  
- 验证经验  
- 形成可复用经验包  
- 向蜂巢和中台提供高质量材料  

---

## 二、图书馆在整个闭环里的位置

完整闭环：

1. 个体 Luna 运行  
2. 白盒留痕  
3. **图书馆提炼经验**  
4. 蜂巢对模型/策略评分并给建议  
5. 中台消费建议并治理  
6. 新配置/经验再回流个体 Luna  

**图书馆位置**：个体 Luna 与蜂巢之间的 **「经验加工层」** — 不是前台，不是最终决策层。

---

## 三、图书馆的四类核心职责

### 1. 经验归档职责

把个体 Luna 跑出的真实数据，转成可检索、可归类的经验资产。

例如：某类长语音常触发 clarification；某模型在 mixed 下易漏 non-task；某任务链在某场景常出错。

**一句话**：把散乱留痕变成「经验对象」。

---

### 2. 经验提炼职责

从大量记录中提炼：

- 共性问题  
- 共性模式  
- 共性成功路径  
- 高价值失败模式  

**一句话**：把「发生过的事」变成「有意义的经验」。

---

### 3. 经验验证职责

须区分：个例 vs 可复用规律；偶发噪声 vs 高价值经验。

须做：去噪、去重、交叉验证、样本量判断、有效性判断。

**一句话**：图书馆不是垃圾堆，是经验筛选器。

---

### 4. 经验打包职责

把验证通过的经验整理成：

- 给蜂巢看的经验包  
- 给中台看的经验包  
- 给个体 Luna 调用的轻量经验包  

**一句话**：经验要能再利用，不只是存。

---

## 四、图书馆不能做什么

图书馆**不负责**：

- 直接修改线上模型路由  
- 直接替换主模型  
- 直接改治理规则  
- 直接下发强制策略  
- 直接替个体 Luna **当前轮**拍板  

图书馆**只能**：提供经验材料、经验结论**候选**、经验包；**不能**自己决定线上怎么改。

---

## 五、图书馆与个体 Luna 的接口

### A. 个体 Luna → 图书馆（上行）

建议固定 **三类**：

| # | 类型 | 示例 |
|---|------|------|
| 1 | **使用记录摘要** | 用了哪模型、哪类任务、latency/success/fallback |
| 2 | **质量问题摘要** | validator、mixed 保留、clarification、任务候选冲突 |
| 3 | **事件上下文摘要** | 任务域、环境、链路状态、强切/续接等 |

**上行原则**：非原始数据无脑全量；先经白盒/中台裁剪为**可归档摘要**。

---

### B. 图书馆 → 个体 Luna（下行）

当前阶段建议只允许 **两类**：

| # | 类型 | 示例 |
|---|------|------|
| 1 | **经验包候选** | 某类任务常见 clarification 模板；mixed 常见切分模式；某场景经验摘要 |
| 2 | **历史记忆辅助信息** | 上次同类任务成功路径；对象历史匹配等 |

**下行原则**：不是「命令」，是**辅助材料**；是否采用由个体主链/中台治理决定。

---

## 六、图书馆与蜂巢的接口

### 图书馆 → 蜂巢

给 **高纯度经验材料**，非原始日志。建议固定 **三类**：

| # | 类型 | 示例 |
|---|------|------|
| 1 | **模型问题经验包** | 某模型在某域持续 timeout；mixed 漏切分；非法映射倾向 |
| 2 | **任务经验包** | 哪类任务易 clarification；哪类适合规则链/外部 API |
| 3 | **优化线索包** | prompt/schema/fallback 侧共性线索 |

**一句话**：蜂巢拿到的是「高价值可分析输入」。

---

### 蜂巢 → 图书馆

反向**不是**强命令；建议固定 **两类**：

| # | 类型 | 示例 |
|---|------|------|
| 1 | **重点观察方向** | 多收某模型某域失败样本；观察某风险/新模型 mixed |
| 2 | **经验提炼要求** | 补某域经验包；补 clarification 归因样本；补测试样本 |

**一句话**：蜂巢可指导「往哪看」，**不能**代替图书馆筛选。

---

## 七、图书馆与中台的接口

### 图书馆 → 中台

**不能**给「命令」，只能给：

| # | 类型 | 示例 |
|---|------|------|
| 1 | **经验材料引用** | 某建议背后的经验包链接；降级建议的经验支撑 |
| 2 | **经验验证结果** | 非偶发、多个体已验证 |
| 3 | **测试样本集** | 回归集、灰度前验证集、专项样本 |

**一句话**：给**证据**，不是动作。

---

### 中台 → 图书馆

中台可要求：

| # | 类型 | 示例 |
|---|------|------|
| 1 | **补证据** | 某蜂巢建议证据不足，补样本 |
| 2 | **补测试** | 某模型灰度前补回归集 |
| 3 | **补经验包** | 某任务域扩展前先补材料 |

## 八、图书馆对象模板（三类）

### 1. Library Experience Record（最小经验记录）

| 字段 | 说明 |
|------|------|
| `experience_id` | 唯一标识 |
| `source_scope` | 来源范围 |
| `source_task_type` | 任务类型 |
| `source_model_id` | 模型（可选） |
| `problem_type` | 问题类型 |
| `context_summary` | 上下文摘要 |
| `evidence_refs` | 证据引用 |
| `raw_confidence` | 原始置信 |
| `library_status` | 馆内状态 |

**作用**：单条经验落库。

---

### 2. Library Experience Package（经验包）

| 字段 | 说明 |
|------|------|
| `package_id` | 唯一标识 |
| `package_type` | 包类型 |
| `applicable_domains` | 适用域 |
| `applicable_models` | 适用模型 |
| `summary` | 摘要 |
| `key_patterns` | 关键模式 |
| `supporting_experiences` | 支撑经验 ID |
| `validation_level` | 验证级别 |
| `recommended_usage` | 推荐使用方式 |

**作用**：供蜂巢/中台/个体 Luna 复用。

---

### 3. Library Validation Record（验证记录）

| 字段 | 说明 |
|------|------|
| `validation_id` | 唯一标识 |
| `target_package_id` | 目标经验包 |
| `validation_scope` | 验证范围 |
| `sample_size` | 样本量 |
| `validation_result` | 结果 |
| `confidence_level` | 置信度 |
| `notes` | 备注 |

**作用**：证明经验包是否站得住。

## 九、图书馆在三大主体中的独立边界

| 相对谁 | 图书馆**不是** |
|--------|----------------|
| 个体 Luna | 前台推理器；不负责当前轮任务理解 |
| 蜂巢 | 评分器；不负责模型总评分与全局定位 |
| 中台 | 治理器；不负责升降级与上线生效 |

**正确定位**：**经验加工层**。

---

## 十、图书馆最小宪法条款（四条）

1. **条款 1**：图书馆只提供经验材料、经验包和验证结果，**不直接下发**线上强制动作。  
2. **条款 2**：必须先提炼、再验证、再打包；**禁止**原始经验直接进入中台治理链。  
3. **条款 3**：可向蜂巢提供经验输入，可响应中台补证据请求；**不能**替代蜂巢评分与中台裁决。  
4. **条款 4**：下发给个体 Luna 的只能是**辅助经验**；不得以经验包形式**绕开**主链治理。  

（已并入模型中台宪法 **第十四条**，本条为展开说明。）

## 十一、四方关系一句话

| 主体 | 负责 |
|------|------|
| **个体 Luna** | 生产、使用、留痕 |
| **图书馆** | 提炼、验证、打包 |
| **蜂巢** | 评分、比较、提建议 |
| **中台** | 消费建议、治理执行、升降级、灰度与回滚 |

---

## 十二、一句话收束

图书馆在本体系中**不是存储层、不是裁决层**，而是 **经验加工层**：向上喂蜂巢，向侧面给中台**证据**，向下给个体 Luna **辅助经验**，**不直接碰线上治理**。
