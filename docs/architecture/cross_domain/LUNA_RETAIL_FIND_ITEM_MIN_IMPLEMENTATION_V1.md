# 超市找商品闭环：最小实现方案（V1）

## 1. 为什么选它做第三条旁路

在 `risk_interrupt_v1`（安全抢占）与 `sidewalk_nav_v1`（室外通行）已按同一方法论落地的前提下，第三条旁路若继续只做「更深导航」，能力面会偏窄、主线易被绑成单线。

**超市找商品**作为第三条，能验证另一类跨域闭环：

| 维度 | 与已有两条的互补 |
|------|------------------|
| 目标类型 | **非安全型**任务闭环（找货/对齐货架），不以风险抢占为主叙事 |
| 管线特征 | **环境 gating → 条件触发 OCR → 细节补证**，与「人行道默认少 OCR」形成对照 |
| 主线结构 | 补齐「零售货架语境」下的语义与任务链更新，不把系统拉回纯导航单线 |

本方案**不是**复杂购物系统、比价、促销或结账流程；只回答最小闭环如何跑通。

---

## 2. 最小闭环定义（V1）

闭环最小包含：

1. **环境识别层**：先判断当前是否进入 **零售货架环境**（最小等价：`scene_type=retail_shelf` 或 `retail_aisle`，置信度可低但需可解释）
2. **任务对齐**：用户意图为「找某商品」（商品名/类别来自语音或任务链，V1 可规则占位）
3. **条件触发 OCR**：仅在 gating 通过且满足下文触发条件时，对 **局部 ROI** 做 OCR（非全画面常驻）
4. **结果汇合**：OCR 文本 + 环境标签 → **语义层**（解释、纠错、用户可理解表述）→ **任务链**（步骤推进：已定位货架区 / 已看到标签 / 需挪步等）
5. **输出裁决**：决定本轮 **播什么**；其余进 **白盒**

---

## 3. 环境识别层：先判断「零售货架环境」

- **目标**：在进入 OCR 与细节补证之前，先回答「是不是超市/货架通道语境」，避免在非零售场景误触发 OCR。
- **最小输出**：
  - `scene_type`：`retail_shelf`（或团队统一枚举名）
  - `retail_context_confidence`：0~1
  - `gating_passed`：布尔；仅当为 true 时，才允许进入「可触发 OCR」状态机（V1 可用规则/轻量分类占位，**不强制**新增视觉大模型；与既有视觉主链策略对齐）

---

## 4. 在什么条件下触发 OCR（V1）

同时满足下列 **最小集合** 才触发（缺一不可，可再收紧）：

1. `gating_passed == true`（零售货架环境初判通过）
2. 存在 **明确找货任务**（任务链或本轮用户意图标记为 `find_item`）
3. **下列至少一条**：
   - 用户主动说「帮我看下这排写的什么」「标签上是什么」（显式请求文字）
   - 系统判断 **需要文字才能推进任务**（例如已到达目标货架区，但仍缺 SKU/价格带信息；V1 用简单规则：缺字段则允许一次 OCR）
4. **频控**：同一任务在短时间窗口内 **OCR 次数上限**（V1 写死如每任务 N 次/每分钟 M 次），避免刷屏与耗电

**默认不触发**：仅在通道行走、未对齐货架、无找货任务时，**不**跑 OCR。

---

## 5. OCR 结果如何进入语义层 / 任务链

### 5.1 语义层

- **输入**：OCR 原始文本 + 置信度 + ROI 说明 + 当前商品查询词（若有）
- **职责**：
  - 将碎片文字整理为 **短句事实**（如「第三层标签含牛奶二字」）
  - 与用户说的商品名做 **弱匹配**（同音、简称），不保证 SKU 级精确（V1）
  - 产出 **给用户听的解释候选**（可多条，由输出裁决选一条）

### 5.2 任务链

- **最小更新**：
  - `task_step`：例如 `approaching_shelf` → `reading_label` → `item_maybe_found` / `need_move`
  - `task_evidence`：保留 OCR 摘要、时间戳，供白盒与后续轮次使用
- **不写死**：完整购物车、多商品并行优化（V1 不做）

---

## 6. 哪些信息直接播报，哪些只留白盒

| 类型 | 建议（V1） |
|------|------------|
| **可直接播报** | 与用户问题强相关的一句结论（如「这一层标签上有酸奶」）；任务链关键状态变化（如「已对齐目标货架区」若产品需要） |
| **只留白盒、默认不播** | OCR 全文原始串、ROI 坐标、多候选列表、低置信识别、中间调试字段 |
| **降级** | 支持 **whitebox-only** 模式：仅更新任务链证据与 metadata，**不外显**导购句，与既有旁路「先观测再放开」一致 |

具体开关与键名在后续《代码计划 V1》中写死；本方案只定原则。

---

## 7. 与已有旁路的关系（固定边界）

- **不与 `risk_interrupt_v1` 抢优先级叙事**：在零售区内若出现安全风险，仍以风险链为准；找货提示可被压制（与 `sidewalk_nav_v1` 同类：**安全 / 高风险摘要优先**）。
- **与 `sidewalk_nav_v1` 互斥语境**：室外人行道 vs 室内货架；环境 gating 应先分流，避免同一帧混用两套闭环（实现阶段用 `scene_type` 裁决）。

---

## 8. 当前阶段不做什么（写死）

- 不做完整 **路径规划**、跨区调货、库存对接
- 不做 **促销/比价/会员** 与支付
- 不做 **高复杂多模态融合**（多模型并行投票）；V1 仅「gating + 条件 OCR + 语义汇总 + 任务链小步」
- 不把 OCR 作为 **全时段主链路**（避免与「人行道默认少 OCR」方法论冲突）
- 不默认接入主链：第三条仍按 **旁路 + 默认关闭 + 可白盒** 的工程方法演进

---

## 一句话收束

第三条旁路用 **超市找商品** 的最小闭环，专门验证 **零售货架环境 gating → 条件 OCR → 细节补证 → 语义与任务链**，与安全链、人行道链并列，形成更均衡的跨域能力面；本文件只定方案边界，后续再进入代码计划与实现切片。
