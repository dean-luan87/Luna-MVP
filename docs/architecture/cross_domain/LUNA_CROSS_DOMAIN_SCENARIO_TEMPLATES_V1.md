# LUNA：跨链闭环场景模板（V1｜第一批日常生活场景）

## 1. 目标

把第一批 3 个日常生活跨链闭环场景，正式收成统一模板文档，作为后续：

- 实现优先级排序
- 白盒观测设计
- 模型测试板块

的共同输入。

本文件只做逻辑设计：不写实现代码、不接新模型、不扩展更多场景。

## 2. 统一模板结构（每个场景固定 9 段）

1. 场景目标  
2. 起点输入  
3. 视角链处理  
4. 语义层处理  
5. 任务链处理  
6. 输出裁决  
7. 白盒记录  
8. 当前阶段不做项  
9. 后续模型测试关注点  

---

## 场景 1：出门后的人行道导航闭环

### 1) 场景目标

验证最基础的日常出行闭环是否成立：

- 识别室外道路/人行道环境
- 判断可通行方向
- 识别近距离风险
- 结果进入语义与任务链
- 输出当前最必要的一句导航提示

### 2) 起点输入

- 视角输入：道路、人行道、路口、行人、车辆、台阶、围挡、树池等
- 位置输入：GPS 粗定位
- 记忆输入：是否存在“回家/去公司/去常去地点”的历史目标
- 任务输入：用户明确说过“带我去某地”或系统已有导航任务
- 状态输入：当前是否在行走中

### 3) 视角链处理

**环境识别层**：

- 输出：`scene_type=outdoor_walkway`、`path_confidence`、`crossing_nearby` / `sidewalk_present` / `road_edge_present`

**细节识别层**：

- 默认不主动触发 OCR
- 仅在“有明确交通标识/路牌、路径判断不稳、用户主动问路”时触发补证

**风险与行为层（快扫）**：

- 来车 / 路缘 / 台阶坑洞 / 迎面密集行人 / 施工围挡
- 输出：`risk_level`、`risk_type`、`safe_direction_hint`

**汇总决策层**：

- 合并“道路环境 + 风险情况 + 导航目标”成最小通行建议

### 4) 语义层处理

- 不重做视觉判断，只负责解释与吸收偏好：
  - 有导航任务 → 环境/风险作为导航上下文变量
  - 无导航任务 → 输出为通行建议态
  - 吸收偏好记忆（避开人多/避开马路边等）

### 5) 任务链处理

- 有主任务：映射为任务步骤（继续直行 / 靠右避开 / 路口准备右转）
- 无主任务：不新建复杂任务，仅维持“通行建议态”

### 6) 输出裁决

依据《`LUNA_UNIFIED_OUTPUT_ARBITRATION_V1.md`》的优先级：

- **必须直接播报（风险类）**：
  - “前方有人迎面，请稍靠右”
  - “右侧接近车道，请往左一点”
  - “前方有台阶，请注意”
- **可作为任务关键提示播报**：
  - “沿人行道继续直行”
  - “前方路口右转”
- **不应立即播报**：
  - 背景环境丰富描述
  - 低价值补充信息

### 7) 白盒记录

- `scene_type`
- `risk_level`
- 是否触发细节补证（OCR/局部）
- 任务链是否更新
- 最终输出类型：风险播报 / 任务关键提示 / 仅白盒

### 8) 当前阶段不做项

- 不做复杂路径重规划
- 不做完整地图构建
- 不做复杂交通灯逻辑
- 不做多模型协同
- 不做社交行为复杂预测

### 9) 后续模型测试关注点

- 环境识别是否成立（室外道路/人行道分类是否合理）
- OCR/细节触发是否合理（默认不触发；触发理由是否正确）
- 风险优先级是否正确（danger/caution 是否能抢占）
- 语义层是否正确吸收场景变量（偏好/任务上下文）
- 任务链是否接得住（步骤更新是否稳定）
- 输出裁决是否符合优先级（不重复、不刷屏、风险不延迟）
- 白盒是否可观测（scene/risk/trigger/route/decision）

## 场景 2：进入便利店 / 超市找商品闭环

### 1) 场景目标

验证“环境识别先定场景，再按场景触发 OCR/细节识别”的逻辑成立：

- 系统先知道当前在零售环境
- 工作重心转向货架/商品/标签/价格
- 不把道路导航逻辑错套进来

### 2) 起点输入

- 视角输入：货架、商品排面、价格牌、购物篮、通道、促销标识
- 位置输入：GPS 粗定位或进入室内后的失真定位
- 记忆输入：是否知道用户正在找某商品
- 语音输入：用户是否说“帮我找矿泉水/纸巾/药”
- 状态输入：行走寻找态 vs 驻足查看态

### 3) 视角链处理

**环境识别层**：

- 输出：`scene_type=retail_shelf`、`retail_confidence`、`shelf_visible`

**细节识别层（主工作层）**：

- 触发条件：环境稳定为零售 + 有找商品意图/驻足货架
- 做：OCR 读标签/价格/规格/品牌，必要时局部放大

**风险与行为层**：

- 默认降权，仅做低频快扫（障碍/人群/购物车）
- 触发安全事件时才提权插入

**汇总决策层**：

- 合并“货架环境 + OCR 商品结果 + 用户目标”成找商品建议

### 4) 语义层处理

- 判断：是否在找商品、OCR 候选与目标相关性
- 吸收偏好：品牌/价格区间/容量偏好

### 5) 任务链处理

- 明确找商品任务：轻量任务链（到货架→扫描→锁定→确认位置）
- 无明确商品任务：仅维持浏览辅助态

### 6) 输出裁决

- **必须播报**：
  - “右前方货架中层有矿泉水”
  - “你面前这一排是纸巾区”
  - “前方有购物车经过，请稍等”（风险插入）
- **不应立即播报**：
  - OCR 全量结果
  - 与目标无关的价格信息
  - 低相关商品信息
- **用户追问时再答**：
  - 品牌/规格/价格细节与对比

### 7) 白盒记录

- `scene_type=retail_shelf`
- 是否触发 OCR
- OCR 是否命中目标商品
- 是否存在风险插入
- 输出去向：直接播报 / 等追问 / 仅白盒

### 8) 当前阶段不做项

- 不做复杂购物推荐
- 不做全货架盘点
- 不做营养深度分析
- 不做购物篮长期记忆
- 不做多商品优化排序

### 9) 后续模型测试关注点

- 环境识别是否成立（零售场景识别稳定性）
- OCR/细节触发是否合理（只在零售稳定 + 明确意图/驻足时触发）
- 风险插入是否正确降权/提权（默认不抢主导，安全事件可插入）
- 语义层是否正确做相关性判断（避免错把相邻货架当目标）
- 任务链是否接得住（找商品轻量任务链状态切换）
- 输出裁决是否稳定（不播报 OCR 全量、低相关只进白盒/追问）
- 白盒是否能观察到命中与否（hit/miss + reason）

## 场景 3：行走中遇到风险打断闭环

### 1) 场景目标

验证风险链是否具备真正抢占权：

- 任务进行中风险能直接打断
- 输出裁决优先安全
- 风险解除后任务可恢复

### 2) 起点输入

- 视角输入：快速接近的自行车/电动车/行人、台阶、积水、围挡、狭窄口
- 当前任务：导航/找路/找物进行中
- 环境输入：人行道/路口/通道/站内等
- 行为状态：用户正在前进

### 3) 视角链处理

**环境识别层**：

- 只保留上下文，不抢主导（室外人行道/商场通道/站口区域等）

**细节识别层**：

- 默认降权，不因看到牌子就先 OCR（让位风险链）

**风险与行为层（主导）**：

- 输出：`risk_level=high/critical`、`interrupt_required=true`、`avoidance_hint`

**汇总决策层**：

- 风险提权，其它链路降级

### 4) 语义层处理

- 只做最小可说解释（配合安全表达，不拥有主导权）

### 5) 任务链处理

- 必须支持：挂起当前任务 → 插入风险事件 → 风险解除后恢复/重算

### 6) 输出裁决

- **直接抢占播报**：
  - “停一下，前方有车”
  - “右侧有人快速接近，请先靠左”
  - “前方有围挡，请不要继续直走”
- **被压下去的输出**：
  - 当前导航下一步
  - 环境补充描述
  - OCR 细节结果
- **风险解除后**：
  - 恢复原任务播报或输出新的通行建议

### 7) 白盒记录

- 原任务是什么
- 风险类型与等级
- 是否发生抢占
- 哪条输出被中断
- 是否恢复原任务
- 最终给用户播报了什么

### 8) 当前阶段不做项

- 不做复杂多对象轨迹预测
- 不做长时序行为建模
- 不做复杂社交意图判断
- 不做全局路径重规划
- 不做完整风险学习模型

### 9) 后续模型测试关注点

- 风险识别是否足够敏感（danger/caution 触发是否及时）
- 风险是否能抢占输出（preempt 是否生效，危险不延迟）
- 任务链是否接得住抢占/挂起/恢复（状态机一致性）
- 语义层是否不过度展开（安全期只做最小表达）
- 输出裁决是否符合优先级（安全 > 任务 > 解释；被压下的是否正确）
- 白盒是否完整记录抢占/中断/恢复链路（含被中断输出候选）

## 3. 文档结尾说明（为什么先选这 3 个）

### 3.1 为什么第一批先选这 3 个

- 覆盖“日常通行”的基本闭环（场景 1）
- 覆盖“安全抢占”的核心机制（场景 3）
- 覆盖“环境 gating → OCR/细节补证”的补充链机制（场景 2）

### 3.2 它们分别覆盖的核心机制

- 场景 3：验证统一输出裁决口与任务链抢占/恢复是否成立
- 场景 1：验证环境识别 + 风险快扫 + 任务链更新的基础配合
- 场景 2：验证环境稳定后触发 OCR/细节，并控制其不刷屏/不误导

### 3.3 后续复杂场景如何扩展

后续复杂场景（地铁站、医院、政务大厅等）将在本模板基础上扩展：保持 9 段结构不变，只替换场景输入与触发规则细节。
