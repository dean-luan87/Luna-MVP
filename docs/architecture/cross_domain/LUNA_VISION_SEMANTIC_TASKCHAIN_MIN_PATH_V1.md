# LUNA：视角 × 语义 × 任务链 最小打通路径（V1）

## 1. 目标

在《视角主线分层 / 接口与状态对象 / 最小运行链》已就位的前提下，本文件把主线继续推进到**跨链路最小闭环**：

- 从“看见（Vision）”到“理解（Semantic）”到“任务/播报（TaskChain/Feedback）”
- 明确：**谁先消费视角结果、谁决定播报、谁决定打断任务、任务链如何接住视角事件、语义层如何把环境变量变成解释能力**

本文件仍然只做逻辑设计：

- 不写实现代码
- 不接新模型
- 不改现有语义主链逻辑
- 不改现有任务链逻辑

## 2. 最小打通闭环定义（V1）

### 2.1 闭环的“最小成功标准”

只要满足以下条件，即认为“最小闭环打通”：

1. 视角主链输出一个结构化 `SummaryDecision/summary_packet`（可包含环境/风险/细节补证）
2. 上层至少有一个消费者明确消费该输出，并产生**用户可感知结果**（播报/提示/任务策略变化之一）
3. 白盒能记录“输出去了哪里、是否被消费、是否触发播报、是否发生打断/降级”

### 2.2 闭环的最小路径（概念顺序）

1. **视角输入进入**（图像/视频片段 + `task_context_hint`）
2. **视角最小运行链**产出：
   - `EnvironmentState`（环境限制变量）
   - `RiskEvent`（风险等级与行为建议，可中断补充链）
   - `DetailEvidence`（可选：OCR/局部补证）
   - `SummaryDecision.summary_packet`（统一交付包）
3. **语义层消费（解释层）**：
   - 吸收环境变量为上下文（不越界做任务决策）
4. **任务链消费（执行层）**：
   - 仅接收“与执行/路线/动作相关”的高优先级事件（尤其风险打断）
5. **播报/反馈层消费（对用户输出）**：
   - 风险事件可绕过语义解释，直接触发安全播报（安全优先）
6. 白盒记录跨链路路由结果

## 3. 三条链的职责边界（写死）

### 3.1 视角链（Vision Mainline）

**负责**：

- 产出：环境状态（限制变量）、风险事件（安全优先）、细节补证（可选）、汇总决策包（结构化）
- 明确：是否建议中断补充链（`interrupt_supplementary_flows`）
- 保证：风险判断优先且可解释（理由/证据来源/置信度）

**不负责**：

- 不生成最终播报文案（避免把“解释/措辞”提前做掉）
- 不直接改写任务链状态（只输出事件与建议）
- 不把 OCR/细节当作全局主导

### 3.2 语义链（Semantic / Understanding）

**负责**：

- 把视角输出转成“可解释的上下文变量”，用于对话/解释策略
- 将环境变量纳入语言理解（例如：室外道路/低光/拥挤 → 解释风格与提醒策略）
- 对用户提出澄清/补拍请求的**语言表达与交互策略**（但不抢任务链裁决权）

**不负责**：

- 不替任务链做“是否执行/是否打断”的最终决策
- 不覆盖风险层的安全结论（可解释，但不稀释安全优先级）

### 3.3 任务链（TaskChain / Execution）

**负责**：

- 接收与执行直接相关的视角事件（特别是风险打断）
- 在任务进行中决定：继续/暂停/绕行/请求用户动作（例如“停下再拍一张”）
- 与既有任务上下文合并，保持执行一致性

**不负责**：

- 不对环境/风险做“感知推理”（应消费视角输出）
- 不将低置信度细节补证当作强事实直接执行

## 4. 最小协同顺序（V1）

建议的最小协同顺序（语义顺序）：

1. **视角先出风险快扫**（RiskEvent）→ 给播报/任务链一个“安全底线”
2. **视角出环境变量**（EnvironmentState）→ 给语义层“解释上下文”
3. **按条件触发细节/OCR**（DetailEvidence）→ 只补证，不抢裁决
4. **汇总层出 summary_packet**（SummaryDecision）→ 统一交付
5. **播报/反馈**优先消费风险事件（可绕过语义解释）
6. **语义层**消费环境变量与补证，用于解释与交互
7. **任务链**只消费“可执行相关”的高优先级事件（尤其 risk 打断）

## 5. 高优先级插入规则（打断/不打断）

### 5.1 风险类事件何时可以打断任务链（写死）

当 `risk_level=danger`：

- 必须允许：
  - 直接触发安全播报（可绕过语义层）
  - 作为**高优先级插入事件**进入任务链（可暂停/中断当前任务）

当 `risk_level=caution` 且环境限制变量指向风险快速变化（车流/动态障碍/低光）：

- 允许：
  - 触发更保守的任务策略（例如减速/提示注意/请求确认）
  - 中断/降级补充链（OCR/局部）

### 5.2 环境变化何时只更新上下文、不打断任务

当环境变化不涉及即时安全风险，且与当前任务执行无直接冲突：

- 默认策略：**只更新语义层上下文**（用于解释/提示风格）
- 不应打断任务链执行

示例：从“室内 → 室外”，但风险仍为 safe，任务链继续导航即可。

### 5.3 OCR/细节结果何时进入任务链、何时只作语义补证

- **进入任务链（可执行相关）**：当 OCR/细节提供了“任务必需且置信度足够”的执行参数（例如明确的出口编号/门牌/路标，且与任务上下文强相关）
- **只作语义补证**：当 OCR 只是解释性信息、或置信度不足、或与环境/风险结论存在冲突（此时应触发澄清/补拍，而不是直接执行）

## 6. 输出裁决口（最小口径写死）

为避免跨链路“多头播报/多头决策”，本阶段建议的最小裁决口径：

- **安全即时播报裁决权**：播报/反馈层（由风险事件触发，优先级最高）
- **任务执行裁决权**：任务链（消费风险插入事件后决定暂停/继续/绕行）
- **解释与交互裁决权**：语义层（消费环境变量与补证，决定如何说、问什么、要不要补拍）

> 说明：本阶段不引入“统一大脑裁决模块”的实现，只先把裁决边界写清，避免互相越界。

## 7. 最小典型场景（至少 3 类）

### 7.1 正常导航场景（不打断）

- 视角：环境=道路/室外；风险=safe；细节不触发或仅补证
- 语义层：把环境变量作为上下文（解释/提示更贴合场景）
- 任务链：不被打断，继续导航
- 播报：不主动输出风险播报（可选轻提示）

### 7.2 风险打断场景（安全优先）

- 视角：风险=danger（动态障碍/碰撞风险）→ `interrupt_supplementary_flows=true`
- 播报层：直接安全播报（绕过语义解释）
- 任务链：高优先级插入，暂停/提示用户动作
- 语义层：后续提供解释/安抚/下一步交互（不改变“先安全”）

### 7.3 环境识别后触发 OCR / 细节补证场景（补充链）

- 视角：环境初判提示“需要文字信息”→ 触发 OCR/局部
- OCR：给出标识/路牌/门牌（高置信才进入任务链）
- 语义层：将 OCR 作为补证用于解释与澄清
- 任务链：仅在置信足够且与任务强相关时消费，否则请求补拍/确认

## 8. 白盒观测（跨链路最小集合）

跨链路至少记录以下观测字段（语义，不锁实现）：

- `vision_output_routed_to_semantic`（bool）
- `vision_output_routed_to_taskchain`（bool）
- `vision_output_triggered_feedback`（bool）
- `vision_output_whitebox_only`（bool）
- `interrupt_happened`（bool）与 `interrupt_reason`
- `degrade_happened`（bool）与 `degrade_reason`
- `consumer_decisions`：语义层/任务链/播报层各自是否消费、消费了什么类别输出
