# 人行道导航闭环：最小实现方案（V1）

## 1. 目标

人行道导航闭环是第一批场景中的第二优先（见《`docs/architecture/cross_domain/LUNA_CROSS_DOMAIN_SCENARIO_PRIORITY_V1.md`》）。

它是“日常主路”的底座：验证 **环境识别 + 风险快扫 + 任务链更新 + 输出裁决** 的基础配合，为后续地铁站/医院/商场等复杂场景提供底盘。

本方案当前只回答一句话：

> **在不新增视觉模型的前提下，人行道导航闭环“现在最小怎么跑”？**

## 2. 最小闭环定义（V1）

闭环最小包含：

1. 视角给出：当前为室外/人行道环境（或最小等价的 `scene_type=outdoor_walkway`）
2. 风险快扫：识别近距离危险（来车/路缘/台阶/迎面人群/围挡等）
3. 在“已有导航任务”或“轻任务态”下，产出最小通行提示（方向/靠边/停下等）
4. 结果进入：语义层（解释/偏好吸收）+ 任务链（步骤更新标记）+ 输出裁决口（决定播报什么）

## 3. 最小输入（V1）

至少包括：

- 视角环境信息（scene_type/可通行空间连续性/置信度）
- 风险快扫结果（risk_level + 简要 risk_type + safe_direction_hint）
- GPS 粗定位（可选，但建议）
- 已有导航任务（若存在）
- 用户偏好/记忆（例如避开人多、靠边走等；可选但建议）

## 4. 最小处理步骤（V1）

### Step 1：环境初判（快链）

- 目标：判定是否为室外道路/人行道环境，输出 `scene_type=outdoor_walkway` + `path_confidence`

### Step 2：风险快扫（安全优先链）

- 目标：输出 `risk_level` 与最小可执行的 `safe_direction_hint`
- 注：风险快扫优先级高于普通导航提示

### Step 3：细节补证（默认少触发）

- V1 默认尽量不触发 OCR
- 仅在：
  - 路径判断不稳
  - 用户主动问“这里是哪/怎么走”
  - 前方出现明确交通标识且与任务强相关
  才触发补证（仍不作为主导）

### Step 4：生成最小通行建议

- 合并：环境初判 + 风险快扫 +（可选）导航任务
- 产出：
  - 风险提示（若有）
  - 当前通行方向建议（直行/稍靠右/稍靠左/停下等待）

### Step 5：输出给语义层与任务链

- 语义层：吸收环境变量与偏好，生成解释/交互策略
- 任务链：若存在主任务，更新“当前步骤提示”或标记“已更新”

## 5. 最小输出（V1）

至少定义：

- 风险提示（可抢占）
- 当前通行方向建议（任务关键提示）
- 任务链更新标记（是否更新/更新摘要）
- 白盒记录（见第 8 节）

## 6. 与风险打断链的关系（必须写死）

- 风险打断链（risk_interrupt_v1）优先级高于普通导航提示：
  - 当 risk_interrupt 触发抢占时，人行道导航输出必须被压下去
- 以下情况任务链只更新不播报（由输出裁决口控制）：
  - 仅环境上下文更新、无风险且无任务关键变化
  - 用户处于忙碌/高负载状态（若运行态可观测）

## 7. 当前阶段不做项（写死）

- 不做复杂地图构建
- 不做交通灯完整逻辑
- 不做复杂交叉路口多阶段决策
- 不做高阶世界模型推理
- 不接入新视觉模型
- 不做复杂路径重规划

## 8. 白盒要求（最小集合）

至少记录：

- 当前 `scene_type` + `path_confidence`
- 风险快扫结果（risk_level/risk_type/safe_direction_hint）
- 当前通行建议（方向/行为）
- 是否更新任务链（及摘要）
- 最终播报内容（类别与摘要）

## 一句话收束

先把“人行道环境识别 + 风险快扫 + 最小导航提示”的闭环跑通（不新增模型、不做复杂规划），并确保风险打断链可压制普通导航提示，再进入后续最小代码实现计划阶段。
