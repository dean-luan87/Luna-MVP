# Goal Governance Model v1

## Lifecycle

```text
Detected → Candidate → Evaluated → Admitted → Active → Progressing
       → Completed / Expired → Archived
```

Transitions are governance candidates, not automatic runtime behavior. An
admission request must carry provenance, Field context, unknowns, capability
requirements, resource estimates, and a self-constraint review.

## Sources

Goal candidates may be attributed to Self-Originated Goal, User-Originated
Goal, Environment-Originated Goal, or System-Originated Goal. Attribution is
provenance, not permission. Every source remains subject to Self Goal
Governance and Constitution constraints.

## Priority

Priority is a candidate derived from Safety, Self Preservation, User Need,
Capability State, Resource Cost, and Time Constraint. This phase defines the
inputs and review boundary only; it does not implement an algorithm or make an
execution decision.

## Self review

Self owns governance of goal candidates. It may return Approved Goal, Rejected
Goal, Deferred Goal, or Revised Goal Candidate. It may not rewrite Identity,
Value, Constitution, Brain rules, or Reality, and it may not execute an Action.

Task Manager, Memory, Schema, Emotion, and B Route have no authority to create
or silently modify a goal. A proposed change must remain a candidate for later
review.
