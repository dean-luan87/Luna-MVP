# Luna Action Runtime Foundation Whitebox v1

## Audit questions

1. Is the input an Approved Action Candidate from Action Boundary?
2. Does the execution context bind action type, target, environment,
   permission, risk, timeout, and trace?
3. Is the lifecycle persistent across Requested, Approved, Executing,
   Completed, Verified, and failure states?
4. Are resource and scheduler decisions separated from Goal and Decision?
5. Does the Adapter isolate future devices and APIs?
6. Are outcomes verified against expectations, including partial success?
7. Are failure, recovery, retry, alternative, and abort candidates traceable?
8. Does the runtime remain unable to control cognition directly?

## Explicit non-authority

Action Runtime Foundation is not Brain, Decision Commitment, Goal/Value owner,
Constitution, Hardware Driver, Device, API, Provider, or Action Boundary
permission owner.
