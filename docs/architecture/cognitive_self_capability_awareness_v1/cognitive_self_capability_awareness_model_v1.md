# Cognitive Self Capability Awareness Model v1

## Purpose

This layer gives Luna a governed representation of what capabilities exist,
how reliable they are now, and where their limits are. It is Self Awareness
Infrastructure. It is Self Awareness Infrastructure, not a second cognitive
subject.

```text
Capability Identity
        ↓
Capability State
        ↓
Capability Confidence Candidate
        ↓
Self Capability Awareness
        ↓
Attention Reallocation Candidate
        ↓
A Route Confidence / Brain Awareness Candidate
```

Capability is not a Provider, not Understanding, not Reality, not a Goal, not
a Decision, and not an Action. Capability is not a Decision. A capability describes an evidence-producing
boundary. A Provider may implement a capability, but Provider identity must
not become Self Identity.

## Capability state

The allowed Capability State values are Available, Degraded, Limited,
Unavailable, and Unknown. State is a candidate until validated by Diagnostics
and admitted through the State Reducer. A degraded state lowers confidence and
may increase observation cost; it does not assert that Reality changed.

## Confidence boundary

Capability Confidence is confidence in the capability's current evidence
production, not confidence that an external proposition is true. Every
Capability Confidence Candidate carries provenance, timestamp, uncertainty,
limitation, and calibration context. Evidence Gateway remains the only route
for evidence admission into Reality Representation.

## Self capability context

Self Capability Awareness may expose capability identity, current state,
reliability range, known limitations, resource dependency, and alternative
capability candidates. It may produce Attention Reallocation Candidate and
Brain Awareness Candidate. It cannot modify Reality, Goal, Decision, Action,
Identity, or Personality. It cannot directly select a Provider or control
hardware frequency.

The Reducer remains the sole State mutation authority. Existing Capability
Registry and module baseline assets are governance and diagnostics references;
the baseline is not ordinary Runtime input.

## Prohibitions

No real model, No OCR, No SLAM, No Camera, No Hardware Runtime, No Action,
No Emotion, No Role, No Social Runtime, and No B Runtime are enabled in this
architecture-only phase. No online learning or automatic Self Model rewrite
is permitted.
