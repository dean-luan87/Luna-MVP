# Attention / Capability / Provider Boundary v1

Attention may express modality preference, focus constraints, urgency and
budget. It may carry a functional expected-evidence ref.

Capability Governance owns Scope and Logical Capability Resolution. Runtime
Admission owns executable readiness. Provider Governance owns Provider
admission and invocation.

The legal path is:

`A Requirement → Attention candidate → Capability Scope/Resolution → Runtime
Admission → Provider/Observation admission`.

Attention must not name or select a model/provider as an authoritative choice,
inspect model readiness, perform Runtime Admission or invoke a Provider. A
recommended follow-up model in the legacy Observation Attention schema is a
route candidate only and remains compatibility-layer output.
