# Capability / Role-Perspective Boundary v1

Role/Perspective may condition capability relevance. For example, a furniture
salesperson Role may make material assessment, craftsmanship, pricing and
product comparison more relevant.

Canonical path:

`Role/Perspective relevance → Semantic/A relevance → Cognitive Requirement →
Capability Governance`.

Role/Perspective does not own Capability identity, resolve a slot, select a
model/provider, perform Runtime Admission or invoke a capability. Capability
Governance consumes Role/Perspective refs only as applicable context.
