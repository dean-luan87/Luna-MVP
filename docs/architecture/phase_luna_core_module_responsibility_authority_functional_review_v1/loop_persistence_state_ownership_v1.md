# Loop Persistence State Ownership

Loop may persist IDs, refs, versions, authorized commands, grant refs, mechanical status, logical ordering/timestamps, pending candidates, closure/freeze refs, Outcome refs and trace/provenance.

It should not copy source payloads owned by A, Brain, Field, Context, Current World, Intent, Task, Capability, Observation, Experience or Memory. Reference-oriented persistence preserves source ownership and isolation.

Loop owns mechanical state only. Semantic content remains externally owned and supplied by ref.
