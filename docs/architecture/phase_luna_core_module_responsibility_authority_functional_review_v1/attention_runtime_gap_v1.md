# Attention Runtime Gap v1

## Existing assets

- candidate Attention types and validators in Cognitive State Formation;
- Attention Allocation planning adapter with L0 scan, value assessment and
  budget candidates;
- Observation Attention Layer types/schemas and UI/TestBoard planning;
- attention-gated region-intelligence dryrun assets;
- older runtime contract-only interface.

## Classification

- `NO_GAP`: conceptual need/relevance/priority boundary is now clear.
- `CONTRACT_GAP`: no single canonical A Requirement→Attention→Observation
  handoff contract.
- `ADAPTER_GAP`: legacy Goal/Task/field-centric focus paths need ownership
  narrowing and source-version handoff.
- `RUNTIME_GAP`: no unified canonical Attention runtime/owner implementation;
  existing implementations are planning, dryrun, candidate or contract-only.
- `TERMINOLOGY_GAP`: “what is worth processing”, “attention selection”,
  “observation route” and “resource governance” are used at different layers.
- `LEGACY_OVERLAP`: Cognitive State Formation and Dynamic Flow still compute
  attention-looking ranking/selection.

No new Manager, Scheduler, enum or canonical type is proposed here.
