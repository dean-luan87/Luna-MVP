# A Route / Product Loop Overlap Review

## Retain as orchestration

A Route may retain ingress, context/field handoff, A/B routing, evidence return routing, task/action handoff, output routing, and lifecycle coordination.

## Reassign or narrow

- Need/hypothesis/sufficiency/reconsideration/next-step → A
- Semantic outline transformation → Semantic Module
- Capability Scope/Resolution/Runtime Admission → Capability Governance
- Observation/evidence acquisition → Observation/FPO
- Mechanical persistence → Loop
- Goal/Concern/grant/global closure → Brain
- Decision/Action execution → their canonical governance/runtime owners

Historical Product Loop stages such as `COGNITION_READY`, `DECISION_READY`, `TASK_READY`, and `ACTION_READY` are orchestration/handoff labels, not evidence that A Route owns those semantics.

Disposition: retain orchestration, shrink semantic implication; legacy semantic stages are `R1` retirement candidates.
