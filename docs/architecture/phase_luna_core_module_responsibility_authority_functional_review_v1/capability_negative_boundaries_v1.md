# Capability Governance Negative Boundaries v1

Capability Governance must not:

- own Goal, Concern or A Need;
- judge Sufficiency or Reconsideration;
- mutate Intent, Task, Role, Field, Context or Current World;
- schedule Attention;
- own model files, paths, checksums or provisioning state;
- probe dependencies, devices or runtime health;
- load/infer models;
- select or invoke a Provider;
- create evidence or declare World Truth;
- control Loop;
- make Decision or execute Action;
- mutate Memory/Experience or Learn;
- become Planner/Scheduler;
- bypass Scope, Runtime Admission, Provider Admission or Observation Gateway.

Capability is a functional governance abstraction, not a hidden execution
authority.
