# Target Runtime Information Flow

1. Brain admits a Concern, establishes global policy, and issues an A grant.
2. Source owners provide versioned Role/Perspective, Field, Context, Current World, Task, Intent, Emotion, Attention, Experience, safety, permission, and resource refs into an A Working Envelope.
3. A selects Need, judges evidence/sufficiency, and forms a Cognitive Requirement.
4. Capability Governance performs Scope and Logical Capability Resolution.
5. Runtime Admission combines model/diagnostic/integrity/device/provider evidence into an executable candidate; it does not invoke a Provider.
6. Observation/Provider Governance admits and executes the already-authorized capability, returning evidence/current-world refs.
7. A reassesses, optionally requests B-CR, and evaluates B output. B returns only to A.
8. A/Brain supplied semantic refs are mapped to Loop mechanical commands.
9. Loop persists versions/refs/lifecycle and returns mechanical state.
10. Brain adjudicates final outcome and updates global governance.

The control plane is Brain→grant→A/B/Capability/Loop; the data plane is source refs→envelope→A/B/Capability/Observation→evidence→A. Dynamic Flow may provide computation/compatibility output, but never bypasses A.
