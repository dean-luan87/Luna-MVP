# Memory / Experience Minimal Adjudication Summary v1

## Decision

Memory and Experience are retained as separate **conceptual future governance
boundaries**, with implementation deferred. MemoryCandidate and
ExperienceCandidate are retained as minimal candidate-only handoffs.

## Responsibility

Candidate producers own source binding, version alignment, provenance,
uncertainty, and cross-Concern isolation. Brain Assimilation may authorize
handoffs. Future Memory Governance owns Memory admission/mutation; future
Experience Governance owns Experience admission/mutation. No current module
owns final Memory or Experience semantics.

## Negative boundaries

No persistence, retrieval, retention, forgetting, consolidation, semantic
compression, generalization, Learning, model update, parameter update,
self-modification, Role-memory implementation, Emotion integration, or runtime
Manager is introduced.

## Current status

Repository controlled assets include candidate types, provisional admission and
persistence handoffs, provenance, and negative guards. They remain evidence of
candidate-only infrastructure and do not close the deferred architecture.
