# Multi-Loop Boundary

Brain may govern several Concerns concurrently. Each admitted cognitive work thread may have its own isolated Loop identity and scope.

- A Concern may have multiple historical or bounded Loop instances.
- A Loop may not autonomously create child Loops.
- Any additional Loop requires Brain-governed work/Concern admission and explicit identity/scope.
- Shared read-only Intent/Task/Field refs are allowed; local mechanical state must remain isolated.

“Child Loop” in old planning abstractions is not a runtime authority.
