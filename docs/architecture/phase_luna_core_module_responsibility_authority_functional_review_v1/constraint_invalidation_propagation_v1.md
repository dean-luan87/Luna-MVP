# Constraint Invalidation Propagation v1

Safety policy change, Permission revocation, Resource change, Role/Identity
change, or Context change propagates through versioned refs/invalidation:

`constraint/source change → Working Envelope/Grant refresh → A/Attention/
Decision/Task impact refs → Runtime Admission recheck → Provider/Observation/
Action block or recheck → A/Outcome/Brain consequence assessment`.

No direct cross-owner mutation is introduced.
