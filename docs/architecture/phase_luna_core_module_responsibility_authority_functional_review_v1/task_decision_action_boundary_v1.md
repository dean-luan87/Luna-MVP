# Task / Decision / Action Boundary v1

Decision answers what should be done or authorized. Task organizes the
approved work into units, dependencies, readiness and completion conditions.
Action Governance determines whether an Action is admissible and executes it
through its own boundary.

The target path is:

`Decision candidate/adjudication → Task candidate/lifecycle → Action candidate
and capability requirements → Action/Capability governance`.

Historical Task assets that choose behavior, route a final execution target,
or create an Action are overlap. They must be narrowed to a Task constraint,
requirement, or handoff ref. Task cannot become a Decision maker or Action
executor.
