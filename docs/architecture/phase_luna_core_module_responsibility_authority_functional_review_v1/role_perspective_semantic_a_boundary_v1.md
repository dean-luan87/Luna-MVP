# Role / Perspective / Semantic / A Boundary v1

Perspective Projection and Semantic Projection are distinct.

Perspective Projection answers which additional attributes/relations become
available under Role and current Context, Intent, Task, Concern, and applicable
governance constraints. Semantic Module then
consumes the base and augmented information and organizes relations into the
Semantic Working Outline.

Semantic Module consumes Role/Perspective refs and may produce conditioned
semantic relations:

`same object + same Field + different Perspective → different semantic
projection candidate`.

Semantic Module does not create, admit, update, or invalidate Role. A consumes
the projection and judges its consequence for Need, Hypothesis, Sufficiency,
Reconsideration, and Next-step.

An augmented attribute is not an A judgment. A decides whether it changes
Need, Hypothesis, Sufficiency, Reconsideration, or Next-step.

If Perspective Projection is wrong, the projection boundary owns
transformation error. If semantic organization is wrong, Semantic Module owns
that error. If Role identity or validity is wrong, the applicable source owner
owns source error.
