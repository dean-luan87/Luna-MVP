# M02 Semantic Module / Semantic Working Outline — Module Review

## Identity and purpose

Canonical concept: Semantic Module / Semantic Working Outline. No single verified runtime owner was found in the inspected source; it is primarily a deferred contract. If removed, the architecture loses a shared semantic construction/expansion/folding representation before local A cognition, especially for short-path/filterable work.

## Functions and authority

Intended `CORE`: semantic construction, semantic expansion, semantic folding, working-outline formation. `SUPPORTING`: packaging candidate refs and provenance. `COMPATIBILITY_ONLY`: any historical semantic preprocessing that feeds A. No verified authority to select Need, judge sufficiency, decide continuation, adopt B, or control Loop. Its outputs are `CANDIDATE_ONLY` or `REFERENCE_ONLY`; no global or local semantic authority is assigned.

Responsibility is currently deferred because no unified implementation owner/API exists. A remains responsible for semantic interpretation at the admitted Concern boundary. Brain remains responsible for global governance.

## Inputs, outputs, state, lifecycle

Inputs: Brain-governed working context, Intent/Task/Role/Field/Context/Current World refs, Experience prior refs, and A/B request context. Outputs: outline/semantic candidate refs to A or a short-path filter, never a final decision. State is candidate/reference-only; no authoritative duplication. Lifecycle is assemble → expand/fold → hand off → supersede/archive, with A/Brain deciding semantic adoption.

## Communication and negative boundaries

Allowed: source owners→envelope→Semantic Module; Semantic Module→A/short-path filter; Brain may govern policy. Forbidden: Semantic Module→Loop semantic commands, direct Capability/Provider selection, direct Concern mutation, automatic Need/Sufficiency/Action. No direct implementation bypass was proven; the gap is a missing contract/runtime seam.

## Walkthroughs

1. Normal: construct an outline from refs and return a candidate to A; A decides.
2. Blocked: insufficient or stale source refs produce an incomplete candidate; no semantic adoption occurs.
3. Environment change: version change supersedes the outline; A decides whether to reassess.

## Overlap, gaps, evolution, disposition

Overlap: `TERMINOLOGY_OVERLAP` with A “semantic reasoning” and State Formation “state assembly”; possible `IMPLEMENTATION_OVERLAP` if future outline code reimplements A. Gap: `OWNER_GAP`/`RUNTIME_GAP` for a bounded outline contract, but not authorization to create a new owner in this review. It may evolve into a bounded construction/folding service, never a Brain/A replacement, Need owner, or Loop controller. **Disposition: NARROW / DEFER**.

**Ledger summary:** authority = none beyond candidate construction; responsibility = producing valid candidate/provenance; state = candidate only; receiver = A/filter; confidence = medium-low; status = deferred contract.
