# Brain Responsibility Boundary

## Responsibility ledger

| Responsibility | Initiator | Responsible owner | Receiver | Failure owner |
|---|---|---|---|---|
| Goal admission/priority | governance input | Brain | A/Task/Intent refs | Brain |
| Concern admission/split/merge | Brain or candidate from A/B | Brain | A work contexts | Brain |
| A authority grant | Brain | Brain | A | Brain |
| B derived grant policy | A request under Brain policy | Brain/A boundary | B | Brain for grant, A for request |
| Global constraint decision | Brain | Brain | all admitted paths | Brain |
| Local semantic decision | A | A | Brain/Loop | A |
| B bounded result | A starts B | B for scope compliance | A | B for execution compliance; A for adoption |
| Capability resolution | A request | Capability Governance | Runtime Admission | Capability owner |
| Provider invocation | executable candidate | Provider Governance | Observation/Evidence | Provider owner |
| Mechanical persistence | supplied command | Loop | A/Brain | Loop mechanical error |
| Outcome evaluation | outcome evidence | Outcome Evaluation Governance | Brain | Outcome owner |
| Global assimilation | accepted outcome | Brain | governed source owners | Brain |

Authority and responsibility are paired. Brain must not silently absorb a downstream error merely because it issued a grant; each grant should preserve bounded responsibility at the receiver.
