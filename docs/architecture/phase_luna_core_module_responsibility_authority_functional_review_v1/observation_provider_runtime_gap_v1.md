# Observation / Provider Runtime Gap v1

## Evidence

Observation Gateway has candidate ingress/evidence/observation types, admission
states, trace, provenance and no-truth/no-mutation guards. FPO has extensive
controlled orchestration and visual handoff assets. Runtime Admission exposes
candidate Executable Capability and Provider Admission inputs. The visual
Gateway adapter consumes already-produced visual evidence and does not invoke a
Provider.

## Gaps

- `CONTRACT_GAP`: unified Observation Request→Executable Capability→Provider contract.
- `OWNER_GAP`: FPO is historically composite; target is a narrowed boundary, not a new Manager.
- `ADAPTER_GAP`: Provider Result→Evidence and Evidence→Current World/Field seams remain distributed.
- `RUNTIME_GAP`: no runtime execution is validated by this phase.
- `LEGACY_OVERLAP`: visual/OCR/audio, A Route, B1/B2 and task observation paths.
- `TERMINOLOGY_GAP`: Observation, Evidence, ingress, result and admission names overlap.
