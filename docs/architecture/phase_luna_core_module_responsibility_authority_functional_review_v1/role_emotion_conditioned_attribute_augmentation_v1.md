# Role Attribute Augmentation and Deferred Emotion Boundary v1

## Definition

Attribute Augmentation is the derivation of additional working attributes
from existing object/world information under current Role-, Context-, Intent-,
Task-, Concern-, and applicable governance-conditioned processing.

Augmentation must be evidence-, relationship-, or source-derived. It cannot
fabricate information or rewrite base world state.

## Current Role source

Role-side augmentation primarily uses identity, social position,
responsibility, obligation, skill, domain knowledge, functional duty,
capability relevance, and relationship expectations.

## Emotion status

Emotion is `DEFERRED`, `FUTURE_MODULATION_SOURCE`,
`NOT_CURRENT_CONDITIONER`, and `NOT_CURRENT_PROJECTION_INPUT`.

This document does not define Emotion-conditioned augmentation or Role +
Emotion composition. Future Emotion integration requires separately
adjudicated Modulation / Arbitration / Self-Regulation boundaries and must not
pre-decide whether Emotion affects Perspective, Attention, Memory retrieval, A
weighting, Role augmentation, Decision, output, or a combination.

## Attribute classes

- Base Attribute — source-owned object/world information.
- Relation — source-owned or admitted relation between entities.
- Derived Attribute — computed candidate based on source refs.
- Role-Conditioned Augmentation — functional/social overlay.
- Emotion-Conditioned Augmentation — DEFERRED future concept only; not current
  canonical architecture.
- Perspective Working Attribute — view-specific derived result.

Role-derived functional value is current augmentation scope. A decides its
relevance for the current Concern.
