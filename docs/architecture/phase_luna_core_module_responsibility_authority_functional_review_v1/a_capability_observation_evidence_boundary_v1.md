# A / Capability / Observation / Evidence Boundary

## Canonical return loop

A Cognitive Need → A Cognitive Requirement → Capability Requirement → Scope → Logical Capability Resolution → Runtime Admission → Executable Capability Candidate → Provider/Observation admission → Evidence/Current World/Cognitive State update → A reassessment.

A may express the information/capability category required. It must not select model/provider, inspect checksum/dependencies, perform Runtime Admission, or invoke Provider.

Capability Governance owns Scope and Logical Resolution. Runtime Admission assesses executable readiness. Provider Governance owns provider admission/invocation. Observation/FPO owns acquisition/evidence admission. A owns the cognitive interpretation of returned evidence.

Evidence existence or Provider success never automatically establishes A Sufficiency.
