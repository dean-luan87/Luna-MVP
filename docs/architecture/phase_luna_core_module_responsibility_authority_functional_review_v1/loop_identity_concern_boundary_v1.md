# Loop Identity / Concern Boundary

Brain owns Concern identity and governance. A Loop is a persistent mechanical work thread associated with a Concern and Work scope.

- One Concern may have zero, one, or multiple governed Loop instances over time.
- One Loop may span multiple A reasoning cycles for the same admitted work.
- A superseded Concern may retain archived Loop history.
- Loop cannot create, split, merge, admit, or supersede Concern.
- Any additional Loop identity must derive from Brain-governed cognitive work/Concern admission; Loop cannot create child Loops autonomously.

Loop identity, Work scope, Concern ref and source versions must remain isolated across loops.
