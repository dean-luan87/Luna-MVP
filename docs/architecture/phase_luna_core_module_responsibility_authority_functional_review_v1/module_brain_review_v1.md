# M01 Brain — Module Review

## Identity and purpose

Canonical name: Brain Governance / Brain subject (runtime subject not yet unified). Historical names include Golden Baseline, Integrated Closure, and cognitive governance. Evidence: `capabilities/midplatform/core/brain_golden_baseline/` and `integrated_closure/`. If removed, Luna loses global Goal/Concern governance, grant issuance, safety/resource/permission adjudication, and final cognitive assimilation.

## Functions and authority

`CORE`: Goal and Concern identity/admission/split/merge, global priority, safety/permission/resource policy, authority grants, final adjudication. `SUPPORTING`: baseline/closure validation and provenance. `COMPATIBILITY_ONLY`: terminal evidence and metadata-driven governance artifacts. `LEGACY`: none proven as a runtime owner. `OUT_OF_SCOPE`: local A reasoning, B reasoning, Loop mechanics, provider/model selection, observation execution.

Brain has `AUTHORITATIVE_DECISION` for global governance and final acceptance; local semantic decisions remain A-owned. Responsibility follows each grant and global adjudication. A Brain runtime/API is a `RUNTIME_GAP`; current assets are candidate/metadata governance, not a complete runtime subject.

## Initiation, inputs, outputs, state

Initiated by the external cognitive entry/governance boundary or an existing admitted governance flow; it issues grants before bounded work. Inputs are Goal, Concern, policy, source-state versions, safety/permission/resource evidence, and outcome candidates. Outputs are grants, Concern decisions, policy decisions, and final assimilation candidates received by downstream modules or returned to Brain governance. Canonical authoritative state is intended to be Brain-owned; current source mostly exposes refs/candidates.

Lifecycle: admit → grant → receive A/B/outcome candidates → adjudicate → accept/reject/defer/assimilate → archive governance history. Loop executes only mechanical records; Brain owns semantic/global acceptance.

## Communication and negative boundaries

Allowed: Brain→A, Brain→B through A-issued derived grant, Brain→Loop for supplied governance refs, A/B/outcome→Brain. Reference/envelope paths are preferred. Forbidden: Brain directly selecting model/provider, directly doing local A reasoning, or bypassing Capability Governance/Runtime Admission. Known bypass risk is the absence of a single runtime subject/API, not a verified direct semantic bypass.

## Walkthroughs

1. Normal: admit Concern, grant A, receive A outcome, adjudicate globally; Brain does not choose evidence implementation.
2. Blocked: revoke/expire grant or deny resource; Brain owns the governance failure and downstream receives a blocked ref.
3. Changed context: receive source-version/change evidence, invalidate/reissue grants as governance policy requires; A judges local semantic impact.

## Overlap, gaps, evolution, disposition

Overlap: `STATE_DUPLICATION` risk between intended Brain state and candidate contracts; `IMPLEMENTATION_OVERLAP` with Integrated Closure metadata. Gaps: `RUNTIME_GAP` unified Brain API, `ADAPTER_GAP` change/grant invalidation propagation. Future Brain may become a runtime governance subject, never a duplicate A/B thinker or infrastructure selector. **Disposition: KEEP**, with runtime/API completion deferred.

**Ledger summary:** authority = global governance/adjudication; responsibility = grant and final decision owner; state = authoritative global refs intended; downstream = A/B/Capability/Loop/Outcome; confidence = medium; review status = baseline-complete, runtime-incomplete.
