# Memory / Experience Minimal Boundary v1

## Scope

This is a minimal information-flow adjudication, not a Memory or Experience
architecture. It freezes only candidate handoffs, provenance, future-owner
placeholders, and negative boundaries.

## Minimal definitions

**MemoryCandidate** is a governed candidate reference/package representing
information that may later be considered for Memory admission. It is not
admitted Memory.

**ExperienceCandidate** is a governed candidate reference/package representing
a bounded relation among cognition, context, decisions/actions, execution,
and outcomes that may later be considered for Experience admission. It is not
admitted Experience.

## Conceptual existence result

Memory and Experience retain separate future conceptual boundaries because
their candidate inputs and eventual responsibilities may differ. Final
implementation, ontology, storage, retrieval, lifecycle, and neural form are
**DEFERRED**.

## Current disposition

Memory: **KEEP_CONCEPTUAL_BOUNDARY / DEFER_IMPLEMENTATION**.

Experience: **KEEP_CONCEPTUAL_BOUNDARY / DEFER_IMPLEMENTATION**.

MemoryCandidate and ExperienceCandidate: **KEEP** as candidate handoffs.

Admission, retrieval, learning, retention, consolidation, and semantic
compression: **DEFER**.
