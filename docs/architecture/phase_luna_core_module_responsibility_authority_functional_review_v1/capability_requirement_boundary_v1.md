# Capability Requirement Boundary v1

A owns the Cognitive Need and its semantic reason for information. The
Need→Capability Requirement bridge forms a minimized technical requirement
without selecting a model or Provider.

Task may express a functional execution requirement or dependency. It may
reference a required capability but must not create the cognitive purpose or
choose an implementation.

Capability Governance consumes the requirement and checks problem class,
operation, input contract, output contract, requirement type and required
authority. It must not create A Need, change Task purpose or upgrade a
functional requirement into a semantic judgment.

Requirement fields are candidates/refs until the relevant owner admits them.
The existing bridge explicitly guards against implementation, model, Provider
or scope selection by the upstream cognitive boundary.
