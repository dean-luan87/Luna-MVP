# Semantic Module Adjudication Summary

## Canonical decision

Semantic Module is retained as a narrowly bounded semantic working-environment builder. It constructs, expands, organizes, normalizes, and folds a versioned Semantic Working Outline from Brain-admitted source refs.

## Collision and comparison ownership

- Semantic Module: representation of conflicting information, comparison-ready structure, match/mismatch candidates, unresolved semantic slots.
- Experience/Short-Path Filter: future prior-match computation/candidate.
- A: final judgment of whether prior information resolves the Concern, whether evidence is sufficient, and what Need/next step follows.

## Failure behavior

Missing, stale, conflicting, unknown, or resource-limited inputs produce partial/degraded/ambiguous candidates with trace/provenance. Semantic Module must not invent truth or silently resolve the conflict.

## Repository conflicts

Historical semantic expansion descriptions and Dynamic Flow semantic computations may appear to imply reasoning authority. The verified target precedence is: Semantic Module transforms; A judges. Working Envelope is a source-ref container, not the Semantic Working Outline itself. Memory/Experience semantic compression remains deferred.

## Final disposition

`NARROW`.

Implementation timing: `CONTRACT_ONLY` now; `DEFER_RUNTIME` until Brain-admitted source/version and Experience/Filter boundaries are stable.
