# Outcome / Brain Assimilation Runtime Gap v1

## Evidence

Outcome Evaluation has a canonical registry, candidate types, controlled
engine, static ownership guard and explicit negative guards. Closure assets
contain candidate-only Closure, Loop Package and Brain Assimilation records;
they prohibit Memory/Experience mutation, Learning, Action execution and World
Truth declaration. Experience and Memory contracts likewise expose candidate
and later-admission boundaries.

## Gaps

- `CONTRACT_GAP`: unified OutcomeCandidate-to-Brain committed adjudication API.
- `ADAPTER_GAP`: explicit Outcome→Goal/Concern/Intent/Decision/Task handoffs.
- `RUNTIME_GAP`: no Brain runtime assimilation or Outcome runtime is implemented here.
- `OWNER_GAP`: no new owner required; source owners are known.
- `LEGACY_OVERLAP`: Dynamic Flow, A Route and closure helpers still expose mixed disposition/closure vocabulary.
- `TERMINOLOGY_GAP`: “cognitive outcome”, “closure decision”, “assimilation” and “final outcome” need one ledger interpretation.
