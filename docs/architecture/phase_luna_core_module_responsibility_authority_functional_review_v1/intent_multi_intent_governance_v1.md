# Multi-Intent Governance v1

The controlled assets already represent candidate interaction categories such
as `COEXISTENCE`, `COMPETITION`, `CONFLICT`, `SUPPRESSION`,
`TEMPORARY_DOMINANCE`, and `REACTIVATION`. The skeleton also carries
carryover and resource-constraint candidates. These are useful evidence for a
multi-Intent boundary, not authoritative transitions by themselves.

| Concern | Intent Governance | Brain | A |
|---|---|---|---|
| coexistence/interaction | owns Intent relation and lifecycle candidate | applies global constraints | consumes applicable refs |
| conflict/suppression | governs Intent-level relation | resolves global priority/resource impact | evaluates local cognitive impact |
| temporary dominance | governs bounded Intent dominance | may constrain global priority | receives selected refs |
| carryover/reactivation | validates provenance and prior version | governs cross-Concern impact | reassesses applicability |
| interruption/supersession | owns Intent transition | governs Goal/Concern consequences | stops using stale ref and reassesses |
| handoff | creates candidate/ref | admits Concern if needed | uses admitted ref |

Runtime admission, persistent active-set management and global priority
integration remain implementation gaps. No module may use a local interaction
candidate to bypass Brain or Intent Governance.
