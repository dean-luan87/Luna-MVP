# Luna Dynamic Cognitive Architecture Alignment Migration Strategy v1

## Position

This phase adds the missing governance layer between architecture realignment and
new module development. The operation is named **Architecture Alignment Migration**:
existing organs are aligned to the Luna Dynamic Cognitive System v2 candidate
without assuming that they must be rewritten, moved, or replaced.

The governed route is:

```text
P0 Dynamic Cognitive Architecture v2 Planning
  ↓
P1 Existing Asset Mapping
  ↓
P2 Controlled Architecture Alignment Migration
  ↓
P3 Migration Integrity Validation
  ↓
P4 Architecture Freeze Decision
  ↓
P5 Intent Processing / Evaluation Gate Planning
  ↓
P6 Personal Cognitive Network Skeleton
  ↓
P7 Causal Reasoning Skeleton
```

P3 is a mandatory gate. P4 cannot freeze the baseline and P5 cannot begin until
the migration inventory is complete, every migrated asset has a compatibility
result, the cognitive chain is closed, owner boundaries are preserved, and the
regression set passes under its future authorized execution mode.

## Alignment, not replacement

Migration types are restricted to:

- `keep`: preserve owner, path, interface, and behavior;
- `boundary_update`: update documented positioning or contracts;
- `adapter`: add a compatibility projection without replacing the mainline;
- `rename_candidate`: plan a compatibility-preserving name change for a later
  authorized migration;
- `move_candidate`: plan a physical move only after impact, alias, import, and
  rollback review.

`rename_candidate` and `move_candidate` do not authorize a rename or move. The
current phase produces planning contracts only.

## Owner-safe interpretation

Personal Cognitive Network owns typed links and activation projections. Memory
System remains the owner of persistence, consolidation, activation, and retrieval;
the network receives an admitted Experience Memory projection. Task Manager
remains task lifecycle and routing orchestration; Action Governance/Runtime retain
execution authority. Observation Manager remains evidence coordination, while
Cognitive Attention owns cognitive allocation. Model Manager remains in Capability
Governance.

These distinctions are integrity invariants, not optional migration preferences.

## Completion rule

A migration is not complete when files or documents have changed. It is complete
only when the migration record, owner mapping, compatibility evidence, chain
continuity, negative-boundary checks, regression results, traceability, rollback,
and architecture-freeze gate are all satisfied.
