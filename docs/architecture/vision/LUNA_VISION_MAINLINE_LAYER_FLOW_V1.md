# LUNA Vision：视角主链分层与流转设计（V1）

## 1. 目标

本文件的目标是：**先把视角主链逻辑打通**，再谈“补什么视觉模型/怎么调度”。

它要解决的问题不是“效果更好”，而是“系统不乱”：

- 视角信息**先进哪一层**
- 哪些信息先被“环境层”吸收
- 哪些信息触发 OCR / 局部细节识别
- 哪些信息进入风险链（安全优先）
- 哪些信息最终汇总给大脑（上层任务/语义/输出系统）
- 哪些情况下要**放弃次要流程**，优先做安全判断

## 2. 原则（写死）

- 本轮只做逻辑设计，不做模型接入
- 不新增视觉模型
- 不做单一大模型全包方案
- 不做复杂多模型调度器
- 先定义分层与流转，再决定后续模型补在哪一层

## 3. 视角主链四层结构（总览）

### 3.1 四层定义

1) **环境识别层（Environment Layer）**
- 问题：我在哪？环境属于哪类？我大概率在做什么？

2) **细节识别层（Detail Layer）**
- 问题：基于环境判断，是否需要触发 OCR / 局部细节识别 / 指引用户“放大拍照”？

3) **风险/行为判断层（Risk & Behavior Layer）**
- 问题：是否危险？是否存在动态障碍/碰撞风险？当前通行路线是否安全？

4) **汇总决策层（Summary & Decision Layer）**
- 问题：如何把环境/细节/风险/任务上下文统一汇总，决定下一步输出什么、优先处理什么？

### 3.2 三类链路（优先级）

- **快链（Low-latency fast path）**：必须优先低延迟（如环境粗判、是否需要 OCR 的 gating）
- **安全优先链（Safety-first path）**：必须优先安全（风险/行为判断），可牺牲其他链路的完备性
- **补充链（Supplementary path）**：用于补充证据（OCR、局部细节、放大拍照建议），可被安全链打断/降级

## 4. 各层职责（输入 / 输出 / 不做项 / 与下一层关系）

### 4.1 环境识别层

#### 输入
- **场景视觉**（视角帧/短视频片段的基础特征或描述）
- **GPS / 地理信息**（若存在）
- **记忆 / 历史路径**（若存在）
- **状态模块**（当前模式、速度、是否在车内/步行等若存在）
- （可选）**OCR 结果**：仅作为补证输入之一（见第 5 节）

#### 输出（最小集合）
- `environment_class`：环境类别（例如：室内/室外/道路/停车场/商场/小区等，最终枚举后定）
- `activity_hypothesis`：当前大概率在做什么（例如：步行通行/找车位/进出停车场/找入口等）
- `constraints`：环境限制变量（例如：低光/拥挤/车流/是否需要更谨慎的风险链）
- `confidence`：对上述判断的置信度（用于 gating，而非用于“强行确定事实”）

#### 这一层不负责什么（写死）
- 不做 OCR 的全局主导
- 不做细节字段的穷举（避免环境层膨胀）
- 不做最终行动决策（只输出环境限制变量与粗判断）

#### 与下一层关系
- **细节识别层**由环境层输出决定是否触发（gating）
- **风险/行为层**需要环境层提供限制变量（例如低光/道路/车流）作为安全判断的先验

### 4.2 细节识别层（OCR / 局部 / 放大拍照）

#### 输入
- 环境识别层输出（环境类别、限制变量、gating 信号）
- 场景视觉（可能需要更高分辨率/局部裁剪）
- 任务上下文（例如：是否在找入口、是否在识别路牌/店名等）

#### 输出（最小集合）
- `ocr_result`（可选）：文字识别结果 + 位置/置信度（若触发）
- `detail_findings`：与任务相关的局部发现（例如：门牌/路牌/指示牌/出入口标识等）
- `need_zoom_capture`：是否建议用户放大/重新拍（仅建议，不强制）

#### 这一层不负责什么（写死）
- 不做全局环境类别判定（应以环境层为主）
- 不做安全判断的最终裁决（风险层为主）
- 不把 OCR 结果当作“唯一真相”（只作为补证源）

#### 与下一层关系
- 风险/行为层可使用细节层的“障碍/路牌/警示文字”作为补证，但**不依赖其必然存在**
- 汇总层把细节层结果作为“可解释证据”向上呈现

### 4.3 风险/行为判断层（安全优先）

#### 输入
- 环境识别层的限制变量（道路/车流/低光/拥挤等）
- 场景视觉的风险相关信号（动态物体、距离变化、遮挡等）
- （可选）细节层的补证（警示牌、施工提示、红绿灯/斑马线文字等）

#### 输出（最小集合）
- `risk_level`：风险等级（例如：safe / caution / danger）
- `risk_reasons`：风险原因列表（可解释、可审计）
- `recommended_behavior`：建议行为（例如：停下/慢行/绕行/靠边等）
- `interrupt_supplementary_flows`：是否需要中断/降级补充链（如 OCR/放大拍照）

#### 为什么尽量独立于“全能大模型”（写死口径）
- 风险链属于**安全优先链**：必须可控、可审计、可回退
- 大模型全包容易把“补充链细节”与“安全判断”耦合，导致不可预期行为
- 风险层应优先保证：宁可保守提示，也不要因细节缺失而延迟安全判断

#### 与下一层关系
- 汇总层必须优先消费风险层输出；当 `risk_level` 高时，允许直接输出安全提示并**跳过/中断**次要流程

### 4.4 汇总决策层（交给大脑前的统一汇总）

#### 输入
- 环境识别层结果
- 细节识别层结果（如有）
- 风险/行为判断层结果
- 任务上下文（用户当前目标、历史对话、状态/记忆等）

#### 输出（最小集合）
- `summary_packet`：统一汇总包（结构化），包含：
  - 环境结论 + 关键限制变量
  - 细节证据（可选）
  - 风险结论（强优先级）+ 行为建议
  - 推荐的“下一步输出策略”（例如：先安全提示、再补细节；或先问澄清）

#### 这一层不负责什么（写死）
- 不替代上层“大脑/任务系统”的最终业务决策
- 不把所有信息强行融合成一个大模型 prompt（避免一锅端）

#### 交付给更高层系统的方式
- 以结构化 `summary_packet` 的形式交给上层任务/语义/输出系统
- 上层可选择：
  - 直接输出（安全提示优先）
  - 触发澄清
  - 请求补充输入（例如再拍一张更清晰的图）

## 5. OCR 的定位（写死）

- OCR 是**环境补证源**与**任务细节补证源**
- OCR 不是全局主导源，不应反向决定环境类别
- OCR 触发应被环境层 gating：只有在“环境类别 + 任务上下文”判定需要时才触发
- 当风险层要求中断补充链时，OCR/局部识别应被降级或直接跳过

## 6. 环境识别的定位（写死）

环境识别层应优先结合（若存在）：

- GPS / 地理信息
- 记忆 / 历史路径
- 场景视觉（粗粒度）
- OCR（仅补证）
- 状态模块（速度/模式/是否在车内等）

并为后续模块提供“环境限制变量”，例如：

- 低光 → 风险链更保守、细节链可能需要放大拍照提示
- 道路车流 → 风险链优先级最高，补充链可中断
- 室内拥挤 → 风险链关注动态障碍，细节链触发 OCR 的目标不同

## 7. 风险/行为判断层的定位（写死）

- 这是**安全优先链**，优先级高于细节补充链
- 在资源/延迟冲突时，应优先保证风险判断的实时性
- 风险判断输出必须可解释（risk_reasons），便于审计与回放

## 8. 汇总决策层（写死）

汇总层的优先级规则：

1. 若 `risk_level` 为 danger/caution 且需要立即动作：
   - **先输出安全提示/行为建议**
   - 可中断或延后细节链（OCR/局部/放大拍照）
2. 若风险低且任务需要细节：
   - 触发或等待细节链结果，再输出更具体的指引
3. 若环境/任务不确定：
   - 走澄清/请求补充输入（例如再拍一张更清晰的图）

## 9. 当前阶段不做项（明确写清）

- 先不接入新的视觉模型
- 先不决定多模型调度器
- 先不决定单大模型全包路线
- 后续只在本分层图确定后，再决定“模型补点”与“运行态开关/回退口径”

## 一句话收束

先把视角主链的层次、职责、流转关系写清楚，再决定后续视角模型补在哪一层。
