# Luna Emotion Governance Architecture Planning v1

## Phase boundary

This is a `PLANNING_ONLY` phase. It defines one narrow canonical semantic owner, candidate schemas, lifecycle and temporal contracts, typed cross-owner boundaries, trace/provenance, privacy, idempotency, gaps, deferred work, and a synthetic E01–E36 planning suite. It does not create an Emotion Engine, runtime, persistence, model integration, or semantic compression implementation.

## Audit result

No current `capabilities/midplatform/core/emotion_governance/` module exists. The current repository contains a verified Emotion Context placeholder and a historical/future Emotion Engine reference, but no converged active Emotion owner. `Emotion Governance` is therefore selected as the new canonical semantic owner for candidate-only emotional evidence, appraisal, state, lifecycle, temporal dynamics, conflict/mixed-state governance, privacy, revision, and trace.

Historical `Emotion Engine` assets are useful B-class references for multidimensional state, context binding, candidate interfaces, decay, revocability, and Brain/Attention/Drive boundaries. Their runtime and computation assumptions are not imported as current implementation authority. Existing `Emotion / Integration Governance` strings in core modules are C-class naming references and must not be promoted to an owner.

## Frozen conceptual distinctions

`Emotion Evidence != Emotion Appraisal != Emotion State != Mood != Personality Trait != Self != Memory != Intent != Action != External Reality`.

Emotion Evidence records source-bound observations or references. Emotion Appraisal is a candidate interpretation of those inputs. Emotion State Candidate is a multidimensional, context- and time-bound governed candidate. Mood is a broader or longer-lived contextual pattern candidate, not automatically an Emotion State truth. None of these objects owns Self, Personality, Memory, Intent, Action, or External Reality.

## Owner boundary

Emotion Governance owns candidate-only admission and lifecycle semantics for emotional evidence, appraisal, and state; accumulation, decay, refresh, recovery, conflict, mixed emotions, uncertainty, revision, supersession, revocation, expiration, privacy, and reverse trace. It emits typed influence/reference candidates to Self, Personality, Memory/Experience, Learning, Intent, Attention, Dynamic Regulation, PCN, and Cognitive Flow. Those interfaces do not grant mutation or semantic authority.

Emotion Governance does not own semantic compression, affective memory compression, emotion-memory summaries, personality-memory fusion, memory persistence, runtime expression, model inference, TTS, device action, or cross-user transfer.

## Deferred ownership decision

The four previously deferred capabilities are not assigned to Emotion Governance by convenience. They are planned as future cross-owner semantic synthesis concerns. Emotion Governance supplies emotional candidates; Cognitive Memory & Experience Governance remains the owner of memory-side meaning/admission/persistence contracts; Personality Governance remains frozen `FROZEN_V1`; and a separately authorized cross-owner synthesis layer must govern any fused semantic artifact. All four remain deferred in this phase.

## Planning readiness and stop

The planning package records A/B/C/D asset classification, the owner decision, all required boundary contracts, E01–E36 scenarios, negative guards, gap/deferred registries, and a static verifier. The agent performs editor/static diagnostics only and stops at `WAITING_FOR_USER_TERMINAL_VERIFICATION`.
