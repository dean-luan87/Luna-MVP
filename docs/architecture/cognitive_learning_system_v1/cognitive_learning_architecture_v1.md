# Cognitive Learning Architecture v1

## Position

The Learning System is Luna's governed life-experience adaptation layer. It
unifies Experience, Memory, Attention Adaptation, Strategy Exploration, Field Behavior, and Capability Feedback without training a model or taking cognitive
authority from Brain.

```text
Event → Observation → Outcome → Experience Record
      → Pattern Extraction Candidate
      → Strategy Candidate → Validation
      → Adaptive Update Candidate
```

Learning produces candidates. It does not modify Reality, Identity, Goal,
Decision, or model parameters. Current Reality has priority over historical
historical Experience remains subordinate, Unknown remains explicit, and an incorrect Experience or strategy
can be revoked.

## Learning domains

The first domain is Survival Learning: Field Pattern, Attention Pattern,
Navigation Pattern, Safety Pattern, and Interaction Pattern. Skill Learning is a
future placeholder only; no new skill or model is activated by this phase.

Learning distinguishes Memory from Learning:

- Memory records what happened;
- Learning extracts what may be useful in the future;
- Adaptation Candidate proposes a governed adjustment.

## Experience pipeline

Each learning record preserves Field, Role, Task, Self, Observation, Outcome,
Evidence, Provenance, Confidence, Unknown, and Conflict context. Cause Attribution
precedes Pattern Extraction Candidate. A pattern must be validated
against current Reality and cannot become a Rule merely because it repeats.

## Prediction Error as learning signal

Prediction Error here means an expectation-reality difference, not a Prediction Runtime. The signal is:

```text
Expectation → Reality → Difference → Learning Signal
```

It may create an Attention or Field observation candidate. It cannot directly
change a strategy, Goal, Decision, or Reality state.

## Interfaces

- Field Learning: extracts contextual Field Experience and preserves Field/Role/Task binding.
- Attention Learning: proposes Attention Pattern Candidate for evaluation.
- Memory Learning: reads stored experience and proposes Pattern Candidate; Learning does not rewrite Memory.
- Capability Learning: consumes Performance Evidence and proposes Capability Confidence Update Candidate.
- Strategy: stores Strategy Candidate with context, expected benefit, risk, resource cost, Unknown, and validation status.

## Learning Governance

Learning Governance requires provenance, evidence, confidence, context binding,
Reality precedence, Unknown preservation, validation before activation,
revocability, and human/Brain/Governance review where required. One anomalous episode
cannot permanently change future behavior. Automatic strategy switching, Online Learning Runtime,
model training, parameter modification, Emotion Runtime,
Runtime, B Route, and Action Runtime are outside this phase.

## Lifecycle

`Observed → Recorded → Evaluated → Pattern Candidate → Strategy Candidate →
Validated → Adaptation Candidate → Accepted / Rejected / Revoked → Archived`.

Accepted here means accepted as a governed candidate for a future subsystem;
it does not mean automatic activation.
