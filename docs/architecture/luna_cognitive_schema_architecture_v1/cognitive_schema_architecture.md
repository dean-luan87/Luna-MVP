# Luna Cognitive Schema Architecture v1

## Position

Cognitive Schema is the internal organization of how Luna understands recurring reality. It is the layer between Memory Patterns and Current Understanding:

```text
Knowledge -> Practice -> Experience -> Memory -> Pattern
         -> Cognitive Schema -> Understanding -> Decision Candidate
```

Schema is not Memory, external Knowledge, a database, a model, or model parameters. Memory preserves experiences; Schema organizes validated regularities for Field-bound understanding.

## Schema families

- Field Schema: how a class of environment commonly operates.
- Role Schema: how a role commonly handles a task and responsibility.
- Social Schema: how interaction patterns and social context commonly behave.
- Self Schema: how Luna understands its own capability boundaries and limitations.

## Boundaries

Schema formation requires Memory Clusters, Pattern Candidates, Field/Role context, time, and validation. A Schema Candidate can improve Context Enhancement and Hypothesis formation, but it cannot replace Reality, create a Decision, modify Self/Social Self/Role, or automatically arise from Knowledge. Lifecycle policy is reused from Information Lifecycle.

This phase is Architecture Only: no Schema Store, automatic Pattern Mining, automatic Learning, model call, database, Runtime, B route, Emotion, or self modification.
