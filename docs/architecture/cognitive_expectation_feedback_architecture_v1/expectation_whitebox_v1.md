# Expectation Whitebox v1

## Authority questions

1. Who creates an Expectation Candidate? An admitted Hypothesis, Belief,
   Field Rule, or Task source.
2. Who owns current Reality? Reality Workspace and its Reducer; Feedback is
   evidence about Reality and cannot write it directly.
3. Who compares expected and observed state? The governed Feedback contract.
4. Who owns the Hypothesis/Expectation boundary? Separate contracts with
   separate provenance and validation state.
5. Who allocates observation resources? Attention; Expectation only emits a
   Validation Requirement and Attention Request.
6. Who receives Feedback? Memory and Learning receive governed candidates;
   neither automatically changes Belief or Expectation.
7. Who evaluates material contradiction? Brain receives the Expectation
   Package and retains final judgment authority.
8. Who owns Task continuity? Existing Task/Goal contracts; Task-driven
   expectations are reference-only.

## Allowed flow

```text
Hypothesis / Belief / Field Rule / Task
                         ↓
              Expectation Candidate
                         ↓
          Validation Requirement + Context
                         ↓
                    Attention Request
                         ↓
                   Reality Observation
                         ↓
                Feedback / Difference
                         ↓
             Experience + Learning Candidate
                         ↓
                    Brain Context Package
```

## Negative paths

- Expectation → Prediction Runtime: forbidden.
- Expectation → World Model: forbidden.
- Expectation → Reality write: forbidden.
- Expectation → automatic Belief modification: forbidden.
- Expectation → automatic Decision: forbidden.
- Expectation → Action Runtime: forbidden.
- Attention → Expectation selection: forbidden; Attention allocates resources.
- Learning → automatic Expectation update: forbidden.
- Feedback → silent Unknown completion: forbidden.
- B Route Snapshot → live Expectation mutation: forbidden.

## Preserved fields

Every candidate preserves Expected State, Expected Evidence, Reality
Observation, Feedback Status, Difference, Confidence, Unknown, Risk, Field
Context, Situation, Time Context, Lifecycle State, and Provenance. Multiple
Expectation Candidates can coexist and remain separately auditable.

Contract keyword: Field Context.
