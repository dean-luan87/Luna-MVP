# Luna Capability Fitness Model v1

## Fitness Score Framework

Fitness is a multi-dimensional evidence framework, not a universal numeric score or automatic lifecycle decision.

| dimension | evidence question | boundary |
| --- | --- | --- |
| task success | has the Capability produced bounded, validated value for comparable declared tasks? | no outcome may become Fact by score alone |
| environmental suitability | is the Capability compatible with the current environment/context constraints? | does not authorize execution |
| reliability | are declared behavior and limitations stable and observable? | not a permission or activation signal |
| uncertainty | are coverage, conflict, and unknowns explicit? | uncertainty cannot be suppressed to improve fitness |
| resource efficiency | are cost, latency, dependencies, and consumption proportionate? | not a scheduler or automatic throttle |
| historical performance | what traceable success/failure patterns exist? | history is not Luna Memory or value judgment |
| user preference | is a bounded user preference relevant and permitted? | user preference cannot override governance |
| learning value | does use create reviewable evidence with provenance and uncertainty? | never direct Memory/Training admission |

## Fitness Outcome

A future assessment may emit evidence, comparison notes, warnings, or candidate recommendations such as `suitable_candidate`, `limited_candidate`, `fallback_candidate`, or `insufficient_evidence`. Fitness cannot automatically activate, deactivate, replace, retire, grant permission to, or select a Capability for execution.

## Competition Candidate Selection Framework

When multiple eligible Capabilities offer similar service, Governance may compare declared confidence, cost, latency, historical evidence, environmental suitability, uncertainty, and compatibility. The result is a ranked **selection candidate** with retained trace and alternatives; it is not an automatic replacement or execution order.
