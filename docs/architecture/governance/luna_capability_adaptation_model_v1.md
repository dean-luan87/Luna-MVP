# Luna Capability Adaptation Model v1

## Adaptation Mechanisms

| mechanism | permitted planning meaning | forbidden meaning |
| --- | --- | --- |
| context adaptation | propose bounded availability/configuration from governed Context references | Context mutation or hidden State read/write |
| parameter adjustment | propose a declared parameter variant within an approved future boundary | self-changing Contract, Permission, or authority |
| capability selection | emit a candidate comparison among compatible members | automatic activation or replacement |
| capability combination | propose a traceable composition of candidate contributions | peer-to-peer permission delegation |
| capability fallback | propose compatible alternative when evidence/risk/resource limits require it | bypassing Protocol, Permission, or denied operation |

## Mutation Governance

| mutation | examples | required governance |
| --- | --- | --- |
| low mutation | bounded parameter/configuration adjustment preserving Contract, trace, provider, and authority | recorded evidence and proportionate compatibility check |
| medium mutation | provider substitution with compatible Contract, new bounded dependency, selection/combination variant | Protocol/Permission/dependency assessment and rollback reference |
| high mutation | provider replacement changing semantics, model upgrade affecting boundary, architecture evolution, real external/Runtime impact | new governed proposal, compatibility/migration/rollback evidence, separate approved phase |

No Capability may modify Governance, Protocol, Permission scope, Registry lifecycle, or its own authority through adaptation or mutation.

## Recovery and Degradation

Degradation makes limitations explicit through candidate status, warning, and trace. Recovery is a governance-reviewed proposal based on evidence; Diagnostics may recommend it but cannot enact it.
