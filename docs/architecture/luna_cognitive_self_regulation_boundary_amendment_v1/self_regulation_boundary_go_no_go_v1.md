# Self Regulation Boundary Amendment Go / No-Go v1

## V0 readiness

Ready when failure-domain isolation, impact analysis, self-preservation priority, upgrade rejection, homeostasis v2, permission amendment, dependency mapping, and verifier contracts exist and parse.

## V2 decision contract

`LUNA_COGNITIVE_SELF_REGULATION_BOUNDARY_AMENDMENT_READY` means the boundary amendment is structurally ready. It does not activate Runtime, auto-upgrade, rollback, model switching, hardware control, learning execution, or Emotion integration.

Failure output must be `LUNA_COGNITIVE_SELF_REGULATION_BOUNDARY_AMENDMENT_REMEDIATION_REQUIRED` or the verifier's blocked contract.

## Required invariants

- A failure domain contains impact and preserves unaffected capabilities.
- Self Preservation priority is explicit and stable.
- Upgrade rejection is a candidate, not an automatic switch.
- Capability Governance retains admission authority.
- All changes remain reviewable, reversible, traceable, and candidate-only.
