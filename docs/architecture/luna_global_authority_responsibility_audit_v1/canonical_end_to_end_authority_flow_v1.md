# Canonical End-to-End Authority Flow v1

## Cognitive acquisition

`Brain Concern/Grant → Working Envelope binding → A Need/Requirement → Attention focus candidate → Capability Slot/Resolution → Runtime Admission → Observation Request → Provider Admission/Invocation → Provider Result → Evidence Mapping/Gateway Admission → Current World/Field Event candidates → Field/World/Cognitive Snapshot/Context refs → A reassessment.`

The arrows are contracts and refs, not permission for the consumer to mutate the producer. Need, relevance, Sufficiency, Reconsideration and Next-step remain A authority.

## Execution

`A local disposition → DecisionCandidate → Decision Governance → approved Decision → Task organization/readiness → ActionCandidate → Action Governance → Capability/Runtime/Provider → Action Result → Field/World/evidence admission where applicable → Task/A evaluation → Outcome Candidate → Brain adjudication/Assimilation → Goal/Concern/global consequence → Loop mechanical persistence.`

Simple bounded Decision→Action is allowed only when the existing narrow direct-action conditions are met; Action Governance remains mandatory.

## Constraint flow

`Safety/Permission/Resource policy and Brain Grant → versioned constraint refs → Envelope/Decision/Task/Attention → Runtime Admission → Provider/Observation/Action Admission → enforcement/result → A/Outcome/Brain.`

Policy owners define constraints; boundary owners enforce them. Diagnostics supplies facts and never substitutes for policy.

## Maintenance flow

`OS/device/runtime/model/provider/protocol/config facts → probe/passive observation → Diagnostic Evidence → System Diagnostics finding/health/drift/snapshot → Safety/Permission/Resource/Capability/Model/Protocol/Runtime/Provider/Action consumers → governed consequence.`

Diagnostics stops before admission, remediation and execution.

## Authority trace

| Question | Authority |
|---|---|
| What is needed? | A |
| What is globally permitted/protected? | Brain and domain constraint governance |
| What should be committed? | Decision Governance |
| How is it organized? | Task |
| May a side effect occur? | Action Governance under supplied constraints |
| Which runtime executes? | Provider Governance / runtime executor |
| What concrete result occurred? | Action/Provider/Observation boundaries |
| What does it mean locally? | A / Outcome Evaluation candidate |
| What is the global consequence? | Brain |
| What is persisted mechanically? | Loop |
