# Global Authority Audit Summary v1

## Overall adjudication

**AUTHORITY_MODEL_COHERENT_WITH_GAPS.** The module adjudications compose into a single owner model. The gaps are explicit at candidate adoption, shared mapping approval, cross-constraint binding, version propagation and runtime adapters. They are not evidence that Brain, Loop, Diagnostics, Provider or Protocol Governance should absorb other owners.

## Canonical owner count

32 registry records, including two conceptual future placeholders for Memory and Experience. The count groups Role/Identity/Relationship as one source-governance record and Observation Gateway/Evidence Admission as one boundary record.

## Main findings

- Brain is global governance and final assimilation, not the universal executor or local reasoner.
- A is the sole Concern-local semantic authority for Need, relevance, Sufficiency, Reconsideration and Next-step.
- Decision, Task, Action, Provider and Loop form distinct commitment, organization, side-effect, runtime and mechanical-persistence boundaries.
- Capability, Model, Provider and Protocol ownership are split by abstraction, declaration, runtime and representation respectively.
- Diagnostics is authoritative for diagnostic classification only; it neither admits execution nor repairs.
- Field is the operational state mutation boundary; Current World, Semantic Outline and Cognitive Snapshot remain derived/candidate products.
- Working Envelope binds admitted refs and constraints; it owns neither source payload nor semantic consequence.
- Memory/Experience remain candidate-only and deferred.

## Conflicts and vacuums

Recorded dual-owner appearances are resolved as valid splits except for legacy paths and the seven explicit authority vacuums listed in the conflict audit. No current dual mutation authority is accepted as canonical. The most consequential unresolved items are Current World/Snapshot/Outline adoption, shared Capability/Model/Provider mapping approval, cross-constraint precedence and Envelope refresh admission.

## Responsibility rule

Every named final authority has a corresponding failure responsibility in the reviewed adjudications. Where a candidate has no named final admission, the package records both `AUTHORITY_VACUUM` and `RESPONSIBILITY_GAP`; no implicit owner is invented.

## Recommended next phase

**A. Targeted authority conflict remediation**, limited to closing the P1 contract/vacuum items and resolving legacy direct-bypass declarations. After that, perform canonical contract consolidation. Do not jump directly to implementation restructuring or declare runtime readiness.

## Online-doc-ready sections

### 03.8.1 | Luna Canonical Authority Model

Luna uses one final authority per authoritative state. Brain governs global cognitive work and assimilation; A governs local semantics; source boundaries own source state; admission boundaries admit candidates; execution boundaries execute; Diagnostics classifies; Loop persists. Shared contracts do not create shared final mutation authority.

### 03.8.2 | State Ownership Ledger

The ledger separates AUTHORITATIVE source state, CANDIDATE products, REFERENCE_ONLY bindings, EXTERNAL facts and LOCAL_DERIVED views. The principal rule is that Perspective, Context, Working Envelope, Semantic Outline, Cognitive Snapshot, Gateway and Loop must not become mutable duplicates of Field, Current World, Intent, Task, Outcome or other source state.

### 03.8.3 | Mutation & Admission Authority

Mutation belongs to Brain, Intent, Field, Context, Decision, Task, Action, Model, Protocol and Loop only within their stated domains. Admission is separately named for Concern/Grant, Envelope, Capability, Runtime, Provider, Observation, Evidence, Decision, Task, Action, Permission, Resource, Model and Protocol. Candidate producers cannot bypass admission.

### 03.8.4 | Policy vs Enforcement

Brain and the Safety/Permission/Resource sub-boundaries supply versioned global constraints. Diagnostics supplies facts. Envelope, Decision, Task, Runtime, Provider, Observation and Action enforce supplied refs at their boundaries. Repeated enforcement is not duplicated policy authority.

### 03.8.5 | Candidate → Authority

Candidates are proposals with source/version/provenance. Decision, Action, Evidence, Executable Capability, Outcome, Envelope and future Memory/Experience candidates require the named admission owner. Current World, Snapshot, Outline, mapping approval and Envelope refresh remain explicit vacuums for the next phase.

### 03.8.6 | Cross-Module Conflict / Vacuum

Most apparent conflicts are split-authority-valid: Protocol/source, Capability/Model, Model/Provider, Brain/constraints, Observation/FPO/Gateway, Decision/Task/Action and Outcome/Brain. Seven candidate-adoption or shared-contract vacuums remain; no new Manager is authorized by this audit.

### 03.8.7 | Version & Invalidation

Each domain owns its version. Changes propagate through refs, invalidation and supersession; consumers re-admit or mark bindings stale. No global version and no direct cross-owner mutation are permitted.

### 03.8.8 | Canonical End-to-End Flow

Concern/Grant → Envelope → A → Attention → Capability → Runtime → Observation/Provider → Evidence/Gateway → World/Field candidates → Cognitive products → A; and A → Decision → Task → Action → Provider → Result → Outcome → Brain. Constraint and maintenance flows join through versioned refs.

### 03.8.9 | Legacy Conflict Register

Legacy resource policy, direct routing, closure inference, model/provider embedding, Workspace/Envelope and protocol helper surfaces remain compatibility evidence or migration debt. They do not override the canonical owner registry.

### 03.8.10 | Global Gap / Next Phase Decision

The architecture is coherent with P1 contract and adapter gaps. Next phase: targeted authority conflict remediation, then canonical contract consolidation. Runtime remains unverified and unready for a GO declaration.
