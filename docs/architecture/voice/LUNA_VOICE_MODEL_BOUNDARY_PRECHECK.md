# Luna Voice：外部大模型接入前置边界 Precheck（正式约束）

> 本文档用于后续模型选型与接入评审。Stage-1 不接任何模型；只定义接入前置边界。

## 1) 模型在 Luna 中的角色（允许的角色集合）

外部模型只能以能力提供方身份出现，角色限定为：
- **ASR provider**：音频 → 文本/事件候选
- **TTS provider**：文本 → 音频/播放候选（或播放能力）
- **语义辅助 provider**：轻意图/槽位/归一化候选（不得裁决）
- **表达润色 provider**：对已批准的内容做表达润色（不得改语义边界）

## 2) 模型不能触碰的内容（禁止输入给模型）

禁止把以下内容直接提供给外部模型：
- Core 状态机与主链内部细节
- TaskChain 内部细节（含未脱敏的阶段、策略、阈值）
- Whitebox 链路细节、结构树、时间轴细节（除非专门的白盒模型且严格隔离）
- 规则阈值、治理策略、门控参数（gate/rhythm/quota/cooldown 细节）
- 内部系统信息（路径、密钥、环境变量、调试口令、内部日志原文）
- 记忆核心结构与原始记忆条目（除非脱敏与最小化）
- 后端治理细节与错误码策略细节

## 3) 模型可读取上下文的“最小集合”原则

允许提供的上下文必须同时满足：
- **脱敏**：去除身份/隐私/内部系统细节
- **裁剪**：仅最小必要窗口
- **结构化**：以标准 schema 提供，而非原始对象堆砌
- **最小必要**：为完成角色任务所需的最少字段集

## 4) 模型输出的处理方式（永远是候选）

外部模型输出永远只能作为候选进入系统：
- 模型输出 ≠ 系统最终输出
- 模型输出必须进入治理链路（规则层 + Output Plane）
- 允许的处理结果：accept / reject / rewrite（由系统侧执行）

## 5) 模型内容进入白盒的要求（可追溯）

必须能在白盒/留痕中记录：
- Luna 原始内容（输入/上下文/约束）
- 模型候选内容（raw candidate）
- 最终输出内容（approved final）
- accept / reject / rewrite 的原因（规则命中/权限判断/冲突确认）

## 6) 最低合规检查（接入前必须通过）

接入任一外部模型前，必须明确并通过：
- 输入字段白名单（什么可以给模型）
- 禁止字段清单（什么不能给模型）
- 候选输出治理路径（模型能做什么/不能做什么）
- 白盒留痕 schema（如何记录与归因）
- 故障降级策略（模型不可用时系统仍可运行）
