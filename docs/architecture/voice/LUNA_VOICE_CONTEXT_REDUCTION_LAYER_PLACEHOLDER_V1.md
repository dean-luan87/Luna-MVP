# LUNA Voice：语义吸收层 / 上下文压缩层（占位说明 V1）

## 目标（当前仅占位）

本文件用于在 Voice 主线中**正式预留**一层未来模块，用于在进入模型链路之前，先从高确定性来源中“吸收/固定”信息，只把真正未决的增量问题交给模型推理。

**重要边界（写死）**：

- 当前仅占位：**不实现任何代码逻辑**
- 当前不接入运行时：**不进入当前主链**
- 当前不新增开关
- 当前不改：prefilter / prompt / schema / validator / builder / fallback

## 工程候选命名（当前仅占位）

本层在工程文档中暂给出两个候选名（后续再定最终命名）：

- `context_reduction_layer`
- `semantic_absorption_layer`

说明：

- 本轮只统一“候选名与概念边界”，**不建立空 Python 模块**，避免制造“假实现”。

## 为什么要有这层（它解决什么问题）

该层的目标不是“压缩文本长度”本身，而是：

- **吸收高确定性信息**：来自记忆/状态/任务上下文的稳定事实（例如已知偏好、已确认目的地、已选择路线偏好、已完成的步骤等）
- **固定方向**：把“已确定的约束与上下文”显式注入到下游，使模型把算力用于未决增量
- **减少重复解释成本**：降低模型每次都要从原文里重新推断的负担

与“单纯 prompt 精简”的区别：

- prompt 精简主要在**提示词工程**层面减少冗余、规训格式；
- 本层关注的是**结构化上下文治理**：把“系统已知且可靠的信息”以可控方式并入下游（同时保留原文入口与冲突保护），从而降低推理不确定性与漂移。

## 未来位置（明确写清）

未来预期位置（原则口径）：

- 位于 **prefilter 之后**
- 位于 **模型之前**

并与以下模块存在并联/串联关系（后续实现阶段再定具体拓扑）：

- 记忆模块（Memory）
- 状态模块（State）
- 任务上下文（Task Context / 任务链）

推荐的抽象关系（仅原则，不写实现）：

- 输入：`cleaned_text`（prefilter 产物）+ 记忆/状态/任务上下文
- 输出：保留原文入口 + 增量问题的“缩减后上下文”（供模型链消费）

## 未来职责（只写原则，不写实现）

该层未来应遵循以下职责原则：

- **只吸收高确定性信息**（可被系统证明/已确认/强一致来源）
- **只保留未决增量给模型**（把“已决部分”从推理空间中剥离出来）
- **不吞掉冲突与新意图**：遇到冲突/歧义/新目标，必须显式保留并交由下游处理
- **不替代模型推理**：该层不是“另一个模型”，不做开放式推理与创造性补全

## 明确不做项（当前与未来的底线）

### 当前不做（本轮写死）

- 不实现任何逻辑
- 不接入主链运行时
- 不新增开关
- 不改 prefilter / prompt / schema / validator / builder / fallback
- 不建立空模块/空类（避免误导为“已实现”）

### 未来也不应做（底线约束）

- 不压缩掉“原文入口”（必须可回溯原始输入）
- 不把错误记忆/错误状态当作事实强行注入并放大
- 不在该层“提前吃掉”冲突、歧义、新目标（否则会把风险前移且不可观测）

## 接入原则（未来实现必须遵守）

未来若接入该层，必须满足：

- **只吸收高确定性信息**
- **必须保留原文入口**（可审计、可回放、可对照）
- **不提前吃掉冲突、歧义、新目标**
- **错误记忆不能被直接放大**：若记忆/状态可信度不足，必须以“候选/低置信”形式呈现，并允许下游覆盖
- **可观测**：必须能在 metadata/调试信息里看出“吸收了什么/保留了什么/哪些未决被下放”（但本轮不实现）

## 与后续模块关系（只定义边界）

该层未来与以下模块的关系：

- **记忆模块**：作为高确定性信息来源之一，但不能无条件信任；需有可信度/确认机制（后续实现阶段定义）
- **状态模块**：作为当前会话状态与已决约束来源；同样需可验证与可覆盖
- **任务链**：可接收任务链的已执行/已确认信息，减少重复规划；但不得吞掉新意图与冲突
- **模型评测与准入中心**：该层一旦接入，将成为“运行态能力”的一部分，需要纳入接入 SOP 的契约/回归/灰度闸门与回退模板（后续实现阶段纳入）

## 一句话收束

本轮只完成“语义吸收层 / 上下文压缩层”的架构占位与边界定义：**不实现、不接主链、不新增开关**，作为后续 Voice 主线优化的正式预留项。
