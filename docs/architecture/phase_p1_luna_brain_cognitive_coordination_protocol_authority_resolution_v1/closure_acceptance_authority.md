# Closure Acceptance Authority

| Stage | Producer/consumer | Semantic owner | Mechanical owner | Candidate-only | Decision |
|---|---|---|---|---|---|
| Sufficiency | Cognitive State Formation Governance | Cognitive State Formation Governance | same owner | yes | resolved |
| Stop | Cognitive State Formation Governance | Cognitive State Formation Governance | same owner | yes | resolved |
| Closure eligibility | canonical Stop/Sufficiency consumer | `OWNER_UNRESOLVED` | none established | yes | `OWNER_UNRESOLVED` |
| Closure Candidate / Assessment | controlled Loop/Cognitive Outcome boundary | source cognition + candidate Flow boundary | Cognitive Flow candidate mechanics | yes | resolved as candidate surface only |
| Closure Acceptance | authorized higher-level consumer | `OWNER_UNRESOLVED` | `OWNER_UNRESOLVED` | yes in current skeleton | `OWNER_UNRESOLVED` |
| Lifecycle closure transition | accepted closure ref | no authority to override Sufficiency | Cognitive Flow Governance | yes | `RESOLVED_TO_EXISTING_OWNER` for mechanics |

The lifecycle closure types explicitly separate assessment, decision,
lifecycle closure, and Brain Assimilation Candidate. The closure adapter
identifies `Cognitive Flow Governance` as its canonical adapter owner, while
the existing architecture states that Brain final adjudication is a
responsibility concept rather than an implemented Brain runtime owner.

Therefore Cognitive Flow Governance may persist or materialize a mechanical
lifecycle transition only after an authorized acceptance reference exists. It
may not invent semantic acceptance or override the canonical Sufficiency or
Stop result. The current controlled Brain integration must retain
`governing_owner_ref=OWNER_UNRESOLVED` for semantic Closure Acceptance.
