# Selected route

Selected: **Route B — Brain as a protocol/orchestration domain**.

Reasons:

1. No concrete canonical Brain runtime owner or API was found.
2. Existing Governance modules already own the relevant semantic and mutation
   boundaries.
3. The verified controlled integration already demonstrates a safe candidate
   boundary with `BRAIN / OWNER_UNRESOLVED`.
4. Route B avoids duplicating source-of-truth state and avoids creating a
   parallel cognition runtime.
5. Closure acceptance and assimilation authority can remain explicitly
   unresolved rather than being invented.

Migration impact is limited to documenting and eventually standardizing
reference envelopes. A future change to Route A or C requires an explicit
owner decision, API contract, compatibility plan, owner registry update, and
negative-boundary verification.
