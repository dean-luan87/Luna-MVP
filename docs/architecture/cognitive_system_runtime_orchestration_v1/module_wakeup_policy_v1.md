# Module Wake-up Policy v1

## Wake-up candidates

| Module | Wake-up policy candidate |
|---|---|
| Reality Workspace | resident / state-change driven |
| Attention | continuous governance / request driven |
| Brain | event-driven escalation |
| Experience | background / maintenance tick |
| Capability | on-demand from an admitted Observation Requirement |
| Neural | fast stimulus and health events |
| Field | reality, goal, or context change candidate |

Wake-up condition produces an Execution Candidate, not an execution. The
policy records trigger, priority, resource cost, frequency class, and expiry.

## Boundary

Wake-up Policy is not a Scheduler and does not implement a Scheduler. It does
not call models, control Hardware, execute Action, create a Decision, or modify
Reality. Multi-frequency operation is a contract; runtime timing remains out
of scope. Wake-up Policy does not call models, does not control Hardware, and does not execute Action.
