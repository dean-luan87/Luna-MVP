# Progressive Exploration Methodology

## Frozen progression

`simple task`
→ `single model`
→ `single data condition`
→ `complete cognitive-chain observation`
→ `P0 gap repair`
→ `higher task complexity`
→ `higher data complexity`
→ `model comparison`
→ `version comparison`
→ `interference conditions`
→ `cross-modal`
→ `resource constraints`.

## Operating rule

Start with a small, high-explanation suite. The first question is whether the
chain is observable and governed, not whether a large benchmark produces a
ranking. Scale the dataset only after case identity, provenance, annotation,
trace, and cognitive transitions are stable.

## Gates

- **P0 gate**: no unresolved boundary, provenance, stale-data, or required
  trace gap for the selected suite.
- **P1 gate**: task/condition-scoped fit profile can be reproduced.
- **P2 gate**: fixed-suite comparison preserves old model/version records and
  reports deltas with uncertainty and failure-mode changes.

No gate changes runtime binding or silently selects a provider.
