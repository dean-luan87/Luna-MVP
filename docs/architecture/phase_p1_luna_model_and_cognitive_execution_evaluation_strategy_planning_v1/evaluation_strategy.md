# Luna Model and Cognitive Execution Evaluation Strategy

> Alignment note (Phase-P1-Luna-Field-Cognition-Evaluation-Dual-Test-Plane-Alignment-And-Dataset-Ingress-v1-001): this historical planning document is preserved. Its model/evaluation emphasis is superseded for primary ordering by the dual-plane architecture: Plane A evaluates Luna A-Route cognition; external capability/model/provider fitness is supporting Plane B evidence.

## Status

Planning only. No dataset is registered, no model/provider is executed, and
no runtime contract is changed.

## Priority order

1. **P0 — gap discovery**: expose missing inputs, broken handoffs, weak
   provenance, stale data, annotation defects, boundary violations, and
   cognitive-loop omissions.
2. **P1 — model fit discovery**: understand which model/version/provider is
   useful under a task and condition, including its downstream cognitive cost.
3. **P2 — model/version comparison**: compare fixed suites longitudinally and
   horizontally without replacing historical records.

Traditional benchmark ranking is a supporting metric, not the primary Luna
evaluation objective.

## Evaluation flow

`Task Condition + Dataset/Sample + Resource Constraint`
→ `Capability Requirement`
→ governed Model/Provider resolution
→ Observation cycles
→ Evidence candidates
→ Current World candidate
→ Hypothesis candidate
→ Sufficiency transition
→ Information Gap / Next Observation or Decision Governance handoff
→ evaluation result and protected TestBoard evidence.

The evaluation subsystem observes this flow. It does not own runtime
admission, model selection, Decision, Task, Action, World Truth, or Field
mutation.

## Evaluation knowledge

The primary output is an evaluation knowledge candidate: a traceable statement
of fit, weaknesses, burden, and conditions. It may inform human review or a
future governance review, but cannot mutate Model Manager bindings or runtime
policy automatically.
