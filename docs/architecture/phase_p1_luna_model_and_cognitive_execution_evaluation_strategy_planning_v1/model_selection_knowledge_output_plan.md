# Model Selection Knowledge Output Plan

## Intended knowledge path

`Task Condition + Environment + Resource Constraint + Capability Requirement`
→ repeated fixed-suite evaluations
→ task/condition-scoped Model Fit Profiles
→ comparison and regression evidence
→ human/governance review
→ evaluation knowledge candidate: preferred/avoid conditions.

## Current boundary

The output may say, for example, that a model/version is a candidate fit for
a task under a declared lighting and latency condition. It may not:

- mutate Model Manager bindings;
- switch a runtime model/provider;
- issue Runtime Admission;
- become a scheduler, planner, or selector;
- treat benchmark rank as semantic correctness or World Truth.

## Required evidence

Every knowledge candidate must link to dataset/sample/annotation versions,
model/provider versions, task/condition, metrics, failure modes, cognitive
burden, trace, provenance, and review status. Unavailable data must remain
explicitly unavailable.
