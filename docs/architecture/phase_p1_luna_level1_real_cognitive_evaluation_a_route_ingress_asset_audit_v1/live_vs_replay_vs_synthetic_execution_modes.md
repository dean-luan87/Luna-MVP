# Live vs Replay vs Synthetic Execution Modes

| Mode | Definition | Repository support | Audit verdict |
|---|---|---|---|
| MODE A — LIVE REAL | Real sensor/model/provider → Luna cognition | Narrow raw-frame and RF-DETR provider precedents; no general registered-case A-Route ingress | `PARTIAL` |
| MODE B — RECORDED/REPLAY | Previously captured real evidence → Luna cognition | Replay key/ref builders and real smoke artifacts exist; replay-to-A consumer is not connected | `PARTIAL`, safest next bridge candidate |
| MODE C — SYNTHETIC | Fixture evidence → Luna cognition candidates | FPO, A-Route, Cognitive State Formation, and White-box fixtures | `SUPPORTED_FOR_CONTROLLED_TEST_ONLY` |

## Recommended order

Use MODE B first for one Level-1 bridge if a governed recorded evidence artifact is available. It offers deterministic input, avoids a second provider variable, and keeps failures attributable. It must still enter through Observation/Evidence ownership and must not be treated as World Truth. MODE A remains a later real execution path; MODE C cannot establish real cognition.
