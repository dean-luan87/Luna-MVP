# Official Capability Module Admission Manual

Admission is staged and evidence-backed. The stages are not interchangeable:

1. **Capability Module Definition Admission** — identity, purpose, problem
   classes, origin, requirement class, contracts, and owner are valid.
2. **Capability Implementation Admission** — implementation contract,
   integrity, provenance, dependency, resource, and lifecycle support are
   valid.
3. **Model / Provider Admission** — Model Manager and Provider Governance
   qualify the implementation resources and compatibility.
4. **Slot Compatibility Assessment** — the Module can safely bind to the
   selected generic Slot.
5. **Module-to-Slot Binding** — governed binding candidate is accepted and
   historical references are recorded.
6. **Installation** — implementation assets become locally available through
   an explicitly authorized operation.
7. **Activation** — the admitted, installed, compatible Module is made
   available for controlled use.

Required evidence includes provenance, integrity/signature, compatibility,
resource, permission, dependency, safety classification, rollback/recovery,
and trace references. Official availability alone never activates a Module.

Mandatory Safety Modules additionally require Survival/Safety Constitution
checks. Brain and user requests are candidates only; Capability Governance
retains lifecycle authority.
