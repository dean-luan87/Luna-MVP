# Task and Experience Position Contract

## Task

Task enters CognitiveWorkingEnvelope as refs and constraints:

- target;
- behavior constraints;
- completion conditions;
- resource and permission refs;
- observation dependencies.

Task cannot:

- issue Loop commands;
- choose B;
- change Concern identity;
- own sufficiency;
- own reasoning;
- directly control Loop cognition.

Decision to Task execution organization remains separate from A/B reasoning.
Task Manager remains Task lifecycle owner.

## Experience

Experience may appear:

- before A as Filter/reference input;
- during A/B as read-only cognitive prior;
- after closure as ExperienceCandidate input.

Experience cannot:

- directly mutate reasoning state;
- directly drive Loop;
- override Current Reality;
- become World Truth;
- create a Decision, Action, Task or Concern;
- mutate Memory or Experience in this phase.

## Short-path relationship

An Experience hit may allow Brain direct resolution without Loop
materialization. A bounded Capability path may still expose an unresolved gap;
that gap enters A through the Working Envelope.

## Existing owner reuse

Task Manager, Intent Governance, Role, Field, Current World, Attention,
Capability Governance and Cognitive Memory & Experience remain canonical
owners. This contract adds no owner.
