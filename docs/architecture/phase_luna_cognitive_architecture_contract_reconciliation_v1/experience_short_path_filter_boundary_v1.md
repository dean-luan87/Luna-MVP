# Experience / Short-Path Filter Boundary

## Status

This is a contract boundary only. No filter runtime, retrieval, mutation or
semantic compression is implemented in this phase.

## Target boundary

Semantic Working Outline
→ Experience collision / retrieval
→ information match, confidence and validity evaluation
→ DIRECT_RESOLUTION
  or SHORT_CAPABILITY_RESOLUTION
  or A_REASONING_REQUIRED

## Reuse candidates

Existing composable assets include:

- ExperienceCandidateV1;
- MemoryCandidateV1;
- Cognitive Memory & Experience Governance;
- Attention relevance and uncertainty candidates;
- Current World and evidence refs;
- Capability Requirement, Scope, Resolution and Invocation candidates;
- Observation Gateway admission boundaries.

No new Filter owner should be introduced if existing governance owners can
compose this function.

## Authority rules

- Experience result is not automatically truth.
- Historical Experience cannot override Current Reality.
- A short Capability result may expose a remaining cognitive gap and enter A.
- The filter does not decide general cognitive sufficiency.
- The filter does not choose Provider identity outside Capability Governance.
- The filter does not control Loop lifecycle.
- The filter does not mutate Memory or Experience.
- The filter is not another Brain or reasoning owner.

## Resolution outcomes

DIRECT_RESOLUTION returns a bounded candidate to Brain without Loop
materialization. SHORT_CAPABILITY_RESOLUTION forms only a bounded Requirement
through existing Capability Governance. A_REASONING_REQUIRED transfers the
remaining concern to A, optionally with a Loop materialization request.
