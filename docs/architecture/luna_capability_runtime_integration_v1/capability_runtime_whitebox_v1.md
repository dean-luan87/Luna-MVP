# Capability Runtime Integration Whitebox v1

## Audit questions

1. Was the incoming request admitted before execution context creation?
2. Does the context carry timeout, priority, budget, constraint, caller, and
   trace fields?
3. Is Provider identity isolated behind an Adapter?
4. Does the lifecycle distinguish Requested, Validated, Queued, Executing,
   Collected, Validated, Completed, Failed, Degraded, and Recovered?
5. Does every result pass Result Collector and Evidence Gateway?
6. Are cache classes and sensitive evidence boundaries explicit?
7. Do failure paths preserve Unknown and produce alternatives?
8. Does Capability Runtime remain outside Goal, Decision, Reality,
   Constitution, and Action authority?

## Explicit non-authority

Capability Runtime is not Brain, Goal System, Decision Commitment, Reality
Reducer, Constitution, L1 Governance owner, Model Provider, Hardware Driver,
or Action Runtime.
