## Objective and position

Unify distributed Attention Candidates into a bounded Active Cognitive Allocation Candidate for Workspace formation and future route admission.

```text
Context + Goal + Risk + Resource + Experience + Unknown + Sufficiency
  -> Attention Candidate Pool
  -> Cognitive Attention Controller
  -> Active Cognitive Allocation Candidate
  -> Workspace Formation Candidate
  -> A / B Route Admission Candidate
```

The controller governs cognitive resource allocation: target, budget, depth, duration, direction, and stop/continue candidate. It is not a Decision, Action, Permission, Runtime Scheduler, or Resource Executor.

## Attention architecture extension alignment

The Controller is the Cognitive Attention branch of the later three-direction Attention System. Input Attention governs which external Evidence Candidates are admitted/activated; Active/Output Attention may emit bounded Perception Request Candidates. Neither bypasses the Controller or turns a sensor request into an action.

## Scope

Define candidate aggregation, budget, depth, direction, conflict resolution, consistency constraints, A/B admission, Sufficiency integration, and future Emotion attention interface.

## Out of scope

No attention runtime/scheduler, compute allocation, route execution, B Route runtime, Decision, Action, Permission, Emotion Engine, Memory/Learning/Evolution, or State mutation.
