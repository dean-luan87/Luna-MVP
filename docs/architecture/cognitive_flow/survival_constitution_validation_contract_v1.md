# Survival Constitution Validation Contract v1

## Constitutional-position checks

The validated foundation must remain an L0-oriented architectural constraint only. It must not become a Capability, Field Kernel extension, Reducer extension, Decision Engine, Action Controller, Permission System, or Safety Rule Database.

## Candidate and authority checks

- Survival Constraint Candidate is not a Decision, Action Permission, Action Command, Fact, or State mutation.
- Risk Candidate is not Fact.
- Confidence describes uncertainty and cannot grant authority.
- Unknown remains a valid condition and cannot force automatic completion or universal inactivity.
- Experience can inform future adaptation candidates; it cannot mutate Survival Constitution or Memory.
- Hive cannot modify the Constitution.
- Capability cannot override the Constitution or grant itself an exception.

## Provenance closure

Every future survival-boundary candidate must preserve:

`Survival Principle -> Constraint Reference -> Cognitive Flow Boundary -> Candidate Trace`

The trace must identify the constraint source and applicable Cognitive Flow boundary without promoting either to Fact.

## Deterministic criterion

For a future authorized fixture-only implementation, identical declared inputs must yield byte-equal canonical JSON for run1 and run2. This is a required future evidence criterion, not a Runtime authorization.
