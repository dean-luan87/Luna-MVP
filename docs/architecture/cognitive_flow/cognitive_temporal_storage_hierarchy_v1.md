# Temporal Storage Hierarchy v1

## Three levels

```text
Temporal Storage Boundary
├── Level 0: Transient Temporal State
├── Level 1: Working Temporal Context
└── Level 2: Temporal Pattern Candidate
```

| Level | Lifecycle | Purpose | Example | Boundary |
|---|---|---|---|---|
| Level 0: Transient Temporal State | seconds | immediate dynamic understanding | a vehicle suddenly approaches | not long-term storage |
| Level 1: Working Temporal Context | minutes to hours | current task continuity | recently observed road condition | expires with context; not Memory adoption |
| Level 2: Temporal Pattern Candidate | candidate retained for governed experience review | possible recurring structure | daily rush-hour congestion candidate | not knowledge, Memory, or automatic rule |

## Retention boundary

Only a material, relevant, and traceable change may be considered for promotion
from a transient state to Working Temporal Context, or from working context to a
Temporal Pattern Candidate. Promotion is candidate formation, not state mutation or Memory write.

Level 2 requires Experience validation and Adoption before any future Memory or
Knowledge subsystem may rely on it. This phase neither implements nor authorizes
such adoption.
