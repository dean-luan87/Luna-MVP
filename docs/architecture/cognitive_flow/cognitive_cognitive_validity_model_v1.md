# Cognitive Validity Model v1

## Validity Candidate

Every Retained Cognitive Object Candidate must carry, where applicable:

- Context Condition
- Field Condition
- Time Condition
- Goal Condition
- Risk Condition
- Confidence Candidate
- Invalidation Trigger Candidate

## Rule

Validity is condition-based. TTL may be a supporting signal but must never be the only invalidation rule. A Field Event, risk change, task change, new evidence, or context mismatch can request refresh, decay, dormancy, or retirement candidates.

## Boundary

Validity != Truth, Fact confirmation, Permission, Decision, Action, State mutation, or automatic replacement of current Field evidence.
