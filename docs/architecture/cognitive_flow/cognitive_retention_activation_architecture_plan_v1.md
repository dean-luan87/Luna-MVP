## Position

`Current Cognitive Runtime -> Cognitive Retention and Activation Candidate -> Experience / Representation / Knowledge / Evolution Candidate`.

Retention manages cognitive continuity: what current task/field cognition is worth retaining, whether it remains valid, when it decays, and when a context-bound representation may be reactivated. It is not Memory storage, Experience storage, a State Machine, Decision, Action, Knowledge Base, or State authority.

## Principles

- Task Driven Retention: task requirements determine the relevant cognitive set and release conditions; task requirement != permanent retention.
- Field Driven Activation: Field context may form activation candidates without a user request; activation != authority.
- Minimum Sufficient Retention: preserve only cognition needed for current task and environment; more retention != better cognition.
- Validity Based Retention: context, field, time, goal, and risk conditions determine current applicability; TTL alone is insufficient.

## Scope

Planning only. No retention Runtime, Memory storage, retrieval engine, State Machine, Decision, Action, Experience mutation, Learning/Evolution runtime, Hive, or Reducer modification is authorized.
