# Cognitive Kernel Constraint Model v1

## Constraint Candidate

A Kernel Constraint Candidate records a cross-cutting boundary that proposed cognitive activity must respect.

## Inputs

- Constitution / Survival Candidates;
- Evidence, Context, Goal, Risk, Unknown, and Self State Candidates;
- Attention Allocation, Capability Bundle, Resource Budget, and Process Candidates.

## Candidate fields

- `constraint_id` and provenance;
- affected candidates and scope;
- constraint category: reality, safety, resource, context, or candidate-authority;
- rationale and supporting evidence references;
- conflict, uncertainty, and expiry references;
- suggested adjustment or deferral candidate.

## Constraint examples

- an experience-guided bundle cannot override contradictory current evidence;
- a capability bundle cannot exceed a resource-budget candidate;
- a low-risk exploration candidate cannot displace a survival-relevant interrupt without arbitration.

## Boundary

A Constraint Candidate constrains later evaluation and admission. It does not mutate candidates, decide their final outcome, control a device, grant permission, or change State.
