# Cognitive Conflict Orchestration Model v1

## Purpose

Orchestration detects and exposes incompatible candidate claims, resource requests, priorities, or lifecycle requests so that Evaluation, Sufficiency, Routing, or local re-understanding may respond.

## Candidate responses

- Preserve Conflict Candidate;
- request additional observation or validity check;
- request alternative module contribution;
- defer low-value conflict;
- escalate high-risk unresolved conflict to a higher-priority cognitive path candidate.

Conflict != Error, Failure, Decision, Action, or automatic resolution. This coordination model does not replace the separate Cognitive Conflict Resolution candidate architecture and never chooses a winning candidate.
