# Cognitive Kernel Architecture Plan v1

## Phase

`Phase-Cognitive-Kernel-and-Process-Composition-Architecture-Planning-v1-001`

## Execution mode

Planning Only / V0 static architecture verification.

## Objective

Introduce a Cognitive Kernel Layer and a Cognitive Process Composer above the existing Cognitive Organization Layer. They preserve cross-module cognitive consistency and compose bounded cognitive-process candidates; they do not add cognitive capability or runtime execution.

## Architecture position

```text
Cognitive Kernel
  -> Cognitive Organization Layer
  -> future Cognitive Runtime
  -> Cognitive Capability Layer
  -> External World
```

```text
Cognitive Kernel
  -> Global Constraint / Consistency / Arbitration / Mode / Extension Boundary
  -> Attention Governance / Capability Composition / Resource Modulation / Process Composer
  -> future Cognitive Runtime
```

## Kernel role

The Kernel observes Candidate Flow, generates Constraint Candidates, and provides Arbitration Candidates. It has no authority to create cognitive content, assert reality, make decisions, execute actions, mutate State, or override Reducer.

## Process Composer role

```text
Goal Candidate + Context Candidate + Attention Allocation Candidate
  + Capability Bundle Candidate + Resource Budget Candidate
  -> Cognitive Process Candidate
```

The Process Composer organizes a proposed cognitive process. It is not a task planner, process executor, or action planner.

## Excluded scope

- Runtime Engine, Scheduler, Kernel Runtime, or Process Executor;
- Decision Runtime, Action Runtime, model invocation, or real-sensor access;
- Emotion, Personality, Hive, Learning, or Memory runtimes;
- Memory Mutation and Reducer modification.
