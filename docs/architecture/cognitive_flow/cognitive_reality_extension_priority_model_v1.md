# A-Route Extension Priority Assessment Model v1

## Assessment dimensions

| Dimension | Review question |
|---|---|
| A Core impact | Does it improve reality/self/situation/decision/feedback quality? |
| First-person life value | Does it help everyday situated embodied operation? |
| Decision quality gain | Does it expose a critical constraint, uncertainty, or alternative? |
| Engineering complexity | What new contracts, traces, fixtures, and regression cost are required? |
| Existing compatibility | Can it attach through current interfaces without opening A Core? |

## Priority interpretation

An extension is a `Priority Candidate`, not an implementation order.
Higher priority requires strong value, tractable complexity, interface compatibility, and regression coverage.
It cannot justify bypassing the A Constitution or starting a capability automatically.

Uncertainty and Temporal extensions are likely high leverage for A quality.
Spatial and Attention are high leverage for first-person operation.
Social and Multi-Agent require higher Brain/Process coordination review before A attachment.
