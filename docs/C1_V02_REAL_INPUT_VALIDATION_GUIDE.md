# C1 Active Mode v0.2 真实输入验证指南

## 一、验证目标

验证 C1 Active Mode v0.2 在真实输入下的表现，确保满足上线标准：

1. **无日志 spam / 状态抖动**
   - 日志频率合理（平均间隔 ≥ 0.1 秒）
   - 状态切换频率 ≤ 1 次/秒

2. **任一 SKIP 都能从日志解释原因**
   - 所有 SKIP 都有明确的 `skip_reason`
   - `skip_reason` 包含状态和 Protection 信息

3. **导航安全 0 影响**
   - NavigationExecutor 执行率 ≥ 99%

4. **连续运行稳定性**
   - 10 分钟连续运行无崩溃
   - 内存/CPU 使用稳定

---

## 二、验证方法

### 2.1 使用真实摄像头（推荐）

```bash
python3 examples/c1_v02_real_input_validation.py --duration 10
```

**适用场景**：
- 有可用摄像头
- 需要验证真实环境下的表现

**注意事项**：
- 确保摄像头权限已授予
- 建议在安静、稳定的环境中运行
- 可以模拟不同场景（静止、移动、遮挡等）

### 2.2 使用视频文件

```bash
python3 examples/c1_v02_real_input_validation.py --duration 10 --video path/to/video.mp4
```

**适用场景**：
- 无可用摄像头
- 需要可重复的验证
- 使用特定场景的视频

**注意事项**：
- 视频文件需要存在且可读
- 视频时长应 ≥ 验证时长

### 2.3 使用模拟输入（快速测试）

```bash
python3 examples/c1_v02_real_input_validation.py --duration 1 --no-camera
```

**适用场景**：
- 快速验证脚本功能
- 测试验证逻辑

**注意事项**：
- 使用模拟数据，不反映真实表现
- 仅用于脚本功能验证

## 四、验证标准

### 4.1 日志频率验证

**通过标准**：
- 最小日志间隔 ≥ 0.1 秒
- 无异常频繁的日志（spam）

**失败原因**：
- 日志间隔 < 0.1 秒
- 日志频率异常高

### 4.2 状态稳定性验证

**通过标准**：
- 状态切换频率 ≤ 1 次/秒
- 无频繁抖动

**失败原因**：
- 状态切换频率 > 1 次/秒
- 状态频繁来回切换

### 4.3 SKIP 原因可解释性验证

**通过标准**：
- 所有 SKIP 都有明确的 `skip_reason`
- `skip_reason` 不为 "unknown"

**失败原因**：
- 存在无原因的 SKIP
- `skip_reason` 为 "unknown"

### 4.4 导航安全验证

**通过标准**：
- NavigationExecutor 执行率 ≥ 99%

**失败原因**：
- NavigationExecutor 执行率 < 99%

## 五、验证场景建议

### 5.1 正常场景

- 静止环境（验证稳定性）
- 缓慢移动（验证状态转换）
- 正常行走（验证日常使用）

### 5.2 异常场景

- 快速移动（验证 SUSPENDED 触发）
- 遮挡摄像头（验证 Protection Mode）
- 频闪画面（验证 FLICKER 检测）

### 5.3 边界场景

- 阈值附近抖动（验证迟滞机制）
- 长时间静止（验证状态保持）
- 快速恢复（验证恢复机制）

---

## 六、问题排查

### 6.1 摄像头初始化失败

**可能原因**：
- 摄像头权限未授予
- 摄像头被其他程序占用
- 摄像头驱动问题

**解决方法**：
- 检查系统权限设置
- 关闭其他使用摄像头的程序
- 使用 `--no-camera` 进行模拟测试

### 6.2 验证脚本崩溃

**可能原因**：
- 内存不足
- 依赖缺失
- 代码错误

**解决方法**：
- 检查系统资源
- 安装缺失依赖
- 查看错误日志

### 6.3 验证结果异常

**可能原因**：
- 输入数据异常
- 参数配置问题
- 环境干扰

**解决方法**：
- 检查输入数据质量
- 验证参数配置
- 在稳定环境中重新验证
