## 📋 设计目标

**在真实模型接入前，确认 risk 系统在"烂数据 + 极端行为"下不会乱说话。**

### 总体策略

不是 3 个系统，而是 1 个测试框架 + 3 种输入模式：

```
Risk Robustness Test Harness
 ├─ 噪声/抖动注入（Noise）
 ├─ 极端行为脚本（Scenario）
 └─ Shadow Mode 接入开关（Integration）
```

**所有东西只输出 snapshot 日志，不触发播报。**

---

## 🔧 一、噪声 / 抖动注入（P0）

### 核心目的

验证一句话：

> **模型一抖，Risk 会不会乱跳，ADVISORY 会不会被误触发**

### 实现方式

在**"用户位置输入侧"**加一个测试层，不改 risk 代码。

**NoisyPositionProvider**：
- 小幅连续抖动（`noise_radius`）
- 偶发跳变（`jump_prob` + `jump_magnitude`）

### 用 snapshot 看什么（只看这 3 点）

1. `delta_risk` 是否频繁 > 0
2. 是否出现连续多帧 `advisory_triggered`
3. `trend` 是否在 APPROACHING / STABLE 间疯狂横跳

### 合格标准

**噪声存在，但系统基本不说话。**

---

## 🔧 二、极端场景脚本（P0.5）

### 核心目的

验证一句话：

> **真实世界的"怪行为"，系统能不能保持克制**

### 5 个预定义场景

#### 1️⃣ 阈值附近来回晃

```
dist = 2.9 → 3.1 → 2.8 → 3.0 → 2.9
```

**期望**：系统宁可不说，也不能乱说

#### 2️⃣ 快速靠近又立刻离开

```
5.0 → 2.0 → 5.0
```

**期望**：快速移动不应频繁触发

#### 3️⃣ 静态停留

```
2.5 → 2.5 → 2.5（持续 30 秒）
```

**期望**：只能说一次，甚至不说

#### 4️⃣ 动态区域时间窗切换

```
07:59 → 08:00（dynamic_active False → True）
```

**期望**：时间窗切换不应触发警告

#### 5️⃣ 多风险叠加

```
WATER_EDGE + CROWD + CONSTRUCTION
```

**期望**：多风险叠加时保持克制

### 验收标准（非常重要）

**系统宁可不说，也不能乱说**

特别是：
- **场景 3（静态停留）** → 只能说一次，甚至不说

## 🔧 三、Shadow Mode 接入策略（P1）

### 策略决定（不是代码问题）

**真实模型接入第一阶段 = Shadow Mode**

### 正确顺序（请坚持）

```
模型输出
  ↓
RiskAdvisoryService
  ↓
RiskDebugSnapshot（日志）
  ↓
【人工/离线验证】
  ↓
确认稳定后
  ↓
开启播报
```

### 工程实现

**你未来只需要一个开关**：

```python
RISK_SHADOW_MODE = True  # True = 只打日志，不播报
```

**甚至不需要改 risk，只在执行层拦截即可。**

在 `main.py` 的 `_execute_speech_decision()` 中：

```python
elif action == "ADVISORY":
    advisory_text = decision.get("advisory_text")
    if not advisory_text:
        return
    
    # === v1.8.4: Shadow Mode 支持 ===
    if RISK_SHADOW_MODE:
        # Shadow Mode：只记录日志，不触发播报
        self.logger.info(
            f"[RiskShadowMode] ADVISORY 被拦截（Shadow Mode 开启）: {advisory_text}"
        )
        return
    
    # 正常播报逻辑...
```
