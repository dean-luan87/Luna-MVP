## §1. 文档目标与适用范围

### 1.1 解决的问题

- Luna 的完整形态不止主链与白盒；**长期沉淀与治理层必须分层定稿**。  
- **后处理、图书馆、记忆、治理 reserve** 不能继续作为分散占位，必须明确：谁加工、谁存储、谁审查、谁延迟/阻断。  
- 统一长期层边界，避免主链、白盒、日志、后处理、图书馆、记忆、治理之间越权混写。

### 1.2 讨论范围

| 在范围内 | 不在范围内 |
|----------|------------|
| 后处理链职责与边界 | 主链实现细节 |
| 图书馆/记忆定位与流转关系 | 白盒 UI 细节 |
| 治理与免疫链统一动作语义 | 日志 schema |
| reserve 在治理层归位 | 具体治理算法 |
| summary-first 与长期沉淀读序 | 图书馆/记忆写入实现 |

### 1.3 约束效力

后续所有长期沉淀与治理相关设计，应以本文为上位约束；与总纲冲突时以总纲为准。

## §2. 后处理链、图书馆、记忆、治理链的正式定位

### 2.1 后处理链

- 职责：归类、分析、筛选、优化、去向决策。  
- 定位：**加工厂**，不是仓库。  
- 边界：不直接等于图书馆或记忆，不直接替代主链。

### 2.2 图书馆

- 定位：**外部器官**；多个 Luna 可共享的大后台。  
- 性质：外部知识 / 策略 / 模式器官。  
- 当前阶段：不是 Luna 本体。  
- 未来方向：可扩展为蜂巢式超级大脑。

### 2.3 记忆

- 定位：Luna 个体内部长期高质量结果层。  
- 约束：只接收经处理与筛选的结果。  
- 禁止：原始信息直接注入。

### 2.4 治理与免疫链

- 作用：观察、预警、延迟、阻断。  
- 边界：不是第二主脑；不替代主链生成 Action。  
- 策略：前端轻、后端重（即时轻约束，长期强审查）。

## §3. 后处理链的职责与边界

### 3.1 职责

- 归类  
- 成因分析  
- 模式提炼  
- 筛选  
- 优化  
- 去向决策

### 3.2 典型输入（概念层）

- 运行总结链输出（summary feed）  
- 已落地日志 / 结构化事件 / 白盒解释（按需回溯）  
- benchmark / triage / rebaseline 结果  
- 记忆调用摘要  
- 风险 / 污染 / reserve 观察摘要

### 3.3 典型输出（概念层）

- 图书馆候选  
- 记忆候选  
- 风险观察候选  
- 污染观察候选  
- 丢弃候选

### 3.4 边界

- 不直接替代图书馆  
- 不直接替代记忆  
- 不直接干预主链  
- 不读取未落地的瞬时运行残影

### 写死

# 后处理链是去向决策中枢，不是长期存储体

## §4. 图书馆的正式定位

### 4.1 当前定位

- 图书馆是外部器官。  
- 是多个 Luna 共用的大后台。  
- 承载外部知识 / 策略 / 模式资产。  
- 默认先读 summary，再按需回溯详细过程。  
- 不直接吞原始黑匣子。

### 4.2 当前职责

- 承载候选知识  
- 承载候选策略  
- 承载候选模式  
- 承载失败模式 / 风险模式  
- 承载可版本化、可治理的外部资产

### 4.3 非职责

- 不直接等于记忆  
- 不直接接收原始运行流  
- 不替代后处理链  
- 不直接等于主链或白盒

### 4.4 未来方向

- 图书馆可扩展为蜂巢式超级大脑。  
- 可演进为多个 Luna 的上位知识与策略中枢。  
- 当前阶段仅占位，不展开实现。

### 4.5 与「三方证据源（Reserve）」的关系（占位）

证据源体系中的 **三方证据源（Third-Party Evidence Source，Reserve）** 未来可作为图书馆侧 **外部证据输入** 的一类候选形态（地图、评价、外部平台、社区反馈等非 Luna 自身生成数据）；**须**与 Luna 自身反馈交叉验证后方可进入候选资产语义。**当前不入库、不入主链、不进入** `scheduled_source_state` 参与格局，详见 `docs/INFORMATION_SOURCE_SCHEDULING_ARCHITECTURE.md` §3.1。

## §5. 记忆链的正式定位

### 5.1 记忆本质

- Luna 个体内部长期高质量结果层。  
- 面向长期保留、长期影响、长期复用。

### 5.2 输入门槛

# 原始信息严禁直通记忆

# 必须经过后处理链筛选优化

### 5.3 可接收内容（概念层）

- 已验证稳定模式  
- 高可信偏好  
- 高质量长期结果  
- 被后处理确认的内部认知

### 5.4 不可直接接收内容

- 原始日志  
- 原始错误  
- 未筛选候选  
- 一次性噪声经验  
- 未处理的污染候选

### 5.5 与图书馆区别

- 图书馆：外部候选资产层。  
- 记忆：内部长期高质量结果层。

### 写死

# 图书馆可装候选

# 记忆只能装高质量结果

## §6. 图书馆、记忆与后处理的主流转关系

主流转（概念链）：

```
运行主线
  → 日志黑匣子
  → 运行总结
  → 后处理链
  → 图书馆候选 / 记忆候选 / 风险观察 / 污染观察 / 丢弃
  → 最终沉淀
```

关键规则：

- 图书馆默认先吃总结。  
- 图书馆按需回溯详细过程（事件、白盒、原始 trace）。  
- 记忆不直接接收 summary/raw trace，而接收后处理后的高质量结果。  
- 后处理链承担去向决策职责。

## §7. 治理与免疫链的正式定位

### 7.1 非越权定位

- 治理链不是第二主脑。  
- 不直接替主链创造 Action。  
- 不直接替主链拍板最终路径。

### 7.2 核心任务

- 观察  
- 预警  
- 延迟  
- 阻断  
- 审查长期沉淀资格

### 7.3 作用对象

- 数据源层  
- 主链  
- 白盒  
- 总结  
- 后处理  
- 图书馆 / 记忆

### 7.4 前后端强度

- 前端轻：即时周期以观察、提示、轻延迟为主。  
- 后端重：在后处理、图书馆、记忆侧可施加更强审查与阻断。

---

## §8. 治理链的统一动作语义

治理动作统一使用四类语义：

### 8.1 `observe`

只记录风险或可疑状态，不立即改变前进资格。

### 8.2 `watch`

进入观察名单，持续跟踪，暂不阻断。

### 8.3 `defer`

延迟进入下一层（执行态 / 图书馆 / 记忆 / 强策略）。

### 8.4 `block`

阻断高风险结果继续前进。

### 写死

- 治理链统一优先映射到 `observe / watch / defer / block`。  
- 不建议无约束膨胀动作集合。  
- 污染抵抗、线程观察、议会复核等扩展，优先映射到这四类动作语义。

---

## §9. 治理链与其他链的权限边界

### 9.1 对数据源调度层

- 可观察；可 watch/defer 某类源。  
- 不直接重排，不替代调度器。

### 9.2 对决策运行链

- 可标记高风险路径；可要求 clarification / shadow / defer。  
- 不直接生成 Action。

### 9.3 对白盒

- 可注入风险标签与 reserve 标签。  
- 不让白盒代替治理判断。

### 9.4 对日志

- 可读、可校验。  
- 不可改写黑匣子原件。

### 9.5 对总结

- 可要求附加治理摘要。  
- 不能让总结替代证据。

### 9.6 对后处理

- 可施加筛选与延迟约束。  
- 是治理发力的重要位置。

### 9.7 对图书馆 / 记忆

- 审查权更强。  
- 可延迟、降级、阻断、影子验证、回滚建议。

---

## §10. reserve 能力在治理层中的归位

下列 reserve 统一归入治理与免疫链（与后处理、白盒协作）：

- 污染抵抗 / 决策污染观察  
- 线程报损 / 切换 / 消耗观察  
- Whitebox Plus  
- Post-Processing Intelligence（与治理协作关系）  
- Strategy Shadow  
- 多模型 / 多决策 / 投票议会  
- 高阶置信度治理  
- 自愈 / 自恢复约束

### 写死

- 当前均为 reserve / pre-architecture。  
- 不是已实现能力。  
- 后续扩展应优先挂在治理与免疫链下，而不是各自漂浮。
