# v1.8.3a 阶段 C 验收清单（5 分钟）

**版本**: v1.8.3a  
**阶段**: C  
**验收时间**: 5 分钟  
**状态**: ⏳ 待验收

---

## 验收目标

验证系统"不说话"时，是一个明确的决策结果，而不是悬空状态。

---

## 验收步骤（按顺序执行）

### 步骤 1: 验证决策日志输出

**操作**:
1. 启动系统
2. 观察日志输出

**期望**:
- [ ] 日志中出现 `decision_action=SPEAK` 或 `decision_action=WAIT` 或 `decision_action=YIELD`
- [ ] 每个决策都有明确的 `decision_reason`

**验证**:
```bash
grep "decision_action" logs/*.log
```

---

### 步骤 2: 验证 WAIT 状态（语音总闸拒绝）

**操作**:
1. 让系统连续处理相同场景（保持摄像头不动）
2. 观察日志

**期望**:
- [ ] 不再"像卡死"
- [ ] 日志出现 `Decision=WAIT reason=speech_gate_blocked_duplicate_scene` 或类似
- [ ] 系统继续运行（视频帧继续处理）

**验证**:
- [ ] 日志中有 `Decision=WAIT`
- [ ] 视频帧处理正常（不卡顿）

---

### 步骤 3: 验证 YIELD 状态（用户说话）

**操作**:
1. 启动语音对话功能
2. 开始说话
3. 观察日志

**期望**:
- [ ] 系统彻底让位（YIELD）
- [ ] 日志出现 `Decision=YIELD reason=user_speaking`
- [ ] 系统不播报场景描述

**验证**:
- [ ] 日志中有 `Decision=YIELD`
- [ ] 用户说话时系统不播报

---

### 步骤 4: 验证 SPEAK 状态（正常场景）

**操作**:
1. 确保用户未说话
2. 确保场景未重复
3. 确保语音总闸未阻塞
4. 观察日志

**期望**:
- [ ] 日志出现 `decision_action=SPEAK reason=normal_scene`
- [ ] 系统正常播报

**验证**:
- [ ] 日志中有 `decision_action=SPEAK`
- [ ] 系统正常播报场景描述

---

### 步骤 5: 验证重复场景抑制

**操作**:
1. 保持静态场景（人 + 标志牌）10 秒
2. 观察日志

**期望**:
- [ ] 只感知、不复读
- [ ] 日志出现 `Decision=WAIT reason=speech_gate_blocked_duplicate_scene`
- [ ] 第 1 次播报后，后续不再播报

**验证**:
- [ ] 第 1 次播报正常
- [ ] 后续帧日志显示 `Decision=WAIT`
- [ ] 不再重复播报

---

## 验收标准

### 必须通过（P0）

- [ ] 所有决策都有明确的 action 和 reason
- [ ] WAIT 状态时系统继续运行（不卡死）
- [ ] YIELD 状态时系统让位（不播报）
- [ ] SPEAK 状态时系统正常播报

### 应该通过（P1）

- [ ] 日志可读性强（一眼知道现在在干嘛）
- [ ] 重复场景抑制生效
- [ ] 用户说话时系统让位

---

## 问题排查

### 如果看不到决策日志

**检查**:
1. `_execute_speech_decision()` 是否被调用
2. 日志级别是否设置为 INFO

### 如果系统仍然"卡住"

**检查**:
1. 决策结果是否正确返回
2. 主循环是否正确消费决策结果
3. 是否有其他地方绕过决策层

### 如果用户说话时系统仍在播报

**检查**:
1. `user_state.is_speaking` 是否正确更新
2. 决策逻辑是否正确判断 `user_speaking`
