# Luna 完整形态主线总纲（Mainline Shape Blueprint）— M0

**文件**：`docs/LUNA_MAINLINE_SHAPE_BLUEPRINT.md`  
**版本**：M0（上位骨架定稿）  
**性质**：架构宪法级总纲。**不写**实现细节、代码、API/schema、算法公式。

---

## §1. 文档目标与适用范围

### 1.1 这份文档解决什么问题

- Luna **不是**无结构的模块集合，而是**完整形态**的链式系统：须正式定义主链、观察链、落地链、沉淀链、治理链及其关系。  
- 本文件为 **上位总纲**：约束后续**主线工程、白盒工程、日志工程、后处理工程、图书馆/记忆工程、治理工程**的架构设计与拆分。  
- 本文件**不是**实现说明书；专题设计须以本文为**硬约束**，不得与之冲突。

### 1.2 约束谁、不约束什么

| 约束对象 | 说明 |
|----------|------|
| 主线工程 | 决策运行链与数据源调度层的关系、收口语义 |
| 白盒工程 | 白盒观察链与主链、调度层的对齐方式 |
| 日志工程 | 黑匣子与总结分离、落地边界 |
| 后处理工程 | 深加工与去向，相对图书馆/记忆的位置 |
| 图书馆/记忆工程 | 外部器官与个体内存、summary-first、记忆代谢 |
| 治理工程 | observe/watch/defer/block 与越权边界 |

**不约束**：具体模块名、接口版本、JSON 字段表、评分公式、污染/线程算法、图书馆写入流水线。

### 1.3 与工程执行规则的关系

工程轮次仍须遵守 **主线 → 白盒 → 日志** 串联检查（见 `docs/MAINLINE_WHITEBOX_LOG_CHAIN_RULE.md`）。本总纲定义**完整形态骨架**；该规则定义**每轮交付的验证顺序**。二者互补。

### 1.4 一句话压缩版

Luna 完整形态由 **8 条链、4 个层级** 构成：数据源调度与决策运行承担即时运行；白盒观察与日志落地承担伴随观察与黑匣子记录；运行总结与后置信息处理承担事后提炼与深加工；图书馆/记忆与治理免疫承担长期沉淀与约束。**调度层不产生 Action**；**白盒不生成第二主链**；**日志不干预主线**；**原始信息不直通记忆**；**图书馆先读总结再按需拉 trace**。

## §2. Luna 完整形态的 8 条链

每条链：**一句定义**、**职责**、**明确不负责**（避免功能泛化）。

| # | 链 | 一句话定义 | 负责 | 不负责 |
|---|----|------------|------|--------|
| 1 | **数据源调度层** | 将多源输入整理为**可交给主链的数据源状态** | 源分类、参与源判定、优先级、主导源、冲突整理、时效与可信度约束下的排序与切换 | 业务 Action 的选取与执行；目标达成策略的最终拍板 |
| 2 | **决策运行链** | 在**当前周期**内完成理解、路径选择、recheck/clarification/fallback/recovery，并**收口为可执行下一步** | 当前场景整理、候选路径、主路径选择、当前收口、结果回流到当前闭环 | 历史经验深加工、图书馆写入、记忆筛选、长期沉淀决策 |
| 3 | **白盒观察链** | 对**同一条**主链与调度事实进行可解释呈现与溯源支撑 | 主链事实镜像、调度过程可见、质量与偏移观察、优化与验证的解释位、预留治理的挂接说明 | 另起一套决策；替主链选 Action；用摘要冒充过程 |
| 4 | **日志落地链** | **黑匣子式**记录主链与关键伴随事实，保证可追溯 | 原样落地、顺序与完整性、不可被总结篡改、不干预控制流 | 解释、归纳、评分、替主链做判断 |
| 5 | **运行总结链** | 在**不替代黑匣子**的前提下做轻提炼与 **summary feed** | 本次运行的一页纸归纳、问题与入口摘要、供图书馆/后处理消费的摘要面 | 覆盖或污染原始日志；跳过黑匣子自造事实 |
| 6 | **后置信息处理链** | 对总结与可授权历史材料做**深加工**与去向决策 | 归类、成因分析、模式提炼、筛选、优化、候选池分配 | 替代主链决策；绕过日志与总结契约直接写记忆 |
| 7 | **图书馆 / 记忆链** | **图书馆**：多实例可共享的外部知识与策略器官；**记忆**：个体内长期**高质量**结果层 | 图书馆接纳候选与策略模式；记忆接纳经代谢后的高质量结果 | 记忆直接吞原始信息；图书馆无差别吞全量黑匣子 |
| 8 | **治理与免疫链** | 横跨各链，判断**是否允许继续**与风险处置姿态 | observe、watch、defer、block；高风险先入候选/观察/影子态 | 替代主链生成最终 Action；改写黑匣子原件 |

**说明**：第 8 条链**横跨**数据流主序列，不占用「主序列上唯一一格」；其对各链施加约束，但不替代第 2 条链做当前拍板。

## §3. 四个层级结构

### I. 即时运行层（Fast）

| 链 | 角色定位 |
|----|----------|
| 数据源调度层 | 把输入变为**整理后的数据源状态** |
| 决策运行链 | 当前周期内完成判断与收口 |

**核心约束**：低延迟、与当前帧/当前决策周期强绑定；**主链吃的是整理后的数据源状态，不是原始输入堆叠**。

### II. 伴随观察层（Fast）

| 链 | 角色定位 |
|----|----------|
| 白盒观察链 | 镜像主链与调度，可解释、可溯源 |
| 日志落地链 | 黑匣子，原样、完整、可追溯 |

**核心约束**：与当前运行**同步伴随**；日志**不解释、不干预**；白盒**只读事实链**。

### III. 事后加工层（Slow）

| 链 | 角色定位 |
|----|----------|
| 运行总结链 | 轻提炼、summary feed |
| 后置信息处理链 | 深加工、去向与候选池 |

**核心约束**：可异步、可批处理；**不得跳过**快链已形成的日志事实；**不得改写**黑匣子原件。

### IV. 长期沉淀与治理层（Slow）

| 链 | 角色定位 |
|----|----------|
| 图书馆 / 记忆链 | 外部候选资产 vs 个体内高质量记忆 |
| 治理与免疫链 | 横切约束与免疫姿态 |

**核心约束**：沉淀与治理**后端重**；**记忆不直通原始信息**；**图书馆 summary-first**。

### 快链 / 慢链对照

| | 快链（Fast） | 慢链（Slow） |
|---|----------------|----------------|
| **时序** | 与当前决策周期强绑定 | 可滞后、可批处理 |
| **典型** | I、II 层 | III、IV 层中的加工与沉淀 |
| **硬规则** | 慢链产物不得污染或替代快链黑匣子 | 慢链须尊重日志—总结分界 |

## §4. 主数据流方向

主序列（先后相接的**概念数据流**）：

```
数据源调度层
  → 决策运行链
  → 白盒观察链
  → 日志落地链
  → 运行总结链
  → 后置信息处理链
  → 图书馆 / 记忆链
```

**并行横切**：**治理与免疫链**对各链施加 observe / watch / defer / block；**不**替代决策运行链做当前最终 Action。

**必须写死的三条输入/输出原则**：

1. **决策运行链处理的是整理后的数据源状态**，不是未经调度的原始输入。  
2. **图书馆默认先消费总结（summary）**，再按需回溯详细 trace；不默认吞全量黑匣子。  
3. **记忆不直接接收原始历史信息**；须经后置信息处理链等代谢后再进入可写入的高质量路径。

---

## §5. 越权边界（硬规则）

1. **数据源调度层不准产生 Action。** 调度只整理与裁决「源的状态与优先级」，不下达业务动作。  
2. **白盒只读主链，不生成第二主链。** 禁止平行决策树、禁止事后编造理由替代真实过程。  
3. **日志不准干预运行效率与主链控制流。** 黑匣子只记录，不调度、不阻断、不改写策略。  
4. **总结必须基于日志，不得跳过黑匣子。** 总结不能替代排障与审计所需的原始记录。  
5. **原始信息严禁直通记忆，必须经过代谢。** 代谢主体在后置信息处理链等深加工环节定义与实现。  
6. **图书馆默认先吃总结，再按需拉详细过程。**  
7. **治理链只判断「是否有资格继续前进」，不替主链生成最终 Action。**

## §6. 数据源调度层的正式定位

- **数据源不是平铺输入**；未经调度不得等价于「主链输入」。  
- **数据源层即数据源调度层**：负责把多源变为**有序、可解释、可审计**的输入状态。  
- 每一数据源至少应能表述：**类型**、**权重**、**优先级**、**时效性**、**可信度/稳定度**（具体度量属实现层，本总纲只定维度）。  
- **主链处理对象 = 整理后的数据源状态**，不是原始传感器/原始对话字节的直接堆叠。  
- **后续白盒必须显式展示（观察义务）**：当前参与源；当前主导源；主导源切换；源间冲突；**动态源相对静态源的优先关系**（须结合可信度）；**安全相关源对目标链的覆盖关系**（安全优先于目标）。

### 6.1 预留：三方证据源（Third-Party Evidence Source，Reserve）

证据源体系中预留 **「三方证据源（Third-Party Evidence Source）」** 类型，未来用于接入地图数据、评价数据及其他非 Luna 自身生成的数据。该类证据源**不是** Luna 自身证据，**当前**不进入即时运行层的主流程与主链拍板，不进入现有数据源调度层对当前周期的**默认**整理路径，仅作 **Reserve / Not in current flow**。后续接入须与 Luna 自身反馈**交叉验证**真实性、时效性与可采信度；目标优先指向证据补充、外部世界建模、社区化共识及图书馆 future 的外部证据输入，而非优先增强当前拍板。**当前**不占八条链中的独立运行链路，仅为架构占位；细则见 `docs/INFORMATION_SOURCE_SCHEDULING_ARCHITECTURE.md` §3.1。

---

## §7. 白盒观察链的正式定位

- **白盒不是第二套脑子**；**白盒是主链的镜子**。  
- **白盒必须观察并能在结构上对齐以下层次**（推荐顺序）：  
  1. **主链事实**  
  2. **数据源调度**  
  3. **质量与偏移**  
  4. **优化与验证**  
  5. **预留治理**  
- **问题溯源以逻辑链为主，评分为辅。**  
- **允许出现「高评分但逻辑可疑」** 的可解释状态（如伪稳定、伪恢复、慢性漂移、延迟暴露）；评分负责拉警报与排序，不替代因果链叙述。  
- **记忆片段调用必须可解释**，且至少能回答：**为什么选它**；**依据是什么**；**用了片段中哪些内容**；**使用逻辑是什么**。该解释必须进入白盒观察、日志事实与运行总结链能覆盖的叙述面（实现形态由专题文档规定）。

## §8. 日志落地链与运行总结链的正式分离

### 8.1 日志落地链（黑匣子）

- **原样记录**；**不解释**；**不干预**主链运行；**可追溯**；**不可被总结层篡改**。  
- 日志链**只记录，不归纳**。

### 8.2 运行总结链

- **轻提炼**；形成 **summary feed**；作为图书馆与后处理的**归纳入口**。  
- **不能替代黑匣子**；不能作为审计与排障的唯一依据。

### 8.3 写死分离

**日志链与总结链严格分离。** 总结可引用日志，**不得**污染、覆盖或替代黑匣子原件语义。

**图书馆读取顺序**：**先读 summary，再按需读取详细 trace**。**总结不得污染黑匣子。**

---

## §9. 后置信息处理链、图书馆、记忆的边界

### 9.1 后置信息处理链

承担：**归类、分析、筛选、优化、去向决策**。定位是**加工厂**，不是仓库本身。

### 9.2 图书馆

- **外部器官**；可多 Luna 共用的后台知识与策略资产形态。  
- **外部知识 / 策略 / 模式**的承载位；未来可演化为蜂巢式超级大脑等形态（本总纲不定实现）。

### 9.3 记忆

- **Luna 个体内部**长期**高质量结果**层。  
- **只接收**经筛选、优化、验证后的结果路径所允许写入的内容（实现层后定）。

### 9.4 写死边界

- **图书馆可接收候选**（候选知识、候选策略、候选模式）。  
- **记忆只能接收高质量结果**；**不接受原始信息直接注入**。  
- **原始历史处理信息严禁不经代谢直通记忆**；代谢责任主体在后置链与工程规则中显式化。

---

## §10. 治理与免疫链的正式定位

- **不是第二套主脑。**  
- 仅允许四类动作：**observe**、**watch**、**defer**、**block**。  
- **前端轻、后端重**：即时主链阶段以观察、预警、轻延迟为主；在后处理 / 图书馆 / 记忆阶段可承受更强审查、阻断、影子验证与回滚语义（实现后定）。  
- **不得改写日志原件**；不得以总结替代证据链。

**Reserve 能力（当前以占位与原则为主，非「已全部实现」）**，包括但不限于：

- 污染抵抗 / **决策污染观察**  
- **线程报损 / 切换 / 消耗**观察  
- **Whitebox Plus**  
- **多模型 / 多决策 / 投票议会式复核**  
- **高阶置信度治理**

---

## §11. 评分哲学（原则only，无公式）

- **评分先局部，后全局**：链内评分/状态 → 链间一致性/影响 → 全局治理模型。  
- **状态优先于总分**。  
- **链间一致性高于单链高分**（主链、白盒、日志须对齐同一条事实链）。  
- **高风险维度可覆盖低优先级高分**（如安全、主链 blocked、日志断裂）。  
- **评分用于治理与诊断，不用于美化**。  
- **白盒问题溯源以逻辑链为主，评分为辅**。  
- **允许「高评分但逻辑可疑」** 的显式状态。  

**分层期望（方向性）**：每条链将来须有可操作的**局部评分/状态模型**；链间须有**一致性/对齐/影响**关系；**最后**才收敛为全局治理模型。具体公式与字段不在本总纲定义。

## §12. 当前 reserve 与未来扩展位

下列方向在完整形态中**已有或预留位置**，**当前阶段以 reserve / 占位 / 原则为主**，**不视为已全部交付的实现能力**：

| 方向 | 说明（M0） |
|------|------------|
| 污染抵抗 / 决策污染观察 | 工程占位如 `decision_contamination_guard_reserve`；非全量污染算法 |
| 线程报损 / 切换 / 消耗观察 | 结构预留，无具体线程报损算法 |
| Post-Processing Intelligence | 占位如 `post_processing_intelligence_reserve`；非全量后处理厂 |
| Strategy Shadow | 影子验证，不执行真实注入 |
| Whitebox Plus | 扩展位 |
| 多模型 / 多决策 / 投票议会 | 扩展位 |
| 蜂巢模式（图书馆超级大脑） | 架构扩展位 |

**在未稳定专题设计前**，不宜以「单点实现」替代完整形态设计（例如盲目扩场景批次、深做图书馆写入、上统一全局评分模型而脱离链间一致性）。
